# MediaAI Renamer 用户手册

版本：`1.3.0`
覆盖范围：M1-M11 已实现能力
更新日期：2026-10-15
适用v1.3.0；旧安装包以其实际功能为准。

## 1. 产品用途

MediaAI Renamer 用于扫描本地或服务端可访问的影视目录，生成标准化命名预览，并在用户确认后安全重命名真实文件。

当前已支持：

- 媒体源管理。
- 本地目录选择。
- 分批扫描和全量 / 增量扫描。
- 扫描任务和扫描结果查看。
- 命名预览生成、查询、编辑、标题识别模式和冲突提示。
- TMDB / IMDb 补充 / AI 外部匹配。
- dry-run 冲突检测。
- 多选、全部和单条安全重命名。
- 待处理文件列表和批量迁移。
- 系统设置热更新。
- NAS / SMB / NFS 共享目录基础支持。
- AI 智能解析和候选回填。
- 敏感词设置和外部提交拦截记录。
- 命名规则高级配置、模板导入导出、规则测试、差异预览和历史预览模板状态提示。
- 本地认证、用户维护和直接用户权限。
- 审计日志、操作运行日志、重命名回滚和任务治理归档。
- 多源元数据补充源 Tab 配置、多源匹配结果查看入口。
- WebDAV HTTPS 地址校验、连接测试、目录浏览、递归扫描、MOVE dry-run、真实 MOVE 重命名、回滚和失败恢复。
- 亮色、暗色和跟随系统显示模式；提供六套完整主题样式。
- 操作日志查看。

当前主要限制：

- SMB / UNC 连接测试检查当前后端服务进程是否能访问共享路径；系统不会自动执行 `net use` 登录共享。
- NFS 需要用户先在操作系统、宿主机或 NAS 中完成挂载，本系统不会自动执行挂载命令。
- WebDAV 支持 HTTPS、无认证 / Basic / Bearer、连接测试、目录浏览、递归扫描、MOVE dry-run、真实 MOVE 重命名、回滚和失败恢复。
- HTTP WebDAV、Digest、跳过 TLS 校验、FTP、FTPS、SFTP、S3 / MinIO 不受支持。
- 复杂自动归档策略暂不支持，当前仅提供手动归档和恢复。

## 2. 启动和访问

本地开发推荐使用：

```powershell
npm run dev:start
```

启动后访问：

```text
http://127.0.0.1:5173
```

后端默认端口为 `8970`，前端开发端口为 `5173`，Docker Web 端口为 `8971`。

## 3. 页面结构

页面左侧为导航栏，包含：

- 产品名称和 Logo。
- 媒体源。
- 扫描任务。
- 扫描结果。
- 命名预览。
- 系统设置。
- 后端状态。
- 语言选择占位。
- 版本信息和主题切换。

页面右侧为操作台。点击左侧菜单后，右侧会切换到对应页面。

侧边栏支持展开和收缩：

- 展开时显示图标和文字。
- 收缩时只显示图标，鼠标悬浮可查看名称。

## 4. 主题和状态

点击左下角版本信息附近的“外观”图标，在弹层中分别选择“显示模式”和“主题样式”。显示模式支持跟随系统、亮色、暗色；v1.3.0提供清爽专业、柔和彩色、精密高对比、海盐青、林间绿、琥珀日光六套主题，每套都有亮暗两种效果。主题覆盖画布、侧栏、表格、输入和弹窗，不只改变按钮颜色。侧栏版本来自后端健康接口，仅显示v加版本号；接口尚未返回时显示“版本待确认”，不写死或虚构版本。

使用预览列表选择主题，点击立即生效，弹层保持打开以便比较；主题列表过长时在列表内滚动。窄窗口使用单列，可用高度不足时使用对话框；显示模式与关闭入口保持可达。可用方向键切换，ESC关闭并返回外观入口；外部点击关闭不会撤销选择。跨低高度布局时会关闭当前面板，重新点击外观即可打开。

选择后立即生效，刷新页面仍保留；两项互不覆盖，只保存在当前浏览器中。跟随系统只改变亮暗；切换主题不改变登录、筛选或任务，不触发外部请求及文件操作。清除浏览器站点数据后会恢复默认选择，不影响服务端配置。

后端状态使用图标和文字显示：

- 绿色：连接正常。
- 红色：连接异常。
- 灰色：未知或检测中。

语言选择当前默认显示中文，完整多语言切换后续实现。

## 5. 媒体源管理

进入“媒体源”页面后，可以管理需要扫描的目录。

### 5.1 新增媒体源

新增媒体源需要填写：

- 名称。
- 路径类型。
- 目标路径。
- 启用状态。

路径类型包括：

- 本地路径：服务所在机器可直接访问的目录。
- Windows UNC / SMB：形如 `\\NAS\Movies` 的共享路径。
- 已挂载路径 / NFS：Linux、NAS、Docker 或 NFS 已挂载到本地后的路径，如 `/mnt/media`。
- WebDAV：HTTPS WebDAV 服务地址，如 `https://nas.example.com/dav`。

当前保存时只校验必填项和基础格式，不强制校验路径有效性。路径是否可用可以通过“测试连接”入口确认。

### 5.2 本地目录选择

选择“本地路径”或“已挂载路径 / NFS”时，可以点击“选择目录”，在弹窗中浏览服务所在机器可访问的目录。

目录选择弹窗会展示：

- 当前路径。
- 上一级目录。
- 子目录列表。
- 可读、可写权限状态。

不可读目录会禁用进入。

### 5.3 SMB 路径

选择 Windows UNC / SMB 时：

- 目标路径需要手动输入。
- 路径必须以 `\\` 开头。
- 账号和密码只在 SMB 类型下展示。
- 密码加密保存，不在列表和接口响应中回显明文。

连接测试会检查当前服务进程是否能访问该 UNC 路径，并返回读写权限状态。系统不会自动执行 `net use` 登录共享；如果当前服务进程没有共享访问权限，需要先在系统层完成访问配置。

### 5.4 NFS / 已挂载路径

选择已挂载路径 / NFS 时：

- 不显示用户名和密码。
- 可填写 NFS 服务器和导出目录作为说明信息。
- 系统只访问本地挂载点，不自动执行 `mount`。
- Docker 场景需要先在宿主机完成挂载，再映射到容器内路径。
- Linux 环境下会尽量识别 `nfs` 或 `nfs4` 文件系统类型；无法确认时只提示，不在路径可访问时强制失败。

### 5.5 测试连接

新增和编辑媒体源时都可以点击“测试连接”。

测试内容包括：

- 路径是否存在。
- 是否为目录。
- 当前服务进程是否可读、可写。
- SMB / UNC 路径格式和当前进程访问能力。
- NFS / 已挂载路径访问能力，并尽量识别文件系统类型。
- WebDAV HTTPS 地址格式、认证信息和服务连通性。

测试失败不会删除已保存配置，也不会阻止只保存必填项完整的媒体源。请根据提示检查路径、网络、挂载状态和服务运行用户权限。

### 5.5.1 WebDAV 当前能力

选择 WebDAV 时：

- 地址必须使用 `https://`，不支持明文 HTTP。
- v1.2.0，使用最终地址，不自动跟随重定向；URL 不允许内嵌用户名/密码、查询参数或片段。目录响应和 MOVE 不能跨站点、跨端口或越出配置根目录。
- 支持用户名和密码的 Basic 认证；只填写 Token 时按 Bearer Token 发送。
- 密码或 Token 加密保存，接口和日志不会返回明文。
- 支持连接测试、目录浏览和递归扫描。
- 扫描结果会进入现有扫描结果列表，可继续生成命名预览。
- 当前版本支持 WebDAV MOVE dry-run 和真实 MOVE 写入。真实 MOVE 执行前仍需先通过 dry-run，并使用远程写操作锁防止同一媒体源并发写入。
- MOVE 固定禁止覆盖已存在目标。
- 成功批次支持反向 MOVE 回滚。
- 失败或中断记录可在“任务治理 -> WebDAV 恢复”中查看和处理。

WebDAV 恢复会重新检查源和目标。可安全重试时执行 MOVE，远端已完成时只补齐数据库，状态有歧义时停止自动写入并转人工处理。

详细步骤见 [M11 WebDAV 用户手册](M11-WebDAV用户手册.md)，部署要求见
[WebDAV 部署说明](../deployment/webdav.md)。

从旧版升级至v1.2.0时，媒体源及 AI/TMDB 等持久化凭据使用独立密钥的 v3 加密。数据库与密钥必须分开备份；缺失或不匹配时明确失败，不会清空凭据。首次迁移保持原数据库路径，新密文恢复可变更路径。具体操作、失败处理及回退见部署说明第 7 节。

### 5.6 编辑媒体源

点击媒体源名称或“修改”图标可打开编辑弹窗。

编辑时可以修改：

- 名称。
- 目标路径。
- SMB 账号和密码。
- NFS 服务器和导出目录。
- 启用状态。

路径类型保存后不能修改。如需变更路径类型，请新建媒体源。

v1.2.0修改目标路径时，会要求确认旧执行计划和待处理记录失效、旧索引清理；历史任务、扫描结果和操作证据保留，不删除真实媒体文件。存在运行中任务或未完成恢复时拒绝修改。

### 5.7 删除媒体源

支持单条删除和批量删除。v1.2.0执行退役：源从可用列表移除、旧执行计划和待处理记录失效，历史证据保留，真实媒体文件不删除。存在运行中任务或未完成恢复时拒绝退役。

## 6. 扫描任务

进入“扫描任务”页面后：

1. 选择一个已启用媒体源。
2. 选择“全量扫描”或“增量扫描”。
3. 点击“开始扫描”。
4. 等待任务完成。
5. 在任务列表查看扫描统计。

任务列表包含：

- 任务 ID。
- 状态。
- 扫描模式。
- 已扫描数量。
- 视频数量。
- 警告数量。
- 新增 / 修改 / 跳过 / 缺失 / 已建索引数量。
- 单批数量。
- 间隔。
- 开始时间。
- 结束时间。

首次扫描默认使用全量扫描。存在历史索引时，页面会提示可以优先使用增量扫描。扫描采用分批执行，默认每批 100 个文件，批间隔 1 秒。相关配置可在系统设置中调整。

任务行支持直接跳转：

- 查看扫描结果。
- 查看命名预览。

## 7. 扫描结果

进入“扫描结果”页面后，需要先选择媒体源和扫描任务，再点击“查询”。

扫描结果默认不自动加载，只有用户手动查询或从扫描任务跳转时才加载对应任务的数据。

列表字段包括：

- 序号。
- 文件名。
- 格式。
- 大小。
- 任务 ID。
- 路径。
- 修改时间。

支持分页、排序、详情弹窗和重置。重置会清空查询条件和当前列表数据。

v1.2.0的扫描结果按每页10或50条从服务端读取，不提供“全部”；排序作用于当前任务全部匹配结果，不限于本页。切换筛选或排序回到第一页，刷新保留当前页；数据减少后超出末页会自动回到最后一页。其他列表按各自页面规则执行。

## 8. 命名预览

v1.2.0按每页10或50条从服务端读取，统计与排序作用于当前全部筛选结果；旧“全部展示”设置归一为50。媒体源与扫描任务下拉也按页读取，翻页替换选项，已选项在页外仍显示。媒体源下拉可按名称搜索；选择新来源或任务后旧结果立即清空，点击查询加载对应结果。

工具栏“全部”操作读取当前全部筛选结果中符合操作资格的ID，不限于当前页。确认后仅提交这组ID，不在执行时扩大范围；超出系统批量操作上限时拒绝并提示总数及上限，可缩小筛选或选择页内条目。范围查询仅为本地读取，不等于已发送AI/TMDB请求；实际请求仍需确认及服务端保护检查。确认期间改变筛选、解析方式或选择范围会取消本次提交。

进入“命名预览”页面后，可以对扫描结果生成标准目标文件名。

页面包含两个标签页：

- 命名预览列表。
- 待处理文件列表。

### 8.1 生成预览

1. 选择媒体源。
2. 选择扫描任务。
3. 点击“生成预览”。
4. 点击“查询”查看预览结果。

命名预览默认不会在进入页面时自动加载；只有查询、生成预览或从扫描任务跳转时才加载。

### 8.1.1 标题识别模式

进入“系统设置 -> 解析重命名配置”可切换标题识别模式：

- `file_name_first`：优先使用文件名标题。
- `parent_folder_fallback`：文件名标题不足时，用上级文件夹补位。
- `parent_folder_first`：优先使用上级文件夹标题。
- `manual_only`：不自动替换，只展示上级文件夹候选，交由用户确认。

文件名和上级文件夹标题冲突时，系统不会自动覆盖文件名标题，会将预览标记为“需检查”。

### 8.2 预览状态

常见状态包括：

- 可使用：系统生成了可执行的目标文件名。
- 需检查：解析结果不完整，需要人工确认。
- 已编辑：用户手动修改过目标文件名。
- 已重命名：真实文件已完成重命名。

### 8.3 编辑目标文件名

点击操作列中的“编辑”图标，可以修改目标文件名。

规则：

- 只能编辑文件名，不能输入目录路径。
- 如果没有输入扩展名，系统会自动补回原扩展名。
- 手动编辑会保存到预览记录中，并优先用于最终重命名。

### 8.4 TMDB 匹配

点击操作列中的 TMDB 匹配图标可对单条预览执行元数据匹配，也可以使用顶部工具栏执行选中批量匹配、全部未匹配匹配或 TMDB→AI 后备匹配。

匹配前可选择提交来源：

- 解析标题。
- 原文件名。
- 上级文件夹标题。

匹配结果包括：

- 高置信：自动回填目标文件名。
- 需确认：打开候选弹窗，由用户选择候选后回填。
- 未匹配：保留本地解析结果。

手动编辑的目标文件名仍优先用于最终重命名。

### 8.5 AI 智能解析

点击操作列中的“AI 解析”图标可对单条预览执行 AI 辅助解析，也可以使用顶部工具栏对选中条目或当前列表批量执行 AI。

AI 解析规则：

- 仅在用户点击后调用。
- 命中敏感词或外部提交保护规则时不会发出 AI 请求。
- 批量 AI 和 TMDB→AI 后备执行前会展示当前 Provider、模型、Base URL、提交范围和 Token 成本提示。
- 成功后弹出候选结果，展示标题、类型、年份、季集、置信度和原因。
- 点击“选择回填”后只更新命名预览目标文件名。
- 不会直接修改真实文件。

回填后的记录仍需通过安全重命名流程执行真实文件改名。

## 9. 安全重命名

真实重命名必须从命名预览页面发起。

支持三种方式：

- 勾选多条记录后点击“执行重命名”。
- 点击“全部重命名”。
- 点击单行操作列中的“执行重命名”图标。

执行前系统会先检查目标文件名是否为空。如果存在空目标文件名，可以返回编辑，也可以一键剔除空名条目后继续。

空名检查通过后，系统会执行 dry-run 冲突检测。常见冲突包括：

- 源文件不存在。
- 目标文件名为空。
- 目标文件名包含目录分隔符。
- 目标文件已存在。
- 同一批次中多个文件使用相同目标路径。
- 预览状态不允许重命名。

只有 dry-run 通过的条目才会进入真实重命名。系统不会覆盖已有文件，也不会移动目录。

v1.2.0：确认重命名后立即返回原批次并进入“已排队/执行中”，页面按秒串行读取真实进度；有日志权限时自动打开该批次日志。离开页面不取消后台执行，可从任务治理进入同一批次继续查看。查询暂时失败时点击批次弹窗的“刷新”，只读取状态；不要重新创建批次重复执行。断线或15秒请求超时不能证明文件未改名。

任务中断时显示中断原因，已成功项保留、未执行项不自动重试；权限撤销、总时间上限（当前固定3600秒）或原执行进程状态不明时需要核对。进程未确认退出前，禁止修改相关媒体源及再次执行同一预览，不能提前生成回滚计划。桌面/服务异常退出后的遗留槽可由服务机器维护者只读查看：

```powershell
$env:PYTHONPATH = 'backend'
.\.venv\Scripts\python.exe -m app.recover_renames --config config/config.toml
```

预期结果：输出有界批次ID、状态、PID和租约摘要，不读取媒体、不打印凭据、不改数据库。常见错误：配置/数据库缺失、版本不匹配或无法确认进程状态时拒绝维护，不初始化另一个实例。释放槽位须先停应用及全部worker，再指定 `--apply --operation-id <批次ID> --confirm-service-stopped`；工具仍检查PID，活进程或PID未知会拒绝。释放仅维护槽位和审计，不解决未知文件动作、不重新执行批次。

## 10. 刮削设置

进入“系统设置”，打开“刮削设置”分类。

可配置：

- 启用 TMDB。
- TMDB V4 只读访问令牌。
- TMDB V3 API Key。
- 请求语言。
- 地区。
- 接口超时时间。
- 站点优先级。
- 最小扫描文件阈值。

系统优先使用 V4 令牌；V4 失败后自动降级使用 V3 API Key。

保存后可点击“测试连接”验证配置。弹窗会分别展示 V4 和 V3 的连接结果、响应时间、失败原因和最终可用通道；成功时会明确说明当前实际连通的是 V4 还是 V3。

## 11. AI 智能解析设置

进入“系统设置”，打开“AI 智能解析”分类。

可配置：

- 启用 AI 智能解析。
- Provider 配置列表，支持新增、编辑、删除和一键切换当前激活配置。
- 服务商，支持 DeepSeek、OpenAI Compatible 和自定义兼容服务。
- 模型名。
- API Key。
- Base URL。
- 接口超时时间。
- 限流最大重试次数。

普通AI解析和连接测试仅对明确的HTTP429限流响应重试，次数为首次请求之外的上限。等待遵守Retry-After，缺少有效等待值时使用有上限的退避；等待和后续请求共用配置的超时预算。401/403、网络断开、超时、5xx和无效响应不自动重发，以免重复计费。该预算不等于能够强制中断所有底层阻塞读取。

当前激活的 Provider 会同时影响：

- 单条 AI 解析。
- 批量 AI 匹配。
- TMDB→AI 串联后备匹配。
- AI 连接测试。

保存后可点击“测试连接”。状态栏会显示连接结果、当前 Provider、模型和完整更新时间。批量 AI 入口只有在当前激活 Provider 配置完整且连接测试通过时才允许直接执行。

连接测试由后端直接调用已保存的配置并保存结果，浏览器不能自行提交成功状态。重命名页只读取“已就绪、未测试、配置已变化、测试失败”四类通用状态，不显示 Provider、模型、请求地址或敏感词等设置明细。修改当前 AI 配置后需要重新测试连接。

AI 解析失败不会影响本地解析、TMDB 匹配、待处理文件和安全重命名。

## 12. 敏感词设置

进入“系统设置”，打开“敏感词设置”分类。

可配置：

- 是否启用默认敏感词库。
- 默认影视风险词。
- 自定义敏感词。

多个词使用 `||` 分隔。命中文件名、路径或解析标题后，系统不会提交 TMDB、IMDb、AI 或后续外部刮削源。

`AV` 等短 ASCII 风险词按完整片段匹配：目录名或文件名片段为 `AV` 时仍会拦截，但 `save`、`avatar` 等普通单词不会因包含相同字母而误判。

页面提供外部提交拦截记录列表。用户可以将记录标记为已改名、忽略、确认风险继续提交或归档。

点击“继续提交”后，确认窗口会按当前生效策略重新核对文件名、路径和解析标题，并显示本次命中的脱敏词及数量。这里展示的是本次授权的确认范围；列表中的原始命中摘要仍表示最初拦截原因，不会被覆盖。确认窗口打开后如果敏感词或服务配置发生变化，提交会被拒绝且不会调用外部服务，需要重新打开确认窗口。

v1.2.0的“继续提交”先显示文件/路径、解析信息、目标配置、认证通道和授权有效期。填写风险确认原因后只调用指定的AI或TMDB，不切换其他站点、不自动应用候选或重命名。授权绑定当前用户和配置，使用后不能重用；文件、媒体源或配置变化需重新确认。

“查看结果”和弹窗中的刷新只读取本次结果，不重新提交。明确服务拒绝显示失败；网络中断或未保存确定结果显示未知，需要人工核查，不能通过改记录状态绕过。一次性覆盖入口关闭自动重试。历史“已继续提交”状态显示为“历史确认（未验证）”，不代表实际调用成功。旧版本不包含此流程。

## 13. 待处理文件

待处理文件列表位于命名预览页面的标签页中，主要展示低于最小扫描文件阈值或无需刮削的文件。

支持：

- 单条移除任务记录。
- 单条 AI 解析并查看候选结果。
- 清空列表。
- 批量迁移真实文件。

移除和清空将待处理记录标记为已移除，不删除源文件。批量迁移会移动真实文件，请确认目标目录正确。

v1.2.0待处理列表独立分页，每页10或50条；清空范围仍是所选来源/扫描任务的全部待处理记录，不限当前页，确认框显示全局待处理条数。迁移仅操作选中项；“迁移中”和“需要恢复”项不能再次迁移、提交AI或移除。写入后重新读取当前页，超出末页会自动收敛；部分迁移失败不会自动重放文件操作。

迁移操作（v1.2.0）：选中待处理记录，填写服务机器可访问的绝对目标目录并确认。预期结果：立即进入已排队/执行中状态，按秒显示实际已迁移、失败和未完成数量；有日志权限时自动打开实时日志。受理不保证目录存在或可写，目录及文件检查在后台进行。目标冲突不会覆盖，失败停止后续条目，前面已迁移的文件不会撤销。

离开页面不会取消后台任务，可从任务治理进入同一迁移，或保留带请求标识的页面地址继续只读查看。状态条的“刷新”“详情”和“日志”不重发迁移。常见错误：请求超时/断线后结果未知，先刷新原任务，不重复提交；按请求标识暂时未找到仍可能是原请求在途，不自动放行重试。需要恢复表示真实文件动作尚未确定，先停服核对，不能仅凭源缺失或目标存在认定成功。遗留槽维护见24.3。

待处理文件 AI 解析只展示候选结果，不直接生成命名预览，也不直接回填目标文件名。

## 16. 登录、权限和用户维护

首次启用认证且用户表为空时，登录页会显示“初始化管理员”入口。初始化成功后入口自动隐藏，后续登录只展示普通登录表单；完整系统重置并清空数据库后，初始化入口会重新开放。

“系统设置 → 通用设置”中的“允许初始化管理员”仅对拥有 `settings:write` 权限的管理员开放。该开关只在用户表为空时生效，不能绕过已有用户校验重复创建管理员。新安装默认通过页面初始化管理员；无人值守部署如需自动创建默认管理员，可在配置文件中显式启用 `default_admin_enabled`。

系统设置中可以维护本地用户：

- 新增用户。
- 修改显示名称。
- 启用或停用用户。
- 重置临时密码。
- 勾选直接权限。

常用权限包括：

- `settings:write`：保存系统设置和维护用户。
- `source:write`：新增、编辑、删除媒体源。
- `scan:run`：创建扫描任务。
- `rename:execute`：执行真实重命名。
- `rollback:execute`：创建、dry-run 和执行回滚计划。
- `metadata:submit`：提交外部匹配或覆盖外部提交拦截记录。
- `audit:read`：查看审计日志。
- `task:manage`：查看任务治理页面。

默认管理员密码登录后，页面会提示修改密码；暂不修改时，下次登录继续提示。密码只保存哈希，不保存明文。改密成功后全部旧会话失效，请使用新密码重新登录。

管理员应急恢复需在服务机器上操作：先在实例配置中开启 `auth.admin_password_reset_enabled`，从项目或发布包根目录执行以下命令，恢复后登录改密并关闭开关。普通页面及匿名 HTTP 接口不能重置管理员密码。

```powershell
$env:PYTHONPATH = "backend"
.\.venv\Scripts\python.exe -m app.admin_recovery --config config/config.toml
```

预期结果：提示管理员密码已恢复、旧会话已失效；使用实例配置的默认管理员密码登录，页面再次要求改密。配置或数据库不存在、开关关闭时恢复拒绝；若提示完成审计失败，密码可能已恢复，应先核对恢复意图而非盲目重复操作。容器/Linux 使用其对应 Python 可执行程序运行相同模块。

## 17. M10 多源元数据源

v1.2.0：刮削设置的“多源整体等待预算”默认30秒，允许1至300秒。parallel按可用站点有界并发，fallback按优先级逐站点；繁忙站点提示未发起，预算耗尽不再开始下一站点。各次HTTP还共享同机实例的速率/在途预算，配置及失败排查见24.2；超时不代表底层请求取消，不自动重放。

M10 的目标是把 TMDB、IMDb、Bangumi、TVDB 和用户自备豆瓣代理纳入统一配置和匹配编排模型。

截至 `0.10.7`，多源元数据源基础能力已落地；截至 `0.11.4`，前端补充源配置已改为同一卡片 Tab 展示，支持折叠状态保存，多源匹配完成后可在结果弹窗中查看每条记录的 Provider 执行结果，并继续进入候选回填。

- 元数据源配置表和配置接口。
- Provider registry。
- 重命名预览多源匹配后端入口。
- `primary_only`、`fallback`、`parallel` 三种编排模式。
- 多源候选去重键、来源优先级、字段完整度和字段来源记录。
- 批量多源匹配 Provider 摘要。
- 敏感词和外部提交保护复用。
- Bangumi 动画条目真实搜索、连接测试、失败隔离和统一候选映射。
- TVDB 剧集条目真实搜索、连接测试、季集信息和 episode title 补充。
- 用户自备豆瓣代理真实搜索、连接测试、失败隔离和统一候选映射。
- 系统设置“刮削设置”中的补充元数据源配置卡片。
- 重命名页面多源匹配按钮、匹配模式选择和批量确认提示。
- 多源匹配结果查看入口。
- 多源候选弹窗中的来源标签和字段来源展示。

当前后端接口包括：

- `GET /api/settings/metadata-providers`
- `PUT /api/settings/metadata-providers/{provider}`
- `POST /api/settings/metadata-providers/{provider}/test`
- `POST /api/rename-previews/{preview_id}/metadata-multi-match`
- `POST /api/rename-previews/metadata-multi-match/batch`

安全规则：

- API Key 和 Token 只返回是否已配置，不返回明文。
- 豆瓣代理不内置第三方地址，必须由用户自行配置 Base URL。
- 豆瓣代理未配置 Base URL 时，不发起配置级连接测试。
- 豆瓣代理配置 API Key 后，仅随请求发送到用户配置的代理 Base URL。
- 命中敏感词或外部提交保护规则时，不调用外部 Provider。
- Bangumi Access Token 可选，保存后只在后端解密使用；搜索固定排除 NSFW 条目。
- Bangumi Token 只发送到官方 HTTPS 主机，可通过 `clear_api_key=true` 显式清除；连接测试要求系统设置写权限。
- TVDB API Key 必填，保存后只在后端解密使用；TVDB Base URL 只接受官方 `https://api4.thetvdb.com/v4`。

当前限制：

- v1.2.0“全部多源匹配”读取当前全部筛选结果中的合格目标，再确认固定ID集合；超出批量上限时拒绝，不仅执行当前页或静默截取前N项。正式旧版本仍按原列表范围执行。
- 多源匹配只缓存候选和状态，不自动修改真实文件名。

## 18. 审计日志和操作运行日志

审计日志用于追踪“谁在什么时间做了什么”。系统会记录登录、用户维护、系统设置保存、媒体源变更、外部提交覆盖、真实重命名和回滚执行。

v1.2.0后台按小批清理已明确过期的登录会话，不影响有效会话，不删除用户或安全审计。运行日志的保留天数不适用于安全审计；数据库删除记录后空间可复用，文件大小不保证立即缩小，系统不会在线自动执行VACUUM。

审计日志使用统一分页控件，支持切换每页 10 / 50 条，避免初次进入页面时一次性加载过多记录。

操作运行日志用于查看任务过程。扫描、重命名 dry-run、真实重命名和回滚会记录阶段、进度、警告、失败原因和结果摘要。

日志窗口支持：

- 自动刷新和手动刷新。
- 按级别筛选。
- 复制当前日志。
- 导出单任务文本日志。
- 日志被清理后显示中文提示。

审计详情和操作日志详情都会脱敏 API Key、token、密码和 SMB 凭据。

## 19. 重命名回滚

回滚只能基于已成功的重命名批次创建。

推荐流程：

1. 在重命名批次入口创建回滚计划。
2. 执行回滚 dry-run。
3. 确认源文件、目标路径和目录权限无问题。
4. 用户确认后执行回滚，计划先显示“等待执行”，由后台进程执行；有日志读取权限时自动打开回滚运行日志。
5. 页面持续查询原计划，查看已回滚、失败数量及逐项结果。离开页面只停止查询，不取消任务；从任务治理返回可定位原批次及回滚计划。

回滚不会覆盖已有文件。部分条目失败时，成功条目保留，失败条目记录中文原因。

连接中断或请求超时时，使用“刷新回滚计划”核对，不重新执行文件动作。执行中断会展示原因，原进程退出未确认时仍保留执行槽，相关媒体源和预览不可修改；其他重命名、回滚等待该槽释放。租约、权限失效或超过固定3600秒总上限会中断任务，但不能保证阻塞的网络文件系统立即退出。

服务机器维护者可在项目根目录只读核对遗留槽，需使用明确配置并设置后端模块路径：

```powershell
$env:PYTHONPATH='backend'
.\.venv\Scripts\python.exe -m app.recover_rollbacks --config config/config.toml --limit 100 --after-id 0
```

预期输出为有界计划列表，包含ID、状态、进程PID、到期时间和后续游标；命令不初始化缺失数据库、不操作文件。释放槽必须停服核对，使用 `--apply --plan-id <计划ID> --confirm-service-stopped`，且记录PID已退出；PID未知或仍存活时拒绝释放。释放只处理槽和审计，不自动重放未知文件意图，文件恢复需另行核对。

## 20. 任务治理

v1.2.0采用服务端分页，显示全部筛选结果的总数，排序作用于筛选结果整体而非当前页；查询/重置返回第一页，刷新保留当前页。归档历史任务不受前500条限制。请求失败会清除旧列表并提示，不以旧行冒充新的查询结果。

任务治理页面集中展示扫描任务、重命名批次、回滚计划、WebDAV恢复记录和未知文件动作审计。

支持按以下条件筛选：

- 任务类型。
- 状态。
- 媒体源。
- 时间范围。

每条任务可以跳转到对应页面，也可以查看关联操作运行日志。

任务归档规则：

- 归档后任务默认从任务治理列表隐藏。
- 勾选“显示已归档”后可以查看并恢复已归档任务。
- 归档只影响治理页面展示，不删除扫描任务、扫描结果、重命名批次、回滚计划或真实文件。

“未知动作审计”页签显示审计辅助记录的数量/逻辑容量使用率和待核查记录。达到80%显示告警；达到100%时新的文件动作会在执行前被拒绝。记录状态含待补写、待人工核查、已完成和已人工关闭。

人工关闭要求当前用户同时具备“查看审计”和“任务治理”权限。点击关闭图标后填写原因和核查证据；预期结果为记录转为“已人工关闭”，页面容量重新计算，并新增一条安全审计。该操作不移动文件、不修改业务任务，也不把结果标记为成功或失败；业务结论仍为unknown。原因或证据为空、记录已经完成、权限不足时拒绝。首次关闭证据不可被重复请求覆盖，不要在原因或证据中填写口令、令牌或密钥。

## 21. 系统日志

在扫描任务页面可打开操作日志。日志用于辅助排查扫描、预览、重命名和系统运行问题。

v1.2.0支持同机多个应用或worker进程共享日志目录。写入、轮转、归档和删除使用同一目录锁，Windows下不会因另一个进程持有活动日志句柄而阻止轮转。清理只处理受管活动日志、轮转日志和归档，锁文件不计入容量；变化中的文件会跳过并在后续维护周期重试。日志目录应位于同一主机可可靠加锁的文件系统，不把该机制视为跨主机分布式锁。

敏感信息规则：

- 不记录明文 API Key。
- 不记录明文密码。
- 不记录完整 token。
- SMB 凭据必须脱敏。

## 22. 列表通用规则

系统内列表统一遵循：

- 默认 10 条/页。
- 支持 50 条/页。
- 非服务端分页列表支持展示全部；服务端分页列表仅提供页面上的有界页大小。
- 文本靠左。
- 日期、数字和状态类字段按页面规则居中。
- 文件大小展示为自然单位。
- 时间不展示毫秒和时区。
- 长文本省略后可悬浮查看完整内容。
- 无数据时显示“暂无匹配数据”。

扫描结果在选择任务查询或从扫描任务跳转时加载。扫描任务页首次进入会读取历史列表并恢复对活跃任务的观察；命名预览按页面筛选与入口参数读取。不能把切换菜单视为所有页面均不重新查询。

## 23. 常见问题

### 23.1 后端连接异常

检查：

- 后端服务是否启动。
- 后端端口是否为 `8970`。
- 页面是否可以访问 `/api/health`。

### 23.2 保存媒体源失败

检查：

- 名称是否为空。
- 目标路径是否为空。
- UNC 路径是否以 `\\` 开头。
- SMB 类型是否填写账号。
- NFS 类型是否填写服务器和导出目录。
- 路径是否与已有媒体源重复。

### 23.3 已停用媒体源无法扫描

这是正常限制。请先在媒体源页面启用该媒体源，再发起扫描。

### 23.4 扫描后没有结果

检查：

- 目录中是否有支持的视频格式。
- 最小扫描文件阈值是否过高。
- 文件是否进入了待处理列表。
- 扫描任务是否已完成。

### 23.5 TMDB 匹配失败

检查：

- TMDB 是否已启用。
- V4 令牌或 V3 API Key 是否正确。
- 网络是否可以访问 TMDB。
- 代理是否配置正确。
- 接口超时时间是否过短。

### 23.6 AI 连接失败

检查：

- AI 是否已启用。
- API Key 是否已保存。
- Base URL 是否正确。
- 模型名是否正确。
- 网络或代理是否可访问服务商接口。
- 接口超时时间是否过短。

### 23.7 AI 解析被拦截

进入“敏感词设置”查看外部提交拦截记录。可以改名后重新匹配、忽略记录，或在明确风险后确认继续提交。

### 23.8 AI 回填后没有真实改名

这是正常行为。AI 只回填命名预览，不直接修改真实文件。请继续执行安全重命名流程。

### 23.9 重命名失败

检查：

- 源文件是否仍存在。
- 目标文件名是否为空。
- 目标文件是否已存在。
- 文件是否被播放器、下载器或其他程序占用。
- 当前服务进程是否有写权限。

### 23.10 回滚失败

检查：

- 当前文件是否仍在重命名后的路径。
- 回滚目标路径是否已存在。
- 目标目录是否可写。
- 是否已先执行回滚 dry-run。

## 24. 后续维护

### 后台探测与匹配

完成用户确认后，重命名干跑、回滚干跑、多源批量和AI批量进入后台队列；顶部“后台任务”查看原请求编号、已处理/总数、未知项、汇总/逐项结果和日志。最近任务下拉可恢复观察，任务治理也可打开原任务；关联干跑结果只打开批次，不自动执行文件操作。

受理响应超时或断开时，不重新创建任务，先查询原编号；明确已发出但未得到结果的条目需在供应商侧核查。“确认已核查”只解除本浏览器的防重复保护。普通结果已清理时查看结果禁用并说明原因，不能用同一编号重新执行。

结果默认保留7天、单任务4MiB、总逻辑预算64MiB，活动任务预留容量；超限可能拒绝受理或不保存候选，原请求不会重发。参数在config.toml的background_jobs，修改后重启。普通结果清理不删除幂等记录和安全审计，不保证SQLite物理文件缩小。详情见[后台接口与维护](../development/background-jobs/api-and-maintenance.md)。

### 24.1 一次性外发核查（v1.2.0）

在服务机器、项目根目录执行，只读核对明确实例：

```powershell
$env:PYTHONPATH = "backend"
.\.venv\Scripts\python.exe -m app.inspect_external_submissions --config config/config.toml --limit 200
```

预期结果：JSON摘要按授权ID分页，包含has_more/next_id、可能仍运行、未知结果、确定结果待补审计等标记，不输出路径、用户姓名或正文；下一页加 `--after-id <next_id>`。配置/库不存在或schema不兼容时返回失败，不初始化数据库、不发送网络请求。

停服并在供应商侧人工核查后，可增加 `--grant-id <授权ID> --record-observation verified_received --confirm-service-stopped` 记录审计观察；确认被拒绝用verified_rejected，无法确认用undetermined。该参数只是维护者停服确认，工具不负责停服。记录观察不覆盖原结果、不解除未知保护、不自动补候选或重发；不要据此重复执行同一外发。容器/Linux使用对应Python执行相同模块。

- `1.0.x` 以问题、安全和兼容性修复为主。
- `1.1.x` 可进行体验、性能和可观测性优化。
- FTP、FTPS、SFTP、S3 / MinIO 仅为未来候选能力，没有实施排期。

### 24.2 外部HTTP预算（v1.2.0）

操作：维护服务使用的明确config.toml，参考config/config.example.toml增加以下静态配置，保存后重启服务及worker。不是系统设置热配置，不需要填写API Key：

```toml
[external_requests]
max_concurrency = 4
[external_requests.ai]
requests_per_second = 2
max_concurrency = 1
[external_requests.metadata]
requests_per_second = 2
max_concurrency = 1
# 可选，TMDB覆盖元数据组默认值，其余字段继续继承
# [external_requests.providers.tmdb]
# requests_per_second = 4
# max_concurrency = 2
```

预期结果：每个站点默认最多1个实际在途请求，至少间隔0.5秒准入；同机同数据库最多4个实际请求。支持tmdb/bangumi/tvdb/douban_proxy/imdb覆盖，IMDb只包含已有网站可达性测试，不代表搜索接入。速率范围0.1至100，并发范围1至64；未知字段及非法值启动时拒绝。不同模型或URL路径共享同一scheme/host/port配额。本机/局域网AI也计入，不限制本地页面API/扫描/改名或WebDAV文件请求。

常见结果：

- “本次未发送请求”：排队截止、数据库不可用或容量拒绝；不是API Key鉴权失败。减少同时外发、适当增加调用超时，或在供应商许可内调整预算；一次性授权已经消费，需重新确认，不自动重发。
- “结果可能未知”：请求已开始，不能凭超时判断供应商未收到。AI未知请求不自动重试；在供应商侧核查，不通过重复点击猜结果。
- HTTP30x：不自动跟随重定向，检查最终Base URL，避免认证或额外请求越过预算。
- 长时间等待：日志可见wait_timeout、storage_unavailable、close/exit/release_failed_slot_retained等阶段及异常类型，不包含请求正文或密钥。无法确认关闭的存活进程槽不会仅按时间清除；确认所有服务及worker实际退出后再重启核对，不直接删库或槽来释放并发。

限制：等待占用配置超时，批量AI可能因此未发送就失败；间隔控制的是准入时刻，系统暂停后实际包发送不能保证匀速。仅限同机共享数据库，不能把SQLite部署在多机器共享盘当分布式限流；底层阻塞读取及供应商计算没有硬取消保证。

### 24.3 待处理迁移遗留槽核对（v1.2.0）

在服务机器项目根目录执行，必须指定实际实例配置；默认只读，不初始化缺失数据库、不探测或移动媒体：

```powershell
$env:PYTHONPATH = "backend"
.\.venv\Scripts\python.exe -m app.recover_pending_moves --config config/config.toml --limit 100 --after-id 0
```

预期结果：返回JSON分页摘要items/has_more/next_id，包含终态但仍保留执行槽的任务ID、状态、PID及租约时间。下一页指定 `--after-id <next_id>`。空列表不证明没有待核对文件意图，任务未到终态不会在该列表中展示。

停服并确认所有相关进程实际退出后，只对核对过的单个任务释放槽：

```powershell
.\.venv\Scripts\python.exe -m app.recover_pending_moves --config config/config.toml --task-id 123 --apply --confirm-service-stopped
```

将123替换为核对出的真实任务ID。预期结果：仅释放已知PID退出且任务终态的槽，保留成功路径和未知文件意图，不重新迁移；没有未知动作的未执行条目解除预约。常见错误：缺配置/数据库/schema不匹配则失败，不创建替代库；任务仍运行、PID未知或仍存活则拒绝释放。停服确认参数不负责终止服务，超时/kill请求不证明NFS进程已实际退出。未知意图需按本地文件恢复流程独立核对，不能直接删记录绕过。

### 24.4 扫描遗留槽核对（v1.2.0）

默认只读列出终态但仍保留执行令牌的扫描，以及状态为running但PID未知的交接窗口：

```powershell
$env:PYTHONPATH = "backend"
.\.venv\Scripts\python.exe -m app.recover_scans --config config/config.toml --limit 100 --after-id 0
```

预期结果：每项包含任务ID、状态、PID、租约时间、是否持有令牌和核对原因。`ownership_unknown` 只提示人工核对，不会自动中断、重放或释放；running任务即使指定`--apply`也拒绝释放。只有任务已进入终态、PID已知且确认进程退出后，才可按命令帮助中的单任务参数显式释放槽。扫描硬失败与租约同时失效时保留原始失败原因，并附加授权过期或监督中断原因，不用后续状态覆盖首因。

槽释放后继续只读核对未知文件动作：

```powershell
.\.venv\Scripts\python.exe -m app.recover_local_files --config config/config.toml --limit 200
```

预期结果：wouldRepair/wouldRelease/manual分别表示身份、实际目录项名称和动作阶段可证的已生效、未执行或需要人工处理；核对不移动、不删除文件。确认服务仍停止后加 `--apply --confirm-service-stopped` 才写入对账。已生效的文件路径、迁移条目和计数一起修复，未执行解除预约，任务仍保持中断且不继续。原执行审计保留，另记维护审计；仍持槽或关联不唯一拒绝修复。仅大小写不同的改名按目录实际保存的名称判断，硬链接、符号链接、第三方替换、源和目标同时存在及旧记录证据不足均保持manual。

manual记录只能在人工核对文件、目录项和备份证据后逐条结案；命令只修复数据库，不移动或删除文件：

```powershell
.\.venv\Scripts\python.exe -m app.recover_local_files --config config/config.toml --action-id 123 --resolution not_applied --reason "人工确认动作未生效" --evidence "核对目录项、文件摘要和备份记录" --confirm-service-stopped
```

将123、结论、原因和证据替换为本次核查结果。`--resolution` 只能是 `applied` 或 `not_applied`；原因上限500字符，证据上限2000字符。预期结果包含 `closed=true`，同时写入维护审计。未停服、证据为空、记录已结案或自动核对已有确定结论时拒绝人工覆盖。人工选择错误会使业务记录与文件事实不一致，因此不能将该入口用于批量清理或释放未经核查的记录。

## 25. 键盘操作（v1.3.0）

本节对应v1.3.0新增和修正的操作，不回写为v1.2.0已有能力。

- Tab或Shift+Tab移动到按钮，Enter或Space执行；表格操作的悬停提示不再拦截这两个按键。禁用按钮仍不可执行，不因键盘操作绕过权限或确认。
- 截断的表格文字、远程路径说明图标和TMDB超时帮助可用Tab获得焦点并显示说明；ESC关闭说明，焦点保持。全屏内先关闭文字提示，再按ESC才退出全屏；短文字、隐藏提示及按钮内部文字不增加独立停靠点。
- 全屏表格开关可用Enter/Space进入与退出，切换后焦点停留在开关。表格内部弹窗或下拉打开时，ESC先关闭内部浮层，不同时退出全屏。
- “解析重命名配置”中，Tab到命名元素主按钮，Enter打开格式项；ESC关闭并返回。F2编辑变量，Enter提交当前编辑、ESC取消，取消不修改变量；Tab离开编辑框按既有行为提交，不强行抢回焦点。
- 命名元素上按Shift+F10打开操作组，Tab到移动命令后Enter执行；ESC关闭操作组并返回原元素。删除按钮是独立Tab停靠点，删除后焦点移到相邻元素；编辑区的变化仍需点击保存才写入配置。

若快捷键由浏览器或系统接管，可继续使用既有鼠标入口；本节不声称覆盖全部读屏软件或全站WCAG验收。窄窗口操作组会换行，不通过缩小字体隐藏按钮。
