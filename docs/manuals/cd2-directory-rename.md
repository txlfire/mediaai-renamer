# CD2 受控目录改名操作说明

类型：操作手册。适用于schema55开发源码，非v1.3.0发布能力。正式媒体写入是否启用由管理员和验收结果决定，本文不授予写入权限。

## 准备

管理员在“系统设置 → 目录整理（CD2 / 115）”维护可信CD2 HTTPS地址、批准媒体根、公开CA和映射修订，配置仅入库；见[配置手册](cd2-settings.md)。按用户直接分配权限，目录写开关默认关闭。普通执行页面不能传入替代地址、扩大根或跳过保护。

| 操作 | 必要权限与归属 |
| --- | --- |
| 打开目录整理、盘点及维护本人观察 | `scan:run` |
| 固定/查看本人目录计划 | `cloud-directory:plan`；页面还需`scan:run` |
| 执行目录改名及只读位置核对 | 在计划权限基础上另需`cloud-directory:execute` |
| 查看/导出本人运行日志 | 另需`audit:read`，仍核对本人计划权限及所有权 |

只看建议不分配执行权限；不需日志时无需分配`audit:read`。缺权限时入口不可用或返回403，不应误判为日志已清理。管理员维护预算需`settings:write`，不能替代本人计划或执行权限。

运行构建须整组匹配[精确版本表](../development/cloud-drive/cd2-runtime-compatibility.md#1-当前结论)；公司1.1.2与家庭1.1.3不能混搭CD2/CLOUDAPI构建。两套精确构建的空目录C2产品链均已通过正向、反向新计划及冲突拒绝验收；这不代表运行中的NAS候选已升级，也不授权正式媒体写入。出现`runtime_not_verified`应停止并核对版本及原动作记录，不反复提交、伪造版本或手工释放未知保护。

先安排维护窗口，确认没有其他客户端修改相关父目录。目录改名不具备服务端原子源身份保护，发送前后的身份检查不能消除外部并发替换风险。只处理同父目录最多五项，不移动、合并、删除或读取媒体正文。

维护期间不要重启CD2、重绑云账号或改变挂载映射。发生这类变化时先关闭执行，核对并更新配置中的映射修订后重新盘点；手工配置修订不是服务端账号世代证明，不能认为相同路径和ID必然属于原账号。

CD2令牌精确绑定计划父目录。执行只允许`allow_list`、`allow_rename`、`allow_view_runtime_info`；只读位置核对只允许`allow_list`和`allow_view_runtime_info`。连接器自检时剩余有效期须为1至600秒，不能使用永久或额外权限Token；这些权限不包含创建、移动、删除或正文读取。不要粘贴主账号密码或全权限令牌，不把令牌保存到文档。页面必须经可信HTTPS打开。

## 生成计划

1. 打开“目录整理”，选择实际分类目录执行本层受控盘点。大库从电影/地区等较小分类开始，不选2PB整盘根递归扫描。
2. 等盘点结束且范围完整，选择需要处理的一至五个同父目录，填写实际要去除的字面净化词，生成固定计划。
3. 核对原名、目标名及条目集合。翻页不会扩大计划；季目录、光盘结构、保留条目、身份缺失和疑似冲突会被拒绝。

预期：此时只创建本地计划，没有云端改名。观察清理/变更、策略变化或30分钟过期后不能执行旧计划，须重新盘点确认。计划总量上限1000，包括取消和反向计划，达到上限停止，不删除历史证据规避容量限制。

当前网页本层盘点上限100条、1MiB；达到条目上限即保守停止，该层可能不完整，不能只看返回100条就认为全部读取。目录改名必须完整盘点其**父目录**，再选其中子目录；进入影片目录内部盘点不能给这个影片目录本身改名。若原有分类更小且能提供目标父层完整观察，可选择该分类；平铺父目录达到上限而无更小有效父层时，当前网页链不支持，保留原目录，不重复读取前缀或扩大Token绕过。同父1000观察项只是内部计划校验上限，不代表网页会自动读取1000条。容量提升和历史归档需另行设计。

## 执行与查看

进入“受控执行 / 核对”，检查维护窗口及旧计划失效两项确认，提交对应临时Token。预期：按固定集合串行检查身份、目标冲突、发送一次改名并核对结果。应用请求预算为`3+7×项数`次、180秒、1MiB元数据，等待也计时。

窗口显示逐项状态、消耗及原因；运行日志入口沿用系统日志保留和容量设置。日志已清理时按钮禁用或提示，但执行意图及对象身份证据仍保留供核对，CD2 Token不持久化。取消只停止后续动作，不能撤销已发请求。

关闭或隐藏页面只清除尚未交接的Token输入，不取消已受理动作，也不证明远端停止。成功、取消或失败后，保留原请求编号，在CD2撤销本轮临时Token并核对不存在；有未知结果时继续保留保护并按下节核对，不能用Token已撤销推断原RPC未执行。反向计划和新只读核对分别使用新Token，旧一次授权不复用。

完成表示远端核验和本地路径修订均完成；旧扫描和文件计划整体失效，不自动重新扫描。需要继续处理文件时，人工重新选择小范围盘点/扫描。

请求超时、断连或页面重载时，使用原请求编号“核对原执行”，不要重复点击创建相同动作。也可以从“目录计划记录”恢复本人记录；列表和查询不会重新发送改名。

## 未知或部分执行

1. 保留原执行编号和日志，不手工删除数据库或保护槽。
2. 确认旧进程已退出、远端请求已静止，等待共享冷却结束。进程退出本身不证明远端未执行。
3. 打开“只读核对当前位置”，提供新的精确父目录只读Token及两项确认，批准独立核对预算。
4. 查看每项“仍在原名称”“位于目标名称”或“位置有歧义”。有歧义保持冻结，不能强制同步。
5. 全部位置确定且worker回收后，再明确确认“仅同步核对位置”。预期：只提交本地修订，原未知历史不改写为成功，也不发送云请求。

每轮核对最多`4+2×项数`次、90秒、1MiB；每原计划最多五轮。新一轮必须再次确认独立预算，不自动重试。位置证据从最早精确查询起最多有效300秒，过期需新的明确核对。Token错误、权限过多、身份变化、旧进程存活或冷却未结束时，先处理提示，不扩大权限或换路径试错。

若旧服务退出后本轮只读核对槽仍保留：由记录所有者在具备计划、执行及系统设置权限时，先“核对原请求”，再点“核对只读进程”，确认原监督服务/只读进程退出及相关远端静止后“确认归还只读槽”。预期仅归还这一轮只读槽，原改名冻结及未知记录保留，不发云请求；随后另行批准新一轮核对。403先核权限，409先核修订、主机或进程，不能手工改PID/槽位。结果不明时按原核对编号查询，不直接重复提交。

如果预算显示手动暂停，只读核对不会自动解除。管理员先确认目录worker正常回收、远端静止、冷却结束，再按[预算维护接口](../development/cloud-drive/c0-budget-implementation.md)撤销手动暂停意图。预期仍显示paused/request_incomplete及目录保护；之后再由计划所有者执行上面的新预算核对。普通“恢复预算”不能清除目录保护，禁止直接改库。

## 恢复原名

原计划完成或当前位置已明确同步后，可点击“生成反向新计划”。预期：只生成一份新固定计划，不立即改名；恢复核对后仅包含实际位于目标名的条目。重新检查名称、冲突、权限、维护窗口和Token后才可执行。

反向是新的云端写入，不是数据库回滚，也不保证永远可用。其他计划推进路径世代、配置变化、目标已存在或来源位置不明时会拒绝。不要通过手工修改计划或重发旧执行规避拒绝。

部署、真实产品验收和实机缩放状态以[验收清单](../development/cloud-drive/c2-acceptance-checklist.md)为准。广告文件取样、隔离和删除不属于本功能。
