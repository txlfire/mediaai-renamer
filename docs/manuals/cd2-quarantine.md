# CD2 文件隔离与反向恢复

文档类型：操作手册。适用于未发布开发源码schema55，不属于稳定v1.3.0功能；实机放行状态以[验收记录](../development/cloud-drive/c4-acceptance-report.md)为准。

2026-10-20公司1.1.2及家庭1.1.3精确构建均通过各自两个合成TXT的最小Token产品正向、反向新计划和同名保护验收，夹具/Token及临时实例收尾已核对。运行中NAS候选未部署家庭兼容增量，不能据此直接开启正式媒体写入。执行仍默认关闭，实际操作须逐项核对批准目录、身份、权限和维护窗口。

## 1. 使用前提

- 当前开发连接器仅整组识别[版本表](../development/cloud-drive/cd2-runtime-compatibility.md#1-当前结论)所列的公司1.1.2及家庭1.1.3精确CD2/CLOUDAPI组合，拒绝混搭和未验Build；两组合的小夹具产品链通过不等于正式媒体授权，现有NAS候选亦未因源码变动自动升级。遇到`runtime_not_verified`不要反复提交、伪造版本或直接释放保护，先核对运行构建和原动作记录。
- 管理员在“系统设置 → 目录整理（CD2 / 115）”配置可信CD2 HTTPS端点、公开CA、批准根与映射修订，配置保存于数据库；“启用受控同云隔离”默认关闭，见[配置手册](cd2-settings.md)。独立授予`scan:run`、`cloud-quarantine:plan`和执行时的`cloud-quarantine:execute`，目录改名权限不能替代。
- 在选定父目录下事先建立专用隔离目录，默认名`_MediaAI_Quarantine`，并完成该父目录的小范围盘点。产品不会自动创建目录或递归补扫。
- 实际移动必须处于维护窗口，停止其他客户端对相关目录的修改。当前接口无原子源身份条件，无法防御外部并发替换。
- 前端也必须通过可信HTTPS访问。移动Token精确绑定计划共同父目录，仅允许列目录、移动、运行信息；不得填写主账号密码或带删除/创建/写入权限的Token。

## 2. 固定隔离计划

### 权限与令牌

| 操作 | 当前必要权限 |
| --- | --- |
| 进入目录整理与盘点 | `scan:run` |
| 本人复核、固定/查询隔离计划 | `scan:run`、`cloud-quarantine:plan` |
| 执行隔离、只读位置核对与本地提交 | 上述权限另加 `cloud-quarantine:execute` |
| 查看或导出本人运行日志 | 另加 `audit:read`，仍核对业务权限及本人记录 |
| 配置及预算维护 | `settings:write`；不是业务执行权限的替代 |

移动Token只允许`allow_list`、`allow_move`、`allow_view_runtime_info`；只读位置核对Token只允许列目录与运行信息。两者精确绑定该计划共同父目录，其他已知权限须为false，未知权限也拒绝。连接自检时剩余有效期须在1至600秒内；短于操作预算仍可能中断，不承诺即将过期的Token能完成任务。每次结束由用户在CD2撤销Token并核对不存在；关闭页面、清理日志或保存系统设置均不等于撤销。

操作：进入“目录整理”→“广告人工复核”或“复核记录”，打开本人当前固定清单。明确勾选1至5个“建议隔离”的普通文件，点击“准备隔离计划”；选择已观察到的专用隔离目录，确认仅固定本地计划，再点击“固定计划”。

预期：默认不选文件和目标。计划保存原名、文件身份、大小、来源与目标、人工理由及证据。此步不发送云请求、不移动文件；有效期30分钟，每次仅同父目录小批量。

常见错误：未盘点目标、保护文件、观察清理/修订、保留例外或路径世代变化均不能沿用旧证据。目标不存在时先由用户建立，再重新盘点所选小范围；不要扩大为整盘扫描。

## 3. 执行与查询

操作：核对固定计划，点击“受控隔离”。核对Token根、权限和页面预算，填写短期Token，分别确认维护窗口及全局失效保护后提交。

预期：一次受理最多`3+9×项数`应用RPC、180秒、1MiB元数据，所有等待计入截止。每项先检查身份、双父目录和目标缺席，再移动并检查实际位置；同名不覆盖、不跨云、不递归。RPC成功或Skip成功不等于文件已移动。Token仅内存交接，请用完到CD2撤销。

操作：受理后查看状态；需要过程时点击“运行日志”。完成后核对逐项位置，确认无其他客户端修改，再点击“同步本地修订”。

预期：工作进程退出并不自动释放业务保护；本地同步不发送云请求，推进全局路径世代，使旧扫描/文件计划失效，不自动补扫。日志按系统保留天数、全局/单任务大小设置清理，清理后按钮置灰；固定动作和审计证据仍保留。

常见错误：提交响应不明确时，保留地址栏`quarantine_plan_request_id`、`quarantine_run_request_id`，点击“核对原请求”。不能生成新编号重复执行。关闭弹窗只清除临时输入，不取消已经受理的动作。“停止后续请求”也不能撤销已发RPC。

## 4. 未知结果与只读核对

操作：原工作进程退出且相关远端已静止后，打开原动作，点击“新只读核对”；使用同一精确根、仅列目录与运行信息权限的新短期Token，确认后提交。

预期：使用独立UUID和新预算，每轮最多`6+2×项数`RPC、90秒、1MiB，最多5轮。只查固定对象和父目录，不移动、列其他目录或读取正文。原未知事实保留；只有最新完整、300秒内、worker已退出且位置明确的证据才可同步。旧普通提交不能绕过核对交接。

常见错误：位置歧义、身份/大小不符、旧进程未退出或证据过期时继续保留保护，不自动重试。管理员可在“维护操作”核对本机旧进程；必须确认旧worker及owner实际退出。手动暂停的受限解除只撤销暂停意图，不清未知、不释原保护、不自动发请求；之后仍需新只读核对。

## 5. 反向恢复

操作：当前位置已完成本地同步后，点击“准备反向计划”，核对原名和固定身份，再以新Token、新维护确认执行。

预期：只对当前世代已确认位于目标的文件生成新计划，交换来源与目标、保留原名，不是自动回滚或旧动作重放。原位置若已有同名文件则不覆盖。执行后仍须核对位置并再次同步本地修订。

## 6. 保留边界

不提供永久删除、自动清空隔离区/回收站、正文下载、OCR、视频取帧或AI内容判断。小夹具实机验证不证明任意媒体大小、其他CD2版本或115风控安全。固定计划全库上限1000条/64MiB逻辑JSON，满额停止新增；普通日志清理不能代替批准、未知或审计归档，也不会在线压缩数据库。

## 7. 查询状态与下一步

查询响应中的 `networkAccess=false` 只说明本次查询读取本地记录，不代表历史动作没有发过云请求。应同时查看 `kind`、`status`、`reason`、`workerSlotHeld`、`globalSlotHeld`、`committedEpoch` 及逐项结果，不能仅凭HTTP200或“review”判断成功。

| 当前记录 | 含义与下一步 |
| --- | --- |
| `accepted` / `running` | 已受理或执行中；查询原编号，可停止后续请求，不重复POST |
| `review`、`awaiting_path_sync`，worker已退出 | 远端核验结束但本地未提交；核对逐项结果和300秒证据有效期后明确同步 |
| `review`、未知/身份异常，或原全局槽仍持有 | 保留保护，先确认原进程退出和远端静止，再单独批准新只读核对；不是重放移动 |
| `kind=observe`、`review`、`positions_observed`，worker/本轮槽已释放 | 已观察固定对象位置；仍需最新轮次、完整无歧义且未过期，才能明确提交原动作的本地修订 |
| `completed` 且 `committedEpoch` 非空 | 普通动作已提交本地修订；需要恢复时生成反向新计划，不重用原请求 |
| 原动作 `review`、`positions_reconciled` 且 `committedEpoch` 非空 | 原未知事实保留，当前位置已由新核对提交；不能把原未知回执改称已响应成功 |
| `cancelled` | 已停止本轮后续处理；仍核对原动作/租约，不推断远端从未发送 |

完整HTTP字段及本地事务条件见[响应契约](../development/cloud-drive/c3-quarantine-contract.md)，按钮是否可用还受当前权限、修订和保护状态控制。
