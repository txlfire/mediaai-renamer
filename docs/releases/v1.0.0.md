# MediaAI Renamer v1.0.0

`v1.0.0` 是 MediaAI Renamer 的首个稳定版本。M1-M11 核心产品范围已经完成，后续默认进入维护和优化周期。

## 核心能力

- 本地、Windows UNC / SMB、已挂载 NFS 和 HTTPS WebDAV 媒体源。
- 全量 / 增量扫描、最小文件阈值、待处理列表和手动排除。
- 命名模板、双语字段、标题来源模式、预览编辑和冲突检查。
- TMDB、IMDb、Bangumi、TVDB、豆瓣代理和 AI 辅助匹配。
- 敏感词外部提交保护、拦截记录和人工覆盖确认。
- dry-run、禁止覆盖、安全重命名、回滚、审计和任务治理。
- 本地用户、权限、默认密码修改提醒和用户信息维护。

## WebDAV

支持：

- HTTPS。
- 无认证、Basic 和 Bearer。
- 连接测试、目录浏览和递归扫描。
- 文件大小、修改时间和 ETag。
- MOVE dry-run、真实 MOVE、反向回滚和失败恢复。
- 远程写锁、幂等操作记录、禁止覆盖和任务治理恢复入口。

不支持：

- HTTP WebDAV。
- Digest。
- 跳过 TLS 校验或自动信任不受信任证书。
- 跨媒体源移动和跨 WebDAV 站点复制。
- FTP、FTPS、SFTP、S3 / MinIO。

## 从 v0.10.7 升级

1. 停止旧服务。
2. 备份 SQLite 数据库、正式 `config.toml` 和日志目录。
3. 下载 `v1.0.0` 发布包或拉取 `v1.0.0` GHCR 镜像。
4. 保留现有运行数据和正式配置，不要用示例配置覆盖。
5. 启动服务，后端会自动执行兼容性数据库迁移。
6. 登录后检查媒体源、系统设置、用户权限和任务治理。
7. 使用测试目录验证扫描、预览、dry-run、重命名和回滚。

fnOS / NAS 推荐：

```bash
docker compose -f docker-compose.ghcr.yml pull
docker compose -f docker-compose.ghcr.yml up -d
```

## 数据与备份

- 升级前必须备份数据库。
- 发布包只包含 `config/config.example.toml`，不包含正式 `config.toml`、数据库和日志。
- WebDAV 私有 CA 需要由管理员加入容器或系统信任链。

## 已知限制

- fnOS / 各 NAS 厂商 WebDAV 和反向代理实现存在差异，需要按部署说明人工验证。
- MOVE 固定禁止覆盖目标；目标存在时必须调整命名结果。
- 当前 ETag 用于扫描指纹，不声明通用源版本条件写能力。
- FTP、FTPS、SFTP、S3 / MinIO 没有实施排期。
