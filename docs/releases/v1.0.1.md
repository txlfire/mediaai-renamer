# MediaAI Renamer v1.0.1

`v1.0.1` 是稳定维护版本，重点完成 Docker 单容器发布和前后端统一发布包。

## 主要变更

- FastAPI 同时托管 Vue 页面和 `/api` 接口，保留 SPA 路由回退。
- Docker 由前后端两个镜像、两个容器合并为一个镜像、一个容器。
- `8970` 和 `8971` 两个兼容端口均映射到同一应用进程。
- GHCR 统一发布 `ghcr.io/txlfire/mediaai-renamer:<tag>`。
- Windows 和 Linux 发布脚本统一生成
  `mediaai-renamer-v1.0.1.zip`，同时包含前端和后端。
- 正式 `config/config.toml` 不再由 Git 跟踪，发布包只包含示例配置。
- 将间接依赖 PostCSS 升级到安全版本，npm 审计结果为 0 漏洞。

## fnOS 实机验证

已在 fnOS `x86_64` 环境完成以下验证：

- 卸载旧 `mediaai-renamer-backend` 和 `mediaai-renamer-frontend` 双容器。
- 保留并复用 `data/`、`logs/` 和 `config/` 持久化目录。
- 从当前源码执行多阶段 Docker 构建。
- 单容器启动、Docker daemon 重启和容器重启后均保持正常。
- `8970`、`8971` 的首页、健康接口、SPA 路由和静态资源均通过。
- 缺失静态资源正确返回 404。
- 最终镜像环境中不包含构建代理变量。

## 升级说明

升级前请备份数据库、正式配置和日志。旧双容器用户执行：

```bash
docker compose -f docker-compose.ghcr.yml down --remove-orphans
docker rm -f mediaai-renamer-backend mediaai-renamer-frontend 2>/dev/null || true
docker compose -f docker-compose.ghcr.yml pull
docker compose -f docker-compose.ghcr.yml up -d
```

新版 Compose 只应显示 `mediaai-renamer` 一个运行中的容器。
