# MediaAI Renamer v1.2.0

发布日期：2026-10-14。[正式Release](https://github.com/txlfire/mediaai-renamer/releases/tag/v1.2.0)已发布，标签来源为`6d32bb986d4e9a2a70481c5157967429970252a3`。

## 主要变化

- 三套完整主题：清爽专业、柔和彩色、精密高对比，独立切换系统/亮色/暗色。统一工作台、表格、输入、浮层和登录页，不只修改按钮颜色。
- 常用桌面布局重排，低高度操作区换行，设置分类可滚动；Provider当前/操作固定，全屏表格进入/退出保留选中状态。
- 干跑、回滚干跑、多源批量和AI批量后台202受理，稳定UUID恢复观察，顶部查看进度、逐项结果、关联批次及日志。未知请求不自动重放。
- 结果默认单任务4MiB、总64MiB、7天，普通结果清理与安全审计分开；清理后禁用查看，保留幂等摘要。聚合结果超限保留逐项已知结果。
- 审查修复整合：服务端分页、确定批量范围、当前权限/输入/租约复核、文件写FIFO、持久化文件动作意图及恢复、一次性外发授权、HTTP共享预算、日志跨进程轮转、独立凭据密钥和依赖哈希锁。
- 修正迟到成功/401覆盖新会话、重复活动查询、分页页码不收敛、超限请求提前外发、混合WebDAV Destination越界和匹配发布事务重入。

## 升级要求

1. 停止正式应用及全部worker，备份数据库、配置和原凭据密钥；先核对实际退出，不以超时或kill请求代替。
2. 第一次从旧版升级保持原数据库路径，启动后自动迁移到schema39，旧凭据转为独立密钥v3格式。旧密文绑定旧路径，不能在迁移前随意改路径。
3. 使用固定版本包或ghcr.io/txlfire/mediaai-renamer:v1.2.0，确认健康版本和账户登录，再核对媒体源/预览。不要将演练数据用于正式库。
4. 回退必须恢复相匹配的旧数据库、配置及密钥，不让v1.0.1源码读取schema39或v3密文；不要用新密钥替换丢失的旧密钥。

Windows开发服务优先运行`npm.cmd run dev:windows -- status`，已停止才start。运行中start会替换旧实例，不把Python静态服务器用于前端；详见[开发指南](../development/development-guide.md)。部署和恢复见[fnOS说明](../deployment/fnos-ghcr-docker.md)。

## 已知边界

- WebDAV仅HTTPS，严格TLS校验；必须先通过端点条件MOVE安全验证才开放真实写。某些NAS不满足条件MOVE语义时，只支持读取/扫描/预览，不绕过门禁。
- 原同步API保留兼容，遗留TMDB批量及AI后备组合并未全部转换为四类后台入口。
- 结果逻辑容量不等于SQLite/WAL物理上限，小型幂等记录保留；审计独立保留/物理停服维护、登录限速及内网部署政策仍需确认，不默认删审计或VACUUM。
- 常用CSS视口自动化不替代4K、Windows200%与浏览器125%的实机验收；NFS硬阻塞、所有供应商实账单及正式实例升级回退不由合成回归证明。
- Vite主包仍有500kB大小警告；未关闭或隐瞒。验证范围、命令及证据见[本轮工作记录](../work-logs/progress-2026-10-14-background-release.md)。
- Windows本地临时TLS测试服务存在间歇性探测/恢复unknown，失败证据保留；Linux受控协议验证通过不能替代所有Windows/NAS断链窗口验证。
