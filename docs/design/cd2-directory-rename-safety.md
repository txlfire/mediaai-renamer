# CD2 目录改名安全设计

类型：安全设计。日期：2026-10-17。适用用户在空目录试验后确认的C2受控维护窗口边界。本文描述目标安全契约，不证明执行链已交付；能力证据见[评估](../development/cloud-drive/c2-capability-assessment.md)，实现与迁移见[实施计划](../development/cloud-drive/c2-implementation-plan.md)。

## 1. 范围

本期在C1本地建议基础上增加固定目录计划及受控执行。受控模式已获产品设计确认，实际执行默认关闭；开发批准不等于真实媒体写授权。未完成执行、恢复及路径一致性验收前不得开放写入口，不提供“强制执行”或跳过条件设置。

允许设计的首个写动作仅为同一父目录、同账号、同云盘内修改一个影片/剧集目录的basename。不迁父目录、不跨云、不合并、不创建临时目录、不经本地复制删除，不同时处理祖孙目录，不用临时名解决交换或环路。媒体根、云账号根、季目录、光盘结构、关联素材、压缩包/只读/加密虚拟对象及身份未知对象保持保护。广告取样、隔离、删除属于C3，不随C2开放。

## 2. 身份与原子条件

受控意图绑定服务端连接及信任配置摘要、批准根、经维护窗口确认的账号映射、源目录非空对象ID、父目录身份、原名、目标名及计划修订。名称、路径、显示账号、mtime及挂载inode不能单独充当远端身份；单次ID稳定不能外推到重启或账号重映射之后。

当前映射修订由管理员维护，不是已证实的CD2服务端账号世代令牌。受控窗口内不得重启CD2、重绑账号或改变挂载；发生变化先停用写入并重新建立观察与映射修订。相同路径和同样的ID字符串不能证明跨重映射仍为同一对象，不能把配置摘要检测宣传为自动识别所有外部映射变化。

当前CD2路径改名接口未证实原子源身份条件。首版采用用户已接受的受控维护窗口：其他客户端不修改、同父目录小批串行、发送前后核对身份及父关系、目标冲突必须拒绝且不覆盖。该模式不能消除最后检查到发送之间的外部源替换竞态；确认文本必须明确呈现残余风险，不能宣传CAS或任意并发安全。

原严格模式的“原子源身份＋受约束父关系＋禁止覆盖”目标保留为未来能力，不作为已经证明的CD2保证。受控样本只支持其端点、版本和场景；未知版本、改配、映射变化、目标/身份核对失败继续拒绝。未知结果禁止重发。

CD2与CLOUDAPI运行构建须作为不可拆分的组合匹配已确认版本，不分别按版本号匹配、不接受主版本通配或自动升级到更高Build。写连接器与只读恢复共用此规则；版本识别不替代端点实机验收、维护窗口、用户直接权限或单次动作授权。当前组合及验收边界见[版本核对](../development/cloud-drive/cd2-runtime-compatibility.md#1-当前结论)。

## 3. 计划与并发

- 名称建议、可执行计划和动作意图区分管理。建议没有执行权限；计划固定选定目录ID集合及规则/元数据版本，不因翻页、新盘点或目录增量扩大范围，不把本页筛选视为全部。
- 发布计划前绑定观察任务、条目代次、规则摘要和修订；缓存清理、保留变更、改配、撤权或身份变化使计划失效。观察完整只说明对应列举范围，不把本层完整外推到子树或最新云状态。
- 受理、实际发送和本地结果提交分别核对当前用户直接权限、所有权、策略、revision、租约和冻结；不引入角色，不能用现有scan:run或rename:execute隐式授权CD2目录写。新的直接权限标识在执行实现审批时冻结。
- 同源/目标、祖孙目录和映射变动必须受控。目录写与普通文件改名、回滚、迁移共享写入互斥；扫描发布、预览和媒体路径解析须遵守冻结。无法可靠映射来源别名时采用全实例保守互斥，不依赖不同media_source_id放行，不能以局部路径前缀猜测来源独立。
- 不在SQLite写事务中等待网络或重建巨型子树。共同槽、预算租约和子树冻结职责不同；释放某个worker槽不代表允许清除未知动作或远端RPC租约。

## 4. 预算与秘密

目录写及恢复核对使用独立批准的动作预算，并受相同账号/实例请求门禁协调，不能沿用只读会话余额或将写方法加进只读白名单直接发送。身份/目标核对、发送、结果核对分别计入RPC、时间和接收预算；管理维护另记，不承诺115固定安全频率。

用户提供的短期Token仅在可信HTTPS及局部内存交接中处理，不进入配置、URL、存储、日志和审计；最小写权限与精确范围必须单独核对，C1的仅列目录Token不可转用。只读元数据请求不得意外取得正文/下载链接；不强制刷新或递归统计来证明“目录安全”。

源与目标必须都是批准根内的严格后代，禁止改名批准根自身。Token的受限根需覆盖原父目录及两个名称，不能为改名一个目录而扩大到云账号根；具体最小根和写路径命名空间必须依据已证实的接口契约确定，不直接把C1的虚拟`/`当作可改名源。权限或范围无法表达时保持拒绝。

取消、超时、响应丢失和进程退出不等于远端未执行。所有层禁止自动重放未知写，包括代理、客户端重试及服务启动自动领取；是否支持远端幂等收据应按接口契约独立验证，不因本机requestId相同就认为远端幂等。

## 5. 动作状态与恢复

以下为执行链目标语义状态；具体已实现状态见实施计划，不能仅凭本表认为功能可调用：

| 状态 | 含义和允许转换 |
| --- | --- |
| blocked | 条件能力或授权不满足；仅展示建议，不能排队发送 |
| prepared | 仅保存固定本地意图；发送前条件未满足可明确取消，不视为云端改名 |
| sending | 发送事实已持久化，远端结果尚未知；取消只停止后续动作，不抹除本项 |
| outcome_unknown | 可能已发送或响应无法确证；保留身份、预算、冻结和意图，只能受控只读核对，不重新发送 |
| not_applied | 有可信证据证明本项未生效；记录原因后终止，不在原意图自动重试 |
| remote_applied | 已有契约有效的成功证据，或完整身份后置条件已核对；明确区分回执证明和当前状态证明，不伪造动作因果 |
| synchronizing | 远端结果已确认，本地路径修订未完成；持续冻结受影响子树 |
| committed | 有界业务同步及审计完成，满足条件后释放冻结；不改历史快照 |
| manual_review | 对象被外部再次移动/替换、账号映射变化或证据不足；保留冻结并交人工，不猜测成功/失败 |

成功响应后的本地写失败同样进入待核对，不补发远端动作。只读恢复查询也须有新批准预算，路径不存在/出现、相同大小和mtime不能单独证明成功。若无法证明请求从未发送，就不能按prepared取消而丢弃证据；worker退出仅是本机进程事实。

反向改名不是数据库回滚。恢复原名称是新的云端写，须重新核对对象、父关系、账号、原子条件及目标冲突并单独授权；不能承诺“撤销”永远可用。

独立只读核对每原计划最多五轮，每轮新UUID、`4+2×项数`次、90秒、1MiB预算；Token仅精确父目录的列目录和运行信息。旧进程退出、远端静止与冷却是新批准前提；关闭写开关不阻断只读核对，也不能借机更换连接身份。核对前后父身份和固定源/目标ID，位置有歧义不释放保护。

位置全部确定且worker已回收后，额外确认才能提交本地位置，证据从最早精确查询起最多300秒有效。原未知因果不改写为成功，单独关联当前位置证据；原动作不再执行。仅为位于目标名的子集记录修订，全批原名也推进旧计划失效水位。反向只从当前全局路径世代的已提交修订生成新固定计划，不接受任意名称、不自动补偿；其他动作推进世代后保守拒绝旧反向依据。接口与持久化见[恢复契约](../development/cloud-drive/c2-recovery-contract.md)。

## 6. 路径与数据

历史扫描、改名、回滚及审计的原始路径快照不修改。当前定位通过受版本约束的目录路径修订或等效身份映射维护；按目录段匹配，不对路径做无边界字符串前缀替换，不全库REPLACE历史路径，不在一次事务中改百万子项。

修订未完成的子树不得继续发布扫描结果、使用旧预览写入或按旧回滚快照执行。分批同步必须可重入、记录检查点、检查当前修订和所有权；如果未来要求本地原路径实体更新，应在独立实施方案中定义批次、上限、索引及中断恢复，不通过后台无限修复掩盖未完成状态。

动作证据独立于可清理的盘点观察：保存固定身份、范围、名称、修订、发送阶段及核对依据，缓存清理不能级联删除未决动作。不能把当前CSV报告或remote_id直接导入执行链。历史批准、消费及审计不因观察清理或日志轮转删除。

固定计划保存在`cloud_directory_plans`及`cloud_directory_plan_items`，不通过观察外键级联删除。计划按用户所有权和请求UUID查询；单计划最多五项，最多保存1000个计划，达到容量时明确拒绝，不静默丢弃证据。完整数据契约及迁移见实施文档。现行持久层为参数化sqlite3，没有ORM，不引入另一套持久层。

## 7. 接口与现有调用

固定计划使用`cloud-directory:plan`直接权限；`cloud-directory:execute`独立于现有扫描和普通文件改名权限，不能隐式继承。当前计划入口不连接云端；实际执行接口、配置及恢复入口在相应阶段独立验收。现有C1[云盘API](../../backend/app/api/cloud_drive.py)与[前端包装](../../frontend/src/api/cloudInventory.ts)的只读契约不变。

固定计划接口：`POST /api/cloud-drive/directory-plans`接收requestId、jobId、expectedRevision、entryIds及folderTerms；`GET /api/cloud-drive/directory-plan-requests/{requestId}`查询原意图；`GET /api/cloud-drive/directory-plans/{planId}`查询快照与有效性；`POST /api/cloud-drive/directory-plans/{planId}/cancel`接收expectedRevision，仅取消本地计划。请求不接受Token、远端路径或身份；参数和前端调用见[实施契约](../development/cloud-drive/c2-plan-contract.md)。

| 现有接口 | 输入/副作用/边界 |
| --- | --- |
| GET /api/cloud-drive/inventory-jobs/{jobId} | 当前用户scan:run及任务所有权；只读本地摘要，freshness未知，writeAvailable=false |
| POST /api/cloud-drive/inventory-jobs/{jobId}/advice | afterId、limit、当前页folderEntryIds、字面folderTerms、当前页keepEntryIds；只分析本地观察，不写云、不外发；folderSuggestion不是执行计划 |
| PUT /api/cloud-drive/inventory-jobs/{jobId}/entries/{entryId}/keep | kept、expectedRevision；只维护当前任务观察的保留例外与本地审计，不成为永久跨盘点规则 |

合成advice请求体如下；ID必须确属当前页、limit为1..200，条目和词条上限沿用现有验证，不允许客户端伪造远端路径或身份：

```json
{
  "afterId": 0,
  "limit": 100,
  "folderEntryIds": [23],
  "folderTerms": ["论坛推广"],
  "keepEntryIds": []
}
```

对应现有Vue/TypeScript调用，可放在frontend/src下的调用模块使用（相对导入，不依赖未配置的路径别名）；应用会话由现有apiClient注入，不能把CD2 Token当应用会话：

```ts
import { fetchInventoryAdvice } from "./api/cloudInventory";

export async function reviewDirectoryNames(
  jobId: string,
  afterId: number,
  folderEntryIds: number[],
  folderTerms: string[],
) {
  return fetchInventoryAdvice(jobId, {
    afterId,
    limit: 100,
    folderEntryIds,
    folderTerms,
    keepEntryIds: [],
  });
}
```

上述C1调用返回分页建议，包含jobRevision/ruleVersion/rulesHash及writeAvailable=false；不把conflict=unknown翻译为“无冲突”。错误沿用401/403、所有者外404、无效输入400/422、修订/缓存状态409、存储不可用503。C1建议不发送目录改名RPC，也不直接成为执行授权。

## 8. 日志、容量与验收

- 日志按计划和动作阶段聚合，不为每个后代写INFO，不打印完整根、账号、Token或远端details；固定原因码与用户可读提示分离。未来查看日志复用既有操作日志窗口及清理/容量设置，日志已清理应提示，不能自动查询云端补齐。
- 证据/动作状态不能仅存在普通可轮转日志中；原始审计和未决意图独立保留。保留时长、容量上限及归档政策在实施前确定，不以日志设置直接删除安全证据，也不无上限保存所有后代路径。
- 验证同父改名、目标创建竞态、源同名替换、同ID账号/父关系变化、大小写/Unicode、祖孙冲突、别名来源、撤权、策略变化、发送前后崩溃、远端成功本地失败、响应丢失、缓存清理、旧预览/回滚失效和恢复冲突。
- 真实验收须另获专用临时对象及写/恢复授权，先合成后小范围；不得在用户媒体子树试错，不为2PB全盘做压力测试。物理恢复未证明时不开放执行，不把重复成功当原子性证明。
- 产品验收口径为：受控风险确认、固定计划、独立权限、预算与互斥、隔离执行、路径一致性和未知核对均有证据；真实小范围产品验收另批。C1建议/导出对外契约不变，不以设计、固定计划或工具试验完成标记C2执行交付。
