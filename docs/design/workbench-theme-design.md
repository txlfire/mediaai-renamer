# 媒体工作台完整主题设计

文档类型：界面设计。目标确认日期：2026-10-13；三套原型视觉方向确认日期：2026-10-14。

本文定义用户已确认的完整主题目标及约束，不描述实现完成状态、迁移过程或测试结果。实施与兼容见[实施计划](../development/ui-refresh/implementation-plan.md)，验证口径见[验收清单](../development/ui-refresh/acceptance-checklist.md)。

## 1. 范围与目标

- 以媒体整理工作台为定位，优化公共外壳、列表、表单、弹窗、状态反馈及操作层级；不改为营销页。
- 三套完整主题，各自支持亮色、暗色；主题差异覆盖画布、侧栏、表头、输入、按钮与选中状态，不限于按钮强调色。
- 保留导航、路由、业务流程、用户权限、选中与全部操作范围、安全确认及外部提交保护。
- 保持 Vue 3、TypeScript、Element Plus、Pinia 与共享 CSS；没有新的后端接口、数据库对象或服务端主题配置。
- 本阶段不新增全局搜索、密度选择、独立移动端导航或其他业务功能。

## 2. 主题与显示模式

| 属性 | 取值 | 职责 |
| --- | --- | --- |
| 显示模式 | `system`、`light`、`dark` | 决定当前使用亮或暗；`system` 解析系统偏好 |
| 视觉主题 | `default`、`candy`、`contrast` | 决定完整的视觉语言和两种模式的成对取值 |

页面根节点以 `data-scheme="light|dark"` 和 `data-palette="default|candy|contrast"` 表达最终状态。`system` 不写入 `data-scheme`，不是第三套颜色。

| ID | 名称 | 画布与侧栏 | 内容与强调 |
| --- | --- | --- | --- |
| `default` | 清爽专业 | 清冷浅灰画布、清楚的侧栏边界；暗态使用中性石墨基底 | 低装饰内容区、克制蓝色强调、少量青绿语义色 |
| `candy` | 柔和彩色 | 很浅的莓色画布、低饱和薄荷侧栏；暗态保留微弱色相区别 | 高可读面板与协调表头、莓色主操作、轻阴影；不用大面积粉紫渐变 |
| `contrast` | 精密高对比 | 白色或炭黑基底、明确分隔 | 更清楚的表头、字段、聚焦和选择边界，少量青色或黄绿强调 |

三套主题共享基本布局、信息密度、操作顺序和字体尺寸。高对比主题不等于仅提供暗色，也不通过缩小字体制造密度。三套原型方向已确认；具体运行值以`frontend/src/styles.css`为唯一源，允许为实际背景上的可读性修正正常及悬停操作色，不在文档复制第二份色值表。

## 3. 令牌职责

`frontend/src/styles.css` 是唯一运行时取值源，不复制到第二份 `tokens.css`。组件消费已解析的语义变量；主题拥有亮暗基础值，显示模式选择对应语义别名。

| 类别 | 覆盖内容 | 现有语义名称示例 |
| --- | --- | --- |
| 背景与分区 | 应用画布、内容面、次级面、侧栏、浮层和遮罩 | `--app-bg`、`--panel-bg`、`--panel-soft-bg`、`--sidebar-bg`、`--el-bg-color-overlay` |
| 文本与边界 | 正文、说明、弱文本、边框、占位与禁用 | `--text-main`、`--text-muted`、`--border-color`、`--input-placeholder` |
| 表格与输入 | 表头、行、悬停、选择、固定列及输入背景 | `--table-header-bg`、`--table-row-bg`、`--table-row-hover-bg`、`--input-bg` |
| 操作与状态 | 品牌色及其文字、成功/警告/危险/信息、表格动作 | `--brand-accent`、`--brand-accent-ink`、`--semantic-*`、`--action-*` |
| 材质 | 阴影、边框强度、圆角 | 优先映射现有公共变量，确无对应语义再集中新增 |
| 排版与几何 | 字号、字重、间距、控件及图标按钮尺寸 | 公共阶梯和组件规则；不随主题改变基本操作尺寸 |

约束：

- 主题可以改变中性色。禁止“视觉主题只能改变强调色”的旧限制再次进入执行规则。
- 成对基础值集中声明，组件语义名称保持稳定；已有品牌与语义色的亮暗名称继续复用，不为形式整齐强行重命名。
- 新增基础值使用语义名，如 `--app-bg-light` / `--app-bg-dark`；不使用颜色名作为角色，也不新增同义变量。
- 禁止 `[data-palette="..."] .el-*` 或按主题复制整页组件 CSS。模式专用样式若涉及值差异，优先转换为语义变量。
- Element Plus 的背景、填充、边框、文字、禁用、遮罩和浮层变量必须映射同一系统；表格固定列不能漏用当前背景。
- hover/active 可从基础值派生，但派生后的最终颜色也必须分别验证，不能假设混色自动满足对比度。
- 所有正式主题完整声明必要值，不依靠跨主题残留。未知主题使用默认主题，避免空变量或混合主题。

## 4. 布局与排版

- 公共外壳保留侧栏、工作区和外观入口；页面标题与说明采用紧凑、无框头部，不使用 Hero 或标题卡。
- 列表按查询、命令与选中范围、数据表格组织。使用无框区或全宽分区，减少标题、筛选、统计和表格之间重复装饰边框。
- 表格、弹窗及确需框定的工具可保留边界；不把页面区块层层包成卡片。
- 基本间距采用4px阶梯，优先8/12/16/24px；同类控件的行高、对齐和内边距一致。
- 字体保留中文系统无衬线，不新增在线字体依赖。字号采用固定阶梯，不按 viewport 连续缩放；页面标题20px、区块标题16px、正文与控件14px、说明13px为默认阶梯。
- 对受限区域允许内容换行、字段重排、截断提示及表格局部滚动；禁止通过全站缩字保证说明文字永不换行。
- 常规控件和重复项圆角不超过8px，6px为基线；独立状态点可为圆形。不用圆形有框按钮代替纯图标表格动作。
- 数字列对齐并使用等宽数字；主操作尺寸与基本行高在六种主题组合中稳定。
- 主题切换、长标签、loading、hover及错误文字不能改变工具栏和表格操作列的基本几何尺寸。

## 5. 交互约束

- 主要动作清楚可见，低频动作可放入已有更多菜单；不隐去日常必需的查询、预览、匹配和执行入口。
- 重命名页面保留 TMDB、AI、重命名的拆分下拉，保留解析标题选择控件；主区域与菜单批量项的范围不变。
- 选中数量与操作目标可以就近展示。AI 未就绪采用就地状态和具体原因，不重新添加突兀的整页黄色告警。
- 表格操作使用现有 Element Plus 图标，纯图标、无边框背景、居中、有语义颜色及名称；危险动作保留确认。
- 加载、空态、失败、权限不足及外部提交保护分别表达。颜色不是唯一状态依据，不将未知执行结果显示为成功。
- 不在就地错误、toast和确认窗口重复同一反馈；全局信息、字段校验、操作结果各自保持清楚的反馈位置。
- 弹窗边界受工作区和视口约束，长内容在内部滚动；主关闭动作、确认动作和必要信息可达。关闭行为沿用原业务契约，不把所有窗口强制设成相同尺寸。
- 保留可见键盘焦点、可访问名称和禁用行为。焦点立即出现、不加动画；空间位移支持减弱动态效果。
- 动效只用于有意义的操作和状态反馈，以短时 transform/opacity 为主；不对表格逐行入场、主题切换和日志刷新添加大范围动画。

## 6. 可读性与缩放

- 正文、品牌文字、状态文字及表格动作按项目门禁分别达到4.5:1；焦点和必要界面边界目标至少3:1。六种组合及对应 hover/active 背景分别检查。
- 禁用项必须可识别为禁用并可理解其原因；不把不可操作状态伪装成可操作。
- 页面根级无横向溢出；长表格局部横滚，操作列固定可见。Provider 的“当前”“操作”两列固定在右侧。
- 主验收环境为3840×2160、Windows 200%、浏览器125%。CSS视口模拟是补充证据，不等同真实组合缩放。
- 同时适配常用桌面分辨率1280×720、1366×768、1600×900、1920×1080和2560×1440。按浏览器实际内容宽高排版，不仅按物理分辨率或宽度判断；低高度桌面收紧留白，不缩小文字和操作按钮。
- 工具栏按可用宽度换行，拆分按钮主区域和箭头保持一个完整组；设置分类在自身区域滚动，不要求用户通过程序滚动或隐藏祖先才能访问最后一项。
- 笔记本以Windows和浏览器100%验收；视口参考、设备待确认项及证据记录由验收清单维护。

## 7. 外观状态与边界

- 外观仍保存在当前浏览器：`mediaai-theme-mode`、`mediaai-theme-palette`；不修改服务端设置或其他用户会话。
- 跟随系统只改变显示模式；切换主题不改变筛选、选择、权限、登录状态或任务状态。
- 主题切换不发送 TMDB/AI 请求，不触发扫描、预览生成或真实文件操作。
- 预览原型与正式页面分开；原型用脱敏合成数据并明确其测试性质，不伪称真实业务结果。
- 如需新运行依赖或外部工具，记录实际收益、版本、许可、网络行为、维护成本和撤销方式；设计需求本身不要求安装额外依赖。
