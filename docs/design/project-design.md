# MediaAI Renamer 系统设计文档

文档类型：系统设计。本文描述已确认的目标约束，不作为实现完成或发布验收证明；修复进度、兼容迁移和未验证限制见[实施计划](../development/reviews/remediation-plan-2026-10-01.md)，部署操作见[部署说明](../deployment/fnos-ghcr-docker.md)。

## 1. 项目定位

MediaAI Renamer 是面向 NAS、fnOS、Emby、Jellyfin、Plex、Kodi 等场景的影视文件扫描、解析、预览和安全重命名工具。

项目不直接承担媒体库管理职责，而是在文件进入媒体库之前，完成安全、可预览、可追踪、可回退规划的标准化整理流程。

## 2. 核心原则

- 先预览，后执行：所有真实文件重命名必须经过 dry-run 和用户确认。
- 本地优先，外部增强：本地解析和安全重命名始终可用；TMDB、AI、多站点能力都是增强能力。
- 可降级：外部接口失败、网络异常、共享目录不可用时，不应破坏已有数据和本地流程。
- 可追踪：扫描、预览、匹配、重命名、失败原因和配置变更都应可记录。
- 文件安全优先：不覆盖已有文件，不绕过冲突检测，不让 AI 直接执行真实文件操作。
- NAS 友好：部署和路径设计要兼容 Windows、Linux、Docker、NAS、fnOS 和已挂载共享目录。

## 3. 设计范围

功能分域与阶段文档对应如下；阶段完成状态和发布版本不在本文重复维护。

- M0：项目骨架、Docker/FastAPI/Vue 基础结构。
- M1：媒体源、本地或已挂载目录扫描、扫描任务、扫描结果、日志和页面框架。
- M2：本地文件名解析、标准命名预览、预览记录保存和目标文件名编辑。
- M3：安全重命名、dry-run、冲突检测、执行记录和批次结果。
- M4：系统热配置、TMDB Bearer令牌/API Key认证、命名预览回填、待处理文件列表和文件运维。
- M5：NAS / SMB / NFS 共享目录基础支持、共享协议接口、连接测试、扫描和重命名前校验、非 TMDB 系统设置分类。
- M6：DeepSeek / AI 智能解析、敏感词外部提交保护、AI 候选确认回填。
- M7：增量扫描、扫描索引、标题识别模式、TMDB 后备 AI、批量 AI 和手动排除。
- M8：命名规则高级配置二期，模板版本、导入导出、规则测试、差异预览、双语字段和历史预览模板状态提示。
- M9：用户权限、历史回滚、审计和任务治理。
- M10：Bangumi、TVDB、豆瓣代理等多站点元数据源。
- M11：HTTPS WebDAV 连接、浏览、扫描、重命名、回滚、失败恢复及协议集成验证。

排除范围：FTP、FTPS、SFTP、S3 / MinIO、HTTP WebDAV、Digest认证及跳过TLS校验，不作为现有可用协议部署。

## 4. 总体架构

```text
Browser
  |
  | HTTP
  v
Frontend: Vue 3 + Pinia + Element Plus
  |
  | /api
  v
Backend: FastAPI
  |
  +-- SQLite
  +-- Config / hot settings
  +-- Logging
  +-- Media source service
  +-- Scan service
  +-- Filename parser
  +-- Rename preview service
  +-- Rename operation service
  +-- Metadata provider service
  +-- AI provider service
  +-- Pending file service
  +-- Shared path protocol service
```

部署形态：

- 本地开发：Vite dev server + FastAPI。
- Docker / NAS：一个FastAPI进程提供Vue静态构建产物、SPA路由回退和同源API，SQLite及配置/日志目录持久化；不依赖独立Nginx前端服务。
- 共享目录：M5 后支持服务端可访问的 UNC (SMB)、Linux mount、NAS / Docker volume、NFS 本地挂载点路径。

## 5. 后端模块边界

`api/`：

- 接收 HTTP 请求。
- 做基础参数校验。
- 调用 service。
- 返回标准响应。

`service/`：

- 承载扫描、解析、匹配、预览、重命名、配置和文件运维流程。
- 不直接依赖前端展示细节。

`schema/`：

- 定义请求、响应和领域模型。
- 为接口和测试提供稳定契约。

`core/`：

- 应用配置、数据库初始化、schema migration、日志基础设施。

`utils/`：

- 文件名清洗、路径处理、视频格式判断、展示格式和通用工具。

`views/`：

- 页面级组合和业务操作入口。

`components/`：

- 通用布局、表格、弹窗、分页、工具栏和可复用业务组件。

`stores/`：

- Pinia 状态管理。
- 保存查询条件、列表数据、配置状态和用户交互状态。

`locales/`：

- 页面文案集中管理。
- 已建立中文文案配置，后续可扩展多语言。

## 7. 核心业务流程

### 7.1 扫描流程

1. 用户配置媒体源。
2. 系统检查媒体源状态和路径可访问性。
3. 用户发起扫描任务，受理接口先持久化任务、操作者及策略快照，返回202和稳定任务ID；受理未知时先查询，不自动重新提交。
4. 后端按批扫描目录，识别视频文件。
5. 小于最小文件阈值的视频进入待处理文件列表。
6. 达标视频写入扫描结果。
7. 页面按任务查看扫描结果。

共享目录扫描检查路径存在、可读和连接状态，不要求可写。执行使用隔离worker及租约，日志独立于长业务写事务；进程未确认退出不释放槽位。只在完整、可比较的扫描范围内推断missing，阈值/隐藏/递归等策略变化重新判定处理资格。总预算和进程终止请求不等于NFS内核阻塞已经退出。

### 7.2 命名预览流程

1. 用户选择媒体源和扫描任务。
2. 后端基于扫描结果执行本地文件名解析。
3. 按命名模板生成目标文件名。
4. 写入命名预览表。
5. 用户可筛选、排序、编辑目标文件名。
6. 后续 TMDB、AI 或人工候选只回填预览，不直接操作真实文件。

### 7.3 TMDB 匹配流程

1. 用户在系统设置中启用 TMDB。
2. 系统优先使用V4只读访问令牌的Bearer认证；实际搜索、详情和连接测试使用 `/3` API，不将令牌名称写成 `/4` 请求。
3. 普通匹配按已有配置使用V3 API Key后备通道；一次性覆盖授权只使用确认的认证通道，不扩大或自动后备。连接测试分别显示认证类型、API端点版本和成功/失败。
4. 候选结果按标题、年份、类型、季集进行 100 分制打分。
5. 高置信结果自动回填命名预览。
6. 低置信结果进入候选弹窗，由用户确认。
7. 匹配失败时保留本地解析结果。

### 7.4 安全重命名流程

1. 用户选择命名预览记录。
2. 后端创建 dry-run 操作批次。
3. 检查空目标名、非法字符、目标冲突、批次内重复、源文件缺失。
4. 用户确认后，受理接口将批次排队状态、操作者和审计意图同事务保存，返回202及原批次ID，不在请求中执行文件动作。
5. 隔离进程逐项执行，动作前核验有效租约和当前用户权限；普通单文件失败记录原因，授权失效则中断整批，不继续下一项。
6. 每项结果与批次真实计数同事务提交，页面串行查询原批次和运行日志；受理或查询未知时不重新发起文件动作。

执行前再次检查权限、预览状态/版本、路径及源身份、目标冲突和协议可写能力，变化使旧dry-run失效。文件动作前先持久化意图、源目录项的实际名称拼写和预期目标名称，并在发出移动前保存动作阶段；动作与数据库不是同一事务。逐项保存已生效结果，未知结果不重放。恢复需要文件身份、实际目录项拼写与动作阶段共同证明，不能仅由路径大小写折叠、inode相等、源不存在或目标存在断言成功；硬链接、符号链接、第三方替换及历史证据不足保持人工核对。

重命名和回滚dry-run先用短读事务取得数据库快照，在事务外探测协议能力及文件身份；最终短写事务复核预览或计划、条目、来源、关联执行状态及当前用户权限，变化则拒绝发布结果。慢I/O不持SQLite写锁；实际执行仍须再次核验物理身份，不保证探测后文件不会变化。

重命名、回滚及待处理迁移跨应用进程共用一个持久化文件写任务槽，按受理时间先后认领，时间相同时按任务类型和ID排序；旧同步执行也检查队列及保留槽，不绕过已受理任务。扫描不属于该队列，不能将此限制理解为所有文件操作的全局调度器。租约过期只中断，未确认进程退出前保留槽位；总时间上限3600秒，监督者请求终止后仍须等待实际退出。离开页面只停止状态查询，不取消后台任务。遗留槽只能经本机核对实际进程退出后释放；释放不执行、重试或自动恢复文件动作，未知文件意图仍需独立核对。

回滚计划须先通过dry-run并保存逐项身份快照。受理接口 `POST /api/rename-rollback-plans/{plan_id}/execute-async` 使用空JSON对象，要求当前用户具备 `rollback:execute` 权限；返回202和原计划，排队与审计意图同事务，受理不访问媒体目录。重复请求只读同一计划，不再次排队；待执行、运行中或进程退出未确认时冻结相关媒体源及预览。后台逐项复核当前权限、租约和快照，不覆盖目标文件。

页面每秒串行调用 `GET /api/rename-rollback-plans/{plan_id}`，返回状态、逐项结果、`rolled_back_count`、`failed_count` 与 `error_message`，不返回执行令牌。未知受理或查询停止轮询并提示只读刷新，不重发文件动作。终态为executed、partial_failed、failed或interrupted；已知计数与每项结果同事务保存。任务治理成功数只统计已回滚项，不把checked计划的可执行候选当成功；导航携原批次和计划ID。

### 7.5 待处理文件流程

1. 尺寸过小或后续识别低价值文件进入待处理列表。
2. 用户可查看、移除任务记录、清空列表或批量迁移文件。
3. 移除和清空只改任务记录，不删除源文件。
4. 批量迁移会移动真实文件，必须校验目标路径和冲突。

受理接口 `POST /api/pending-files/move-async` 要求 `rename:execute`，请求包含 `ids`、绝对目录 `target_directory`、8至64位字母/数字/下划线/连字符的 `request_id`；返回202和稳定迁移任务。请求键绑定当前用户及规范化ID/目标目录载荷，同键同载荷返回原任务，同键不同载荷拒绝。条目受现有 `operations.batch_limit` 限制（默认200、最大10000），不静默截断。

受理只读取数据库、保存任务/来源快照、审计意图并将待处理记录预约为moving，不在HTTP线程探测目录或执行文件操作。所选记录须仍待处理、来源启用且未退役/失效、没有未决文件动作；WebDAV来源不支持此本地迁移流程。预约期间禁止移除、清空、AI解析和来源配置变更，不把排队视为物理文件可访问的保证。

隐藏worker取得共同写槽后固定目标目录身份，每项复核租约、当前用户权限、数据库快照、源范围和文件身份。目标必须为稳定身份的普通目录，禁止覆盖。跨文件系统复制使用独占目标，复制后再次检查权限、租约及源/目标身份，才删除源；失败或未知停止后续项。已确认移动的路径、条目moved状态和 `moved_count` 同事务提交，撤权不抹掉此前已发生的事实；动作成功但事务失败保留未知意图，不推断成功或重放。

查询接口 `GET /api/pending-files/moves/{task_id}` 返回任务状态、真实计数、逐项结果与错误，不返回执行令牌；按请求键查询 `GET /api/pending-files/moves/by-request/{request_id}` 限当前用户，未找到返回null。两者要求登录，不产生文件动作。页面每秒串行查询，迟到结果不覆盖新观察；已发出请求结果未知时只能只读核对，null也不能证明原请求未在途。终态为completed、partial_failed、failed、interrupted，逐项区分ready、moving、moved、failed、recovery_required和not_started。有 `audit:read` 才能查看日志。

受理载荷示例（需用户确认，不由文档示例自动执行）：

```json
{"ids":[12,13],"target_directory":"D:\\MediaArchive","request_id":"move-demo-20261008"}
```

前端调用由共享client的 `acceptPendingMove(ids, targetDirectory, requestId)` 封装POST，`fetchPendingMove(taskId)` 与 `findPendingMove(requestId)` 封装GET并复用登录请求头；页面通过Pinia的 `executePendingMove` / `refreshPendingMove` 调用，不自行拼接后端地址。返回对象为 `PendingMoveTask`（id/status/target_directory/total_count/moved_count/failed_count/error_message/created_at/updated_at/items）。数据库访问沿用sqlite3参数化SQL，不引入ORM；数据模型为冻结dataclass，不把它称为ORM映射。

运行日志以 `pending_move` 及真实任务ID记录受理、开始、复制阶段、逐项提交和终态，沿用有界读取与清理设置，不逐字节刷日志。治理导航携迁移任务ID及可确定的来源/扫描任务ID；归档不删除任务或文件动作证据。进程实际退出后，只释放没有未知意图的预约；未知动作仍需本地文件恢复核对。

停服文件对账须先核对并释放关联终态执行槽；槽未释放或任务仍queued/running时拒绝写修复。依据唯一动作关联及源/目标身份，已生效更新pending_files、任务条目moved和已知计数；明确未执行更新为pending/not_started，同事务记录维护审计与运行日志。原任务保持中断，不自动继续其他条目；原已固定的执行审计结果不被后续对账改写，维护审计单独解释核对事实。旧独立意图不猜测新批次关联。

## 8. 配置体系

可热更新的业务配置通过 `system_settings` 管理；路径、运行环境及部署安全开关由实例配置和环境管理，不能用热配置替代本机恢复授权。

优先级：

```text
环境变量 > 数据库热配置 > 默认值
```

热配置分组：TMDB/补充元数据源、AI Provider、扫描、敏感词/外部提交保护、解析重命名、共享目录、运维及通用设置。默认管理员自动创建和本机应急恢复等部署安全开关由实例配置文件控制，不作为公开HTTP恢复授权。

配置要求：

- 敏感值脱敏。
- 非法值后端拒绝保存。
- 配置保存后热生效。
- 已启动任务使用任务启动时记录的配置，不被中途修改影响。

## 9. 数据设计概览

核心表及职责：

- `app_meta`：schema version。
- `system_settings`：热配置。
- `media_sources`：媒体源。
- `scan_jobs`：扫描任务。
- `media_files`：扫描结果。
- `rename_previews`：命名预览。
- `rename_operations`：重命名批次。
- `rename_operation_items`：重命名明细。
- `pending_files`：待处理文件。
- `external_submission_blocks`：外部提交拦截记录，M6 用于敏感词过滤和后续规则拦截的处理列表。
- `scan_file_index`：扫描索引、范围及策略比较基础。
- `metadata_provider_configs`：补充元数据源配置与加密凭据。
- `page_test_results`、`imdb_test_result`：配置连接测试结果。
- `users`：本地用户。
- `user_sessions`：用户会话。
- `audit_events`：权限和配置审计。
- `rename_rollback_plans`：回滚计划。
- `rename_rollback_items`：回滚计划明细。
- `operation_logs`：任务运行日志与游标读取。
- `task_archives`：任务归档标记，不删除业务历史。
- `remote_operation_locks`、`remote_operation_items`：远程写入租约、幂等和恢复证据。
- `local_file_actions`：本地文件动作意图、源和目标目录项名称、动作阶段及身份对账；历史记录不反向猜测缺失的名称证据。
- `pending_move_tasks`、`pending_move_items`：迁移请求键/固定载荷、执行租约与操作者、真实计数、来源快照及逐项终态；任务与条目保留历史，不随运行日志清理。
- `media_source_history`：来源生命周期快照。
- `file_action_audit_intents`：文件动作与审计的可靠补写意图。
- `external_submission_authorizations`：一次性外部提交授权、消费与已保存结果。
- `external_request_sites`：外部HTTP origin摘要、最近准入时间及间隔；最多1024个站点状态，超过一天且没有在途请求的状态有界清理。
- `external_request_leases`：实际请求的随机令牌、PID和限制；同机共享数据库协调，不存URL、凭据、正文或媒体信息。

AI候选保存在对应预览/返回结果中，不虚列独立的AI任务表。凭据分布在媒体源、Provider和敏感热配置字段，统一使用独立密钥，不建立角色体系或全局凭据表。

## 10. 安全边界

文件操作安全：

- 不覆盖已有文件。
- 不允许空目标文件名。
- 不允许目录穿越。
- 不绕过 dry-run。
- 不让 AI 直接修改真实文件。

共享目录安全：

- 凭据不写普通日志。
- 持久化凭据采用独立随机密钥与 Fernet 认证加密，版本化密文前缀 v3；覆盖媒体源、元数据 Provider、AI/TMDB 敏感热配置与 AI Provider 列表。密钥优先环境秘密，其次配置指定文件，默认独立文件 data_dir/secrets/credentials.key，不由数据库路径派生。
- 密钥缺失、不匹配或密文损坏明确失败，不清空凭据。数据库与密钥分开备份；迁移步骤及回退另见部署文档，不混入目标设计。
- WebDAV 带凭据请求、href 和 MOVE 目标受同源、有效端口和配置根目录约束。URL 禁止内嵌凭据及不安全路径编码，自动重定向拒绝，TLS 校验不能跳过。
- WebDAV 连接成功只证明目录可读。真实重命名和回滚默认关闭，只有随机隔离目录中的错误 ETag 拒绝、正确 ETag 移动、禁止覆盖和清理复核全部通过后，才按端点与凭据版本记录 `verified` 并开放写链路；结果不明或清理失败保持 `unknown`。
- 扫描前检查可读。
- 重命名前检查可写。
- 网络断开时失败记录必须明确。
- 路径类型为 `local / unc / mounted_nfs / webdav`，按协议能力处理，不把远程协议伪装成本地路径。SMB使用UNC及媒体源加密字段，依赖运行环境共享访问权限；已挂载NFS校验本地挂载点和UID/GID，不保存密码，不提供Kerberos配置。WebDAV为HTTPS独立实现。

外部服务安全：

- API Key、token、SMB 密码必须脱敏。
- 运行诊断不记录完整prompt/响应正文或凭据。授权审计可记录追溯所需的源/目标路径，读取和导出均需要audit:read；对外分享前必须检查脱敏，不承诺导出自动抹除所有媒体路径。
- 文件名、路径或解析标题命中敏感词时，不得提交到 TMDB、IMDb、后续刮削源或 AI。
- 被敏感词或后续规则拦截的条目必须写入拦截记录，用户可在列表中选择修改后重新匹配、不再匹配并忽略，或在强确认后无视规则继续提交；覆盖提交必须记录原因和审计信息。
- 一次性覆盖授权在 `prepare` 时按同一份有效配置重新计算文件名、路径和解析标题的当前命中，将脱敏词、数量和策略修订信息写入该次授权的不可变快照及审计；原拦截记录继续表示最初拦截原因，不被后续核查覆盖。`prepare` 后策略或载荷变化使提交指纹失效，必须重新确认且不得发出外部请求。
- 覆盖授权绑定用户、目标服务、条目、解析载荷及目标配置摘要，有效期300秒；消费时重新核对权限和源/预览有效性。消费前的审计与业务认领同事务，外部请求在事务外执行。结果未知不重放，结果补写仅使用已保存的结构化快照；不得通过旧状态或缓存推断实际请求成功。
- 一次性覆盖只针对AI或TMDB的一次顶层操作，不扩展到多源或后备服务，不自动应用候选；TMDB搜索和详情可以包含多次HTTP请求。普通AI请求只对明确429响应按上限退避，鉴权失败、超时、网络断开及5xx不盲目重发。共享截止预算限制重试启动和等待，不将其等同于底层阻塞读取的强制中断。
- 外部服务失败只降级，不阻断本地流程。

外部HTTP预算：

- AI和TMDB/Bangumi/TVDB/豆瓣代理的实例调用、连接测试、认证、详情及允许的重试统一取得准入资格；已有IMDb网站可达性测试也采用元数据预算，不代表IMDb搜索接入。包括配置在本机/局域网的AI；不限制浏览器访问本地API、本地文件动作或WebDAV媒体协议。
- 站点按scheme/规范化host/有效port区分，路径、查询和模型不另建配额。默认每站点准入间隔0.5秒（2请求/秒）、单站点1实际在途请求、同机同数据库全局4实际在途请求；这不是供应商承诺配额，也不是多机器全局限流。
- 静态external_requests配置分别定义AI/元数据默认值和元数据Provider覆盖，修改后重启服务及worker；范围严格校验。不同调用策略共享origin时，活动槽采用较小并发限制，相邻准入采用较长间隔。预算约束准入时刻，不承诺操作系统调度暂停后网络包仍严格匀速。
- 排队、数据库锁等待和重试等待计入调用截止预算。搜索及详情共用预算，TMDB认证切换不重新计时，多源线程继承整体截止时间；已到期不开始下一次HTTP。排队未发送与已经发送但结果未知分别记录，一次性授权排队失败也不自动重用。
- 响应读取及资源退出完成前持槽；无法确认关闭或进程状态时继续保留。确定PID退出后可清除遗留槽，但不推断外部执行结果、不重放请求；Windows核对退出码，不能只凭进程句柄可打开判断存活。
- HTTP不自动重定向；调用者应配置最终API地址。数据库不可用、状态异常或容量满时拒绝外发，不新建缺失数据库。SQLite写事务只用于短暂准入/释放，不持事务等待网络。超时不是所有底层读取的强制取消，供应商可能在连接结束后继续计算。

## 11. 用户权限与来源生命周期

- 权限直接分配到用户，不设计角色。除健康、登录与受控初始化所需入口外，API默认要求有效认证；日志/导出复用audit:read，清理/配置复用settings:write，来源修改复用source:write，扫描复用scan:run，外发复用metadata:submit，重命名/回滚分别使用rename:execute/rollback:execute。
- 系统设置列表、Provider配置、详细连接测试历史和命名配置导出只对 `settings:write` 开放；普通业务页只通过认证用户可读的 AI readiness 接口取得 `ready/status/tested_at/message`，不得返回 Provider、模型、地址、敏感词或配置快照。
- TMDB、IMDb和AI连接测试由服务端实际发出请求并原子保存结果，结果绑定测试开始时捕获的配置快照。客户端提交TMDB/IMDb测试结果的旧接口在兼容期返回410；单通道TMDB诊断不更新完整配置的已验证状态。
- 初始化需用户表为空且初始化开关允许；不能以“无用户”放行所有接口。改密、禁用或应急重置撤销旧会话；默认密码未改时每次登录提醒，不擅自增加高风险操作禁令。
- admin应急恢复仅通过服务机器本机命令及配置开关执行，记录审计、恢复后关闭开关；公开HTTP入口不能仅靠隐藏设置或开关授权。
- 来源删除采用退役；改根路径和退役前检查运行中扫描、重命名、回滚、未完成恢复及有效执行租约，存在时拒绝。
- 来源历史快照、任务与审计保留，旧执行计划/待处理资格失效，旧索引清理，不删除真实媒体文件。退役来源不进入可用下拉，也不复用历史源ID。
- 数据库内的用户、配置或来源写入与对应成功审计在同一事务；文件/网络副作用先持久化意图，再执行和保存实际结果，审计补写不能用旧业务状态猜本次成功。

## 12. 查询、批量范围与日志约束

- 大列表由数据库筛选、稳定排序和分页，同一请求的读快照返回总计与当前页；不同翻页请求不是跨请求快照。按白名单排序，以ID等稳定字段消除排序并列的不确定性。远程操作历史固定按ID倒序，状态和更新时间变化不会使既有行跨页漂移；翻页期间新增记录仍可能改变OFFSET页边界，需要完整一致导出时不得用页面遍历代替专用快照。
- 分页读接口页大小上限200，主要页面提供10/50，下拉每页50并替换选项、不无限积累。页外已选对象按ID查询；任务归档返读不依赖最近前N条。
- 预览全局状态统计与分页范围一致；全部操作读取当前筛选下的合格目标ID，不把当前页当全部。超过operations.batch_limit时明确拒绝，不静默截断；范围读取不执行外部或文件操作。
- 确认绑定固定目标集合及解析选项。筛选、选择范围变化或离页取消未执行的确认；重复点击互斥。写入完成后的列表刷新失败不能把已生效动作说成未执行或自动重放。
- 日志游标指向实际已返回条目，has_more与清理/截断标记分别表达；前端请求互斥、任务代次隔离、失败退避，关闭或终态停止无效轮询。
- 文件日志在同一目录使用跨进程互斥锁协调写入、轮转、归档和删除；Windows处理器延迟打开并在每条记录写入后关闭句柄，避免空闲句柄阻止其他进程轮转。锁文件不计入日志容量。归档前后都复核文件身份，变化中的轮转文件保留到后续维护；维护按文件数和字节数有界执行。该机制保证同机共享目录，不替代网络文件系统上的分布式锁。
- 文件日志、任务运行日志与审计辅助意图有各自数量/逻辑字节预算；未知/待补写意图不能为腾空间删除。审计辅助记录达到数量或逻辑字节上限的80%时在任务治理页告警，达到100%时在文件副作用前拒绝新请求。未知意图使用 `pending / review_required / completed / manually_closed` 状态；进程中断或归属不明只转 `review_required`，不根据后来任务状态推断原请求结果。人工关闭同时要求 `audit:read` 与 `task:manage`，原因和证据必填且首次关闭后不可覆盖；关闭只释放治理容量，结果保持 `action_outcome=unknown`，不修改业务任务。数据库/WAL实际大小与可复用页单独报告，逻辑删除不承诺缩小文件。
- 已明确过期会话可有界清理；安全审计不受运行日志保留天数控制。安全审计独立保留策略和物理维护政策未确认前不自动删除审计、不在线VACUUM。
