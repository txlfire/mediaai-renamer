# MediaAI 私有证书维护

类型：运维操作规程。适用NAS上的MediaAI专用CA及服务器证书，不适用于CD2信任配置。本文不创建自动任务或授权换证；检查结果见[实施记录](../work-logs/progress-2026-10-23-fnos-stable.md)。

## 1. 范围与检查

证书到期前预留维护窗口：建议服务证书剩余30天内安排续签、7天内优先处理；CA剩余90天内单独规划。以上是人工维护建议，没有已运行的自动检查或自动续期。失去信任、SAN不匹配或过期时立即停止凭据交接，不跳过校验。

在NAS的受控SSH终端执行只读检查，输入当前实际挂载的公开证书路径，不输入私钥内容：

```bash
read -r -p '服务器公开证书绝对路径: ' SERVER_CERT
test -f "$SERVER_CERT" || { printf '证书文件不存在\n'; exit 1; }
openssl x509 -in "$SERVER_CERT" -noout -dates -fingerprint -sha256
if openssl x509 -in "$SERVER_CERT" -checkend 2592000 -noout; then
  printf '服务器证书在30天后仍有效\n'
else
  printf '服务器证书临期、已过期或无法解析，需要核查\n'
  exit 1
fi
```

预期：有效期与SHA256符合批准记录。`checkend`只检查时间，不验证证书用途、SAN、链或吊销状态；仍须从实际客户端通过默认系统信任打开HTTPS并核对健康、登录及版本。

CA公开证书可用同样命令查看，建议将`-checkend`秒数改为7776000（90天）。不要导出CA私钥，也不要把服务器私钥或CA私钥导入浏览器。

## 2. 服务证书续签顺序

1. 核对当前容器ID、镜像digest、证书挂载源和既有SAN，确认没有未决工作，另行批准维护窗口。受限备份数据库/配置/密钥及现有TLS目录，私钥副本仅留NAS受限目录；公开CA与私钥不能一起分发。
2. 在独立受限目录创建新服务器密钥和CSR，用原批准CA签发新叶证书；保留实际入口IP/域名SAN、serverAuth用途和完整链。不在运行中的路径覆盖写入，不将叶证书续签变成CA轮换。
3. 离线检查证书与私钥公钥匹配、链/用途/有效期/SAN、属主和权限；目录700、私钥600。用无对外端口的独立副本启动验证HTTPS、实际资源与账号数据保持，不挂CA私钥给应用。
4. 在已批准的短暂停服窗口中切换完整证书集合并正常启动服务；禁止用部分写入的文件热覆盖。核对证书指纹、客户端默认信任和名称校验、健康版本及原账号登录。Uvicorn直接TLS不假定无需重启就能装载新证书。
5. 失败时停止新实例，恢复原完整TLS集合和原镜像/数据关联；旧证书尚未过期是可用回退的前提。结果未知先核对实际挂载及监听，不重复签发或重复切换。

以上为待执行规程，不是已经签发/换证。具体签发命令须依据现场CA私钥位置、签发账本和访问方式核对后生成，不能凭通用示例直接改写CA序列号或签发状态。

## 3. CA轮换与异常

- CA临期、私钥泄露或入口变更需单独决策，制定新旧信任并存、客户端分发和旧信任撤销顺序；不能把新CA同名文件替换视为客户端已信任。
- 默认HTTPS校验通过，不等于在线吊销状态已经验证。私有CA缺少可查询的吊销信息时，额外Online链检查可能返回`RevocationStatusUnknown`，应记录为未确认，不谎称未吊销，也不关闭证书验证来消除提示。
- 容器的`unless-stopped`不是NAS重启验证结果；宿主Docker、挂载和网络是否自启仍需实际宿主重启窗口验证。手动停止的容器不承诺被策略自动启动。
- 不开放公网、不改全机根信任或CD2的CA/Token；续签不授权扫描、改名、隔离或删除正式媒体。
