# 初始化管理员入口治理设计

## 目标

“初始化管理员”仅在系统首次启动或系统重置后可用。系统已经存在本地用户时，后续登录页不再展示初始化入口，也不允许绕过前端重复初始化。

## 状态模型

新增热配置 `auth.admin_bootstrap_enabled`：

- 类型：布尔值。
- 默认值：`true`。
- 分类：`operations`，在“系统设置 → 通用设置”展示。
- 修改权限：沿用 `settings:write`，仅管理员可修改。
- 配置含义：允许用户表为空时初始化首个管理员。

初始化入口最终可用状态同时满足：

1. `auth.admin_bootstrap_enabled` 为 `true`。
2. 本地用户表为空。

系统重置会清空本地用户及业务数据库。重置后的新数据库没有配置记录，因此使用默认值 `true`，恢复首次初始化能力。

正式配置和发布示例默认关闭 `default_admin_enabled`，避免启动过程抢先创建默认账号。无人值守部署仍可显式开启该静态配置，并继续使用原有默认管理员改密流程。

## 后端接口

### 查询初始化状态

新增公开只读接口：

```http
GET /api/auth/bootstrap-status
```

响应：

```json
{
  "available": true
}
```

接口只返回是否可初始化，不暴露用户数量、用户名、数据库状态或配置来源。

### 初始化管理员

保留：

```http
POST /api/auth/bootstrap-admin
```

调用时重新校验热配置和用户表，不能信任前端查询结果。任一条件不满足均返回 `409 Conflict`。

初始化成功后，将 `auth.admin_bootstrap_enabled` 持久化为 `false`。即使后续异常删除个别用户记录，初始化能力也不会意外重新开放；只有管理员重新启用或执行完整系统重置后才可能恢复。

## 前端交互

- 登录页挂载时查询 `/api/auth/bootstrap-status`。
- `available=true` 时显示“登录”和“初始化管理员”两个 Tab。
- `available=false` 或查询失败时只显示登录表单。
- 查询期间默认隐藏初始化入口，避免页面闪烁。
- 初始化成功后立即将本地状态改为不可用，隐藏初始化 Tab，并继续现有登录及默认密码处理流程。
- 后端返回 `409` 时刷新初始化状态并切回登录 Tab。

## 管理员配置

“通用设置”增加“允许初始化管理员”开关：

- 仅拥有 `settings:write` 权限时展示。
- 开启开关不会在已有用户时显示登录页初始化入口。
- 提示文案明确说明：仅在用户表为空时生效，错误开启不会绕过后端用户存在校验。
- 保存使用现有系统设置接口和审计记录。

## 错误处理

- 状态接口失败：登录功能保持可用，初始化入口保持隐藏。
- 初始化期间状态发生变化：后端返回 `409`，前端隐藏入口并提示初始化不可用。
- 管理员保存非法配置：沿用系统设置校验与错误弹窗。

## 测试

### 后端

- 新数据库默认返回 `available=true`。
- 初始化成功后返回 `available=false`。
- 已有用户时，即使配置重新开启，状态仍为 `false`，初始化请求返回 `409`。
- 配置关闭且用户表为空时，初始化请求返回 `409`。
- 系统设置默认值、持久化和布尔校验正确。

### 前端

- API 客户端正确调用状态接口。
- 状态为不可用或请求失败时隐藏初始化 Tab。
- 状态可用时展示初始化 Tab。
- Store 初始化成功后更新可用状态。
- 管理员配置正确加载和保存。

### 回归

- 普通用户名密码登录、“记住密码”和“一周免登录”行为不变。
- 首次管理员初始化、修改默认密码和退出登录行为不变。
- 后端全量测试、前端全量测试、生产构建和编码检查通过。
