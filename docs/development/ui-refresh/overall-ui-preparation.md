## 2. 方案接入与评审材料

用户的方案可以是文档、截图、原型或参考页面。收到后先对照下列清单，已有结论直接沿用，只询问无法从方案或代码确定的分支：

- [ ] 目标是视觉层次/布局调整、交互流程变化还是信息架构重排，列出希望解决的问题和不变项。
- [ ] 明确覆盖页面与优先顺序，以及六主题是全部保留优化还是有新的主题决策。
- [ ] 区分必须一致的公共规则与业务专用差异；提供重命名密集列表、系统设置长表单、目录整理三类代表页面。
- [ ] 给出搜索入口、结果展示及返回原工作区的预期；与GS-0一起确定，不仅画一个新的输入框。
- [ ] 将方案建议、已确认目标、实现偏差及测试结果分开，不把参考截图当最终尺寸规范。
- [ ] 若建议更换组件库、图标、字体、状态管理、路由或新增依赖，先单列收益、迁移成本和兼容风险，不能随视觉变更自动引入。

方案到达前不先做多套全站原型；已有页面和历史证据可作分析索引，但正式新基线要从实际选定源码重新生成。2026-10-27已收到方案，本次只完成材料、11张静态主稿及源码核对；修订清单V2-01至10、分批建议和待确认目标见[评估报告](visual-language-v2-assessment.md)，不能将静态稿或评估建议当成实现通过。

## 3. 必须保持的行为与协作边界

1. 权限直接授予用户，不引入角色。导航隐藏不代替后端授权；CD2连接/目录白名单、任务拥有者和原上下文不能由页面选择覆盖。
2. 重命名的选中/全部范围、解析标题选择、TMDB/AI拆分菜单、冲突检测及危险动作确认必须保留，不因更换按钮或布局改变动作绑定。
3. Provider长列表保持表内横滚，“当前/操作”列固定可见；图标操作有可访问名称、语义色和可见焦点，表单联动及新增/保存逻辑不能回退。
4. 真实任务与日志状态保持区分：受理、运行、失败、结果未知、观察已清理各自表达；不把关闭弹窗解释为远端取消成功，不自动重试未知云请求。
5. 主题不只替换按钮色，也不按主题复制六套组件CSS；共享语义变量与Element Plus映射由现有styles.css管理，不新增第二份运行时色值真值。
6. 字号、间距、表格与浮层的具体新值等待方案评审；不能通过全站缩字、隐藏按钮或固定过小高度规避缩放问题。当前设计仍有效，改变它时明确登记决策。
7. 本轮不改路由、API或组件消费者契约。若方案确需改变，实施前列出兼容与定位参数迁移，不把业务变更藏在“样式优化”里。
8. 当前工作区有大量尚未提交的多连接后端和接口改动。前端阶段先核对最新diff及工作记录；共享文件如App.vue、SettingsView.vue、styles.css、locales/zh-CN.ts和router/index.ts安排一个批次连续修改，避免两条工作线互相覆盖。

## 4. 验收环境与状态矩阵

| 场景 | 设置与检查 | 判定边界 |
| --- | --- | --- |
| 主屏实际环境 | 3840×2160、Windows200%、浏览器125%；记录实际innerWidth/innerHeight及浏览器版本 | 用户此前确认v1.4.0设置和目录整理正常，仅是旧制品、限定页面证据；新UI必须重验，不用1536 CSS宽模拟替代 |
| 常用桌面 | 1920×1080、1600×900、1366×768、1280×720、2560×1440；浏览器100%并记录真实内容高度 | 全页无横向溢出、主动作及弹窗底部可达；表格内部横滚允许 |
| 笔记本 | 系统和浏览器均100%；真实硬件分辨率尚未确认 | 1366×768和1920×1080先作参考测试，不冒称是用户实机 |
| 缩放回归 | 浏览器125%、150%及低高度窗口；侧栏展开/折叠、全屏表格 | 长名称/路径/Provider不能撑宽工作区；只检横向坐标不足以判断按钮可用 |
| 主题与无障碍 | 六主题×亮暗，另测system切换；实际背景文字/动作4.5:1，必要边界/焦点3:1；减弱动效 | 每批记录取样与实际键盘测试，不用历史颜色结果推导新页面全部合规 |

状态数据至少包括：空/单行/长列表、长中英文与路径、低权限、选中单条/多条、部分失败、加载、超时/未知、已清理日志、表单未保存、会话退出/切换及迟到响应。搜索另测中文输入法、防抖、撤权、取消及结果定位。

视觉基线和交互数据默认使用合成API与隔离页面；截图不包含真实凭据、路径或用户信息。不操作真实媒体、NAS、CD2/115或外部AI/TMDB，不把界面验收变成真实云试验。

## 6. 工具与启动准备

- 本轮只启用文档生命周期Skill，不加载UI风格Skill，不安装依赖，不运行外部初始化或改MCP配置。
- 实现前根据最终任务再建议一个主要Skill并按用户规则确认。项目实现优先考虑mediaai-frontend-ui；需要审阅已有页面时再考虑一个只读诊断补充，不同时叠加多套风格规则。
- 延续Vue 3、Element Plus和现有CSS；外部Skill若以React/Radix/Tailwind或motion/react示例为主，必须转为项目现有方案，不能直接拷入新的运行时依赖。
- 浏览器工具和服务届时按[规范启动](../development-guide.md#2-规范启动)核对。使用真实DOM、截图与实际交互验证；只有需要隔离服务时才使用独立端口，不重启/停止用户正在使用的标准服务，不迁移运行库。
- 验证命令沿用package.json中的frontend:test、frontend:build、check:encoding及git diff --check；具体Node和浏览器版本在执行时实际读取，历史记录不是当前运行环境证明。

本准备不包含全站实施、Skill启用授权、Git提交、版本升级、部署或发布，也不宣称已完成本轮视觉审查。
