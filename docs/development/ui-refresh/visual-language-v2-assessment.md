## 3. 推荐保留的方向

- 背景、侧栏、内容区有稳定层次，品牌色与成功/告警/失败等语义角色分开。
- 六个主题ID和system/light/dark保留；共享Vue 3、Element Plus、路由、权限及偏好机制。
- 表格由高频字段带动信息层级，低频字段进入有明确入口的详情；保留排序、筛选、勾选与固定操作。
- 重命名采用可收起的详情面板，让单条比对和编辑更直接；窄宽度必须有退化方案。
- 使用固定字号阶梯、等宽数字、可见焦点、有限背景过渡，不按物理分辨率缩放字号。
- 深色可以采用令牌加代表页样板，不要求设计师重复出8张暗色稿；实施仍须验证六主题亮暗全部组合。

## 4. 实施前必须修订

P1表示可能造成错误操作、信息失真、越权或关键功能不可达；P2表示规范矛盾或落地返工风险。以下均是方案风险，不冒充当前产品已存在相同缺陷。

### V2-01 / P1：补齐真实双重缩放，修正断点表

来源：视觉语言§7.1、7.2、7.8。

- 用户主屏是3840×2160、Windows200%、浏览器125%，而不是文档主要举例的4K150%。满宽CSS宽度约为 `3840 / 2 / 1.25 = 1536`；实际innerWidth/innerHeight须现场记录，不能将物理2160高或画板1080高当成可视高。
- 文档写“1536比1440更窄”属于算术错误；≤1399档列入1536也与断点冲突。表内部分“内容区宽”未扣padding，1366和1150混用了视口宽与扣侧栏后的宽度。
- 建议以实际容器宽度决定列优先级与详情面板布局，视口宽度只决定外壳。内容宽需统一按 `innerWidth - sidebar - 左右padding - 可选详情面板 - gap` 计算。
- 验收补1536逻辑宽与实际低高度、1280×720、1366×768、1600×900、1920×1080及125%/150%缩放；不能只对照1920画板。

### V2-02 / P1：效果图不能引入假进度、假字段或新执行入口

来源：视觉语言§7.3；01、03、04、05、06、08图。依据：[ScanJob接口类型](../../../frontend/src/api/client.ts)、[扫描进度逻辑](../../../frontend/src/views/ScanJobsView.vue)、[盘点接口类型](../../../frontend/src/api/cloudInventory.ts)。

- ScanJob没有总工作量和updated_at；当前活动扫描使用不定进度。不能据稿显示62%、剩余4分钟或把轮询时间称作任务最近更新。
- 目录盘点只读本层，estimatedTotalEntries固定为null，条目没有递归文件数；不能为03图的“文件数”后台补扫115目录。完整仅指批准范围本层完成，不代表整个媒体子树完整。
- 分辨率、设备/归属、全局统计、导出、上次扫描等列逐一做字段与接口映射。现有响应无法提供的项应省略或明确未提供，不擅自读取文件正文、调用外部服务或新增后端契约。
- 01图暂停/重试、06图“批量重试失败”不能成为通用执行能力。未知外发或云写继续只能查原UUID与独立恢复，不因红色失败标签自动允许重放。
- 08图“失败5次锁定10分钟”不能直接上屏：当前只有[登录限流候选](../security-governance-proposal.md)，不是已落地的该规则；也须保留现有记住登录、初始化和改密流程。

### V2-03 / P1：目录整理不能被简化为广告隔离单线

来源：编码输入语D-2、03图。依据：[目录整理页面](../../../frontend/src/views/CloudInventoryView.vue)、[多连接契约](../cloud-drive/multi-connection-contract.md)。

- 本次产品重点包含目录改名C2。三段“盘点→人工复核→隔离”遗漏目录建议、改名计划、执行、只读位置核对和反向新计划。
- 推荐结构是共同的小范围盘点，之后分为“目录命名”和“广告复核/受控隔离”两条工作线，各自保留计划、执行与恢复记录；不伪造两条分支共用的完成百分比。
- MC5必须同时表达连接、目录配置、选定子路径、原任务来源、停用/归档、授权不足、全局保护、未知结果和已清理观察。不可把普通媒体源选择器当CD2来源选择。
- “受保护行所有按钮disabled”过度：禁止写不应禁止有权用户查看依据、详情和日志。实际禁用按动作、来源权限与保护原因判断。
- 隔离目录尚未盘点时的下一步只能帮助用户明确选择/确认，不能因打开页面或空态按钮直接补扫、生成Token或开放执行。

### V2-04 / P1：重命名的新布局不能改变单条、勾选和全部范围

来源：编码输入语C-1至C-3；02图。依据：[重命名页面](../../../frontend/src/views/RenamePreviewsView.vue)。

- 图中“已选3条”与详情面板内的单个执行按钮同时存在，需明确按钮针对当前详情还是勾选3条；必须在确认前可辨认作用范围。
- 保留解析标题选择、TMDB/AI/多源匹配的单条与全部语义、排除、权限、外发确认和固定批量目标集合。不能仅按“1主+1下拉”数量目标合并业务操作。
- 高/低置信应沿用服务端状态，不能在视觉层统一改成confidence<80；metadata_match_score与AI confidence也不能混用。
- 换行、分页、筛选、切换详情前要处理未保存目标名；选择其他行不丢勾选集合，迟到候选不覆盖当前编辑。
- 先拆展示组件，保留原状态与动作入口。不得为“容器小于250行”同时重写约2900行视图的状态、请求、分页和安全逻辑。

### V2-05 / P1：纠正对比度豁免及补足必要交互状态

来源：视觉语言§2对比度、§5输入框。依据：[W3C非文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)、[文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。

- 结构性卡片描边和侧栏分层并非都要3:1，方案这部分区分可以保留；但输入框不能仅以“不是强边界、用contrast主题即可”整体豁免。
- 本地按声明色值复算：输入边框#CAD7C4对白为1.4969:1，输入底#FAFDF8对白为1.0259:1；它们并不能相互叠加得到足够辨识度。需评估识别该控件所必需的实际线索及焦点，不能只靠会消失的placeholder。
- 表头#53664F/#F0F3ED为5.5447:1，成功文字#0E7A56/#DFF3EA为4.6092:1，暗色表头#AAB8A6/#344A38为4.6348:1，与方案这三组数值相符；这不证明12态整体合规。
- 默认主题也须满足项目既有文字4.5:1及必要边界/焦点3:1目标。验证正常、hover、选中、聚焦、只读、禁用、错误、遮罩、固定列和浮层；高对比主题不能代替其他主题验收。
- 图标16/18px是图形尺寸，不是点击面积；建议表格动作至少保持24px目标并优先28至32px，受密度影响时按[目标尺寸/间距规则](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)核验。

### V2-06 / P1：设置重排不能破坏秘密处理、个人偏好和权限

来源：编码输入语D-3；07图。依据：[设置页](../../../frontend/src/views/SettingsView.vue)、[外观入口](../../../frontend/src/components/ThemePreferences.vue)、[现有配置手册](../../manuals/cd2-settings.md)。

- 当前源码有10个分类，包含用户、审计、共享目录及CD2；07图是局部样板，不应据此删除或合并分类。
- 外观偏好保存在本浏览器，当前Brush入口不要求settings:write；不能只搬进受管理权限限制的设置页，也不能把主题保存到系统数据库。
- “密钥一键显隐”仅适用于当前已输入、允许在前端持有的明文；不能新增读取已保存秘密的接口，或把掩码当真实密钥重保存。CD2临时Token继续不保存。
- 固定保存栏按真实滚动所有者设置，预留底部空间，不能挡住Provider/用户表格、弹层或错误反馈。不同分类的保存/测试仍走各自原确认和请求语义，不为统一按钮自动调用诊断。

### V2-07 / P2：确定令牌唯一来源，补完整主题角色映射

来源：视觉语言§2、§6、§8；编码输入语A。依据：[styles.css](../../../frontend/src/styles.css)、[设计入口](../../../design.md)。

- 新建tokens.css与“styles.css唯一运行时真值、旧变量名不变”冲突。推荐先沿用styles.css，列出新角色到旧别名及Element Plus的映射，不新增并行真值。
- 浅色表给出9个差异变量，却另有contrast卡片描边例外，不能用“第10处颜色不同就是错”验收。各主题的输入、文字、focus、禁用、按钮前景、弹层及预览仍需明确归属。
- 深色仅列forest及amber侧栏，不等于六套完整暗色值已经齐备。可保留现有其他主题的暗色基础，再按角色修订，不能把forest暗色覆盖全站。
- 深色“浅品牌字色”与“深实心按钮+白字”需分开角色，不能同时塞进一个--brand-accent。补button-primary-bg/ink与brand文字/链接的映射，避免其他按钮、分页或选中态反色。
- 新别名须让theme-preview在自身palette与scheme上解析，不只在root解析后继承；浮层/Teleport也须消费同一套语义变量。

### V2-08 / P2：统一图标和动作颜色规则

来源：视觉语言§2的“所有图标统一--icon”、§5；编码输入语A-2、B-2。

- 最新视觉稿把表格操作图标也中性化，旧执行文档却要求查看蓝、执行绿、删除红；与用户此前要求表格彩色图标也存在待决定的变化。
- 推荐侧栏、搜索及装饰图标用中性角色；表格操作保留少量稳定语义色，危险动作红，图标保持无边框背景、居中、可见焦点和可访问名称。状态色与品牌色不混用。
- 当前使用Element Plus图标，部分SVG是fill路径而非24网格stroke图。不能靠全局stroke-width:1.35将其可靠变成稿中图标；先保留现库，统一size/视觉重量。更换图标库需另行确认，不作为换色附带操作。
- 保留现有--action-*消费接口；收敛值可以做，但以实际状态对比和无未定义变量验收，不锁死24条。旧文档的8亮+8暗+8亮hover+8暗hover按所列角色是32种，不是24。

### V2-09 / P2：保留Element Plus表格结构及局部滚动

来源：视觉语言§5表格、§7.3至7.5；编码输入语B。

- 不把el-table表头/表体重写为flex+gap行；这会影响列布局、固定列、勾选、排序、布局重算和无障碍结构。沿现有table/column及CSS分隔线实现目标观感即可。
- 不把“无横向滚动”作为一刀切约束。页面根不得横向溢出；长表、Provider列表可在内部横滚，当前/操作固定列继续可见。不能为过稿隐藏字段或只靠overflow:hidden裁掉控件。数据表也有[重排例外](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)，但不免除其周边控件适配。
- 一个页面选定主要纵向滚动所有者；表体/必要详情面板可独立滚动，低高度下须允许外层安全退化。侧栏不能永不滚动导致底部设置消失；保留用户手动折叠偏好。
- 统计项数量按页面数据，不能“永远5列”：01稿本身只有4项。窄端应换行或采用紧凑摘要，不能通过全站缩字硬塞。
- 重命名详情面板在文档中有330至400、图注420等不同宽度；以容器可用宽度定义展开/抽屉阈值，而非固定占满。

### V2-10 / P2：统一规范优先级、尺寸和实施边界

来源：两份文档及效果图索引。

- 视觉稿行高分别出现48、52、56，编码输入语初值42；圆角12/8/999与10/7/5冲突。§7.7密度变量还缺px单位，不能原样当length消费。
- 四种状态组件与视觉稿中性第五态冲突；“受保护”是动作限制，并不必然是执行失败。使用独立状态到语义映射，不压缩业务枚举。
- 首次默认forest可作为候选，但已有用户保存的六主题选择和system模式必须保持。默认值/非法值回退涉及index.html首屏、store及测试，不只是CSS覆盖；本轮不改主题ID。
- 现有圆角基线≤8px。推荐保持普通工作台6至8px，状态胶囊可圆；全站12px和登录16px应作为明确目标变化确认，不能从稿隐式推导。
- 新字体首先沿系统fallback验证；不得自动下载在线字体或加入大体积中文字体。确需本地嵌入时另评授权、体积与首屏代价。
- 图片中部分脚注仍写旧列数；10暗色样板面包屑文字偏暗、全局搜索仍浅底；02首行匹配度位置也与其他行不一致。把它们当静态稿待修订，不要求实现复制这些偏差。
- 当前styles.css为4406行，不是约3000；Card/Button/Pill/Field并非现有四原子组件。TablePagination里“&#39029;”是HTML字符引用，不是硬编码颜色；不能用仅按#数字匹配的grep当验收结论。
- 不执行材料中的自动git pull、feature分支、每批PR或“清库制造空态”。当前工作区有未提交多连接变更，Git按用户单独要求处理；空态及视觉验收用隔离合成数据。
