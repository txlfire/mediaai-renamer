## 4. 文件所有者与修改顺序

1. `frontend/src/styles.css`：以当前变量为消费者契约，补成对基础值及别名；Element Plus映射同源。集中声明主题值，不按主题复制组件规则；同期更新文件头中“scheme只承担中性色、palette只承担点缀色”的旧注释。
2. `frontend/src/stores/app.ts`及对应测试：增加contrast白名单与保存/加载；保留键名、旧主题值、未知值回退和系统偏好逻辑。
3. `frontend/src/App.vue`与`frontend/src/locales/zh-CN.ts`：更新两种选择的文案和主题预览信息，复用现有入口，不新增后端设置项。
4. `frontend/src/components/ListPageLayout.vue`：在确认原型后调整装饰结构，保留现有props/slots契约；逐一核对standalone/merged两类消费者。
5. `frontend/src/views/RenamePreviewsView.vue`：落地主流程层级，保留点击处理、禁用条件、解析下拉、选中/全部及敏感保护。
6. 扫描、媒体源、任务与设置消费者：以共享规则继承为主，确需本地差异时记录原因；Provider固定列、图标动作和表单状态不得回退。
7. 登录与浮层：继承同主题变量，验证弹窗、下拉、tooltip、确认框与遮罩；不因“不在主工作台”而留下旧配色。

不为格式统一重命名所有action变量；现有light/dark、hover命名保留消费者，内部映射用测试证明。不更换组件、不修改API契约。

## 5. 原型隔离与服务纪律

- 原型放在`.codex/test-artifacts/ui-refresh/`等本地隔离位置，不进入生产路由。截图与数据包含主题、模式、视口及状态信息。
- 使用显式合成数据或已脱敏数据。禁止测试凭据、真实媒体路径和用户数据出现在预览、截图或分享内容。
- 原型业务动作使用模拟结果，不提交扫描、匹配、重命名、NAS写入或真实外部请求。
- 标准服务只用项目脚本，遵守[开发服务启动规约](../reviews/discussions/harness-development-service-startup.md)；用户要求保持运行，不停止或重启标准5173/8970实例。
- 需要隔离服务时使用独立端口和库，结束后只清理该隔离实例；脚本细节以现有正式[开发文档](../development-guide.md)为准。

## 6. 兼容、恢复与停止条件

- 浏览器已有`default`/`candy`设置在新版本映射到对应完整主题；模式与侧栏状态不重置。
- 新增`contrast`在旧版本会回退default，这是当前旧加载校验的行为；回退不删用户数据、不改登录状态。
- 原型拒绝时只调整原型与提案，不污染正式主题。实现失败时可撤销本批样式/布局变更，不能清空localStorage或数据库作为恢复手段。
- 用户未确认具体原型，不进入全站推广；需要改变业务行为、消费者接口、新增依赖或扩大实测范围时先报告影响。
- 不升级版本、不提交/推送Git、不发布，除非获得对应授权。文档与Skill准备不包含源码实施授权。
