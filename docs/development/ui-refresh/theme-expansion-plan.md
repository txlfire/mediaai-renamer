文档类型：实施与演进计划。日期：2026-10-15。状态：原型获确认，六主题实现与本轮可执行回归完成，已随v1.3.0正式发布；实机等边界单列。

## 1. 结论与范围

保留清爽专业、柔和彩色、精密高对比三套现有主题，在原方向内补强分区与交互层次；新增海盐青、林间绿、琥珀日光。共六套完整主题，每套提供亮色、暗色，形成十二种视觉状态。显示模式仍为跟随系统、亮色、暗色，不增加第三个全局选择轴。

外观入口改为固定的外观图标按钮，主题横排单选改为有界、可滚动的双列预览单选列表；低宽度采用单列。主题变化覆盖画布、侧栏、表头、输入、浮层、选择和焦点，不只替换按钮颜色。

日间先做取色研究、计划、验收场景与交接记录。用户随后明确启动开发，TE-P1原型完成后又确认“按当前原型继续全站实现”。现已执行TE-P2～P4；没有自动设定时任务。原型确认、正式实现、实机验收与发布制品分开记录。

范围外：后台配置、数据库、API、角色、权限、任务流程、密度设置、主题导入导出、自定义取色器、收藏和主题市场。不新增UI库、在线字体、远程图片或运行时配色网站请求，不提交、升级或发布版本。

权威入口：[已确认主题设计](../../design/workbench-theme-design.md)、[既有实施与历史记录](implementation-plan.md)、[验收清单](acceptance-checklist.md)。用户已于2026-10-15确认十二态原型，正式设计随确认同步；本文保留候选来源和实施过程，已实现与已发布仍分开记录。

### 3.1 色彩分工

- 来源四色不能直接一一填入背景、正文、按钮、状态四类角色。浅色用于低面积区域或淡化后分区，深色/衍生色负责可读文字；中性白、灰、石墨仍承担内容阅读。
- ocean：亮态为冷白内容面、淡青侧栏、清楚的青绿主操作与珊瑚次级提示；暗态为中性石墨内容面、带少量青相的侧栏和明亮青色选择边界。禁止做成整页青蓝渐变。
- forest：亮态为中性白内容面、低饱和绿侧栏、深绿主操作与少量赭金；暗态为炭黑阅读面、森林绿导航层和明度足够的叶绿焦点。禁止绿字、绿底、绿边框层层叠加，也不采用大面积米色/棕色画布。
- amber：批准原型的亮态为中性白/浅灰、石墨文字、深蜂蜜主操作配白字及金黄选择；暗态为中性黑/灰、金黄主操作配深字与青色次级细节。不做大面积橙棕/奶油色主题，深棕来源色不作为全站画布。初始金黄候选未直接用作白字按钮，按实际对比度调整后获确认。
- 原有三主题不改ID、不改主要识别特征，不因扩展把default改成另一套蓝黑主题，或把contrast变成装饰性彩色主题。
- 成功、警告、危险、信息的含义全站一致；暖色主题的主操作与警告需要通过图标、文字、边界和布局区分，禁止用颜色替代状态语义。删除、未知结果与权限不足不换成主题成功色。
- 暗态单独推导，不简单反色或统一套深蓝底。说明、禁用、输入、固定列、Tooltip/Popover、抽屉和确认框均随同一语义值变化。

### 3.2 可读性门禁

普通正文、说明、主按钮文字、状态文字、表格操作正常/hover在实际背景上至少4.5:1；焦点和必要边界至少3:1。对选中行、悬停行、浮层等背景分别验证，透明层按实际承载背景合成。源色不满足要求时调整亮度和饱和度，不为了保持原HEX牺牲可读性。

当前仅核验原色来源，没有产品对比度结果。候选亮暗值经原型确认、实测后才写入styles.css，文档不维护第二份运行时全量色值表。

## 4. 外观入口与选择器

### 4.1 入口

- 继续放在现有侧栏底部，使用现有Element Plus图标库的Brush图标和当前主题控件规范，不新增一排主题按钮。
- 固定图标，不再用太阳/月亮兼任完整主题选择入口；可访问名称为“外观”，提示显示当前主题和模式。展开/折叠侧栏均保留同等入口，按钮与命中区域不随主题名变化。
- 点击打开一次浮层；顶部有“外观”和有名称的关闭图标。显示模式为跟随系统/亮色/暗色的独立分段单选，不和主题卡片混成十二个选项。

### 4.2 主题预览单选列表

- 顺序固定：清爽专业、柔和彩色、精密高对比、海盐青、林间绿、琥珀日光。选择目标是六个主题，不为亮暗各复制一张卡。
- 每项为一个ElRadio语义控件，内容为小型工作台配色示意、主题名称及选中标记；示意显示画布、侧栏、内容/表头与强调组合，不仅一个颜色点。示意本身不放业务按钮、文字说明、假数据或嵌套交互控件。
- 预览跟随当前已解析的亮暗模式；system变化时同步。用选中标记、边界和radio选中状态表达当前项，不能只改变背景色。
- 点击即切换并沿用当前浏览器保存机制，浮层保持打开便于比较；不增加“应用”或“保存”步骤，不在hover时切换。关闭不回滚已选主题，与现有即时生效契约一致。
- 六项暂不增加搜索/收藏/分组。以12/24个合成选项夹具验证可滚动和键盘可达；夹具不是新增正式主题，不进入实际存储白名单。

### 4.3 尺寸、滚动与定位

- 浮层目标宽384px，上限为视口宽减24px；最小内边距12px，重复主题项圆角不超过8px。按实际剩余空间使用Popover的翻转与防溢出，而非固定left/top。
- 内容区可用宽度足够时两列；窄于360 CSS像素的视口改一列。主题名称使用固定字号，可换行，不随viewport缩字。
- 浮层总高度上限为560px和视口高减24px两者较小值；标题、关闭、显示模式置于列表之外，主题列表单独纵滚。不让六项或未来长列表撑高整个侧栏、遮住关闭或产生根级横滚。
- 低高度窗口能滚到末项并选择；焦点进入被遮挡选项时仅在列表内部滚动。若可用高度不足以保持完整顶栏及一个选项，使用同一组件的受视口约束Dialog布局，列表仍独立滚动；不复制第二套选择逻辑。
- 边界值需在浏览器中依据真实内容测量修正。384px和560px是实施初值，不是以固定尺寸压过实际可用空间。

### 4.4 键盘与关闭

- 外观按钮可由Tab到达，Enter/Space打开；打开后聚焦当前主题选项并保证其在列表内可见。
- 显示模式与主题各为独立的有名称单选组，优先复用Element Plus及原生radio语义。方向键在组内切换，Space选择；按当前浏览器原生单选行为即时生效，不另写按钮伪装radio。
- Tab/Shift+Tab可到模式、主题和关闭入口；不得把每项示意里的色块加入Tab序列。普通Popover不伪装为Modal，不对背景启用不真实的aria-modal；低高度Dialog布局沿用现有对话框焦点约束。
- ESC只关闭最上层外观浮层，返回外观按钮，不连带退出全屏或关闭底层窗口；点击外部关闭，焦点不强拉回按钮；再点入口可关闭。
- 提示不拦截Enter/Space，焦点立即可见；不做全页主题渐变、色卡入场或大面积模糊，支持减弱动效。
