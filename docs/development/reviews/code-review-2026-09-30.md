### R01：匿名文件操作与后端鉴权覆盖不完整

- 优先级：P1；状态：待修复。
- 位置：`backend/app/api/pending_files.py:76`；关联 `logs.py:27`、`media_sources.py:98`、`settings.py:197`、`rename_previews.py:157`。
- 触发：实例已创建管理员，调用方不携带 Authorization，直接 POST `/api/pending-files/move`，提交有效待处理 ID 和可写目标目录。
- 结果：返回 200，临时文件实际迁移。前端路由登录限制没有阻止直接 HTTP 请求。
- 扩展范围：待处理 AI 调用、删除/清空；预览编辑/排除/候选回填；配置测试与测试结果保存；媒体源目录浏览和连接测试；系统日志读取/导出/清理等接口存在无依赖路径。
- 影响：匿名读取路径与日志、修改任务数据、移动文件、触发外部请求。已登录但无对应权限的用户也可调用这些入口。
- 修复建议：建立逐接口权限矩阵。非公开 API 至少需要认证，文件写入、外部提交、设置测试、日志清理分别按既有直接权限校验；首用户初始化只开放必要的 bootstrap 入口。空用户库放行策略应明确收敛。
- 验收：管理员已存在时匿名请求返回 401，无对应权限返回 403，授权成功；同时确认初始化前不会匿名移动文件或提交外部请求。补齐所有路由的矩阵测试。
- 证据：复现脚本 `test_R01_anonymous_file_move_after_bootstrap`。

### R02：日志分页游标导致漏日志

- 优先级：P2；状态：待修复。
- 位置：`backend/app/service/operation_log_service.py:234`、`frontend/src/components/OperationLogDrawer.vue:132`。
- 触发：任务已积累超过 100 条日志，页面按 limit=100 拉取。
- 原因：后端返回任务所有日志的 MAX(id)，前端直接将其作为下一页 after_id；第一页只读到前 100 条，游标却移动到最后一条。
- 复现结果：150 条日志，首批 100 条，下一批 0 条，50 条未返回。
- 修复建议：区分本页消费游标与服务端最新 ID，返回 `next_after_id` / `has_more` 或以最后一条已返回日志推进；首次展示最近日志时明确尾页策略。
- 验收：150、1000 和跨任务交错 ID 场景全部读齐且无重复；任务结束仍读完积压页；筛选、导出和折叠数量准确。
- 证据：脚本 R02。

### R03：扫描过程日志直到任务结束才提交

- 优先级：P2；状态：待修复。
- 位置：`backend/app/service/scan_service.py:479`、`:619`、`:707`。
- 触发：扫描超过一个批次，另一连接查询 operation_logs。
- 原因：进度日志写入扫描 SAVEPOINT 所在业务连接，所有处理结束后才提交；批次间还会在事务内 sleep。
- 复现结果：扫描内部写入 scan_progress 后，独立读取只能看到 scan_prepare。
- 影响：实时窗口没有真实进度；长事务占用 SQLite 写锁，可能影响配置保存、其他任务和日志写入。
- 修复建议：缩短业务事务并建立进度提交边界。日志可随安全批次一起提交或采用队列处理，但不能在已有 SQLite 写锁内直接另开写连接。
- 验收：任务未完成时独立 HTTP 请求能看到至少两个递增进度；扫描失败保留失败前的可追溯日志；同时保存无关设置不会长时间锁住。
- 证据：脚本 R03。

### R04：待处理文件批量迁移部分失败无法保持一致

- 优先级：P1；状态：待修复。
- 位置：`backend/app/service/pending_file_service.py:175`、`:190`、`:196`。
- 触发：选择两个文件，第一条移动成功，第二条源不存在或目标冲突。
- 原因：逐条 shutil.move 后更新数据库，全部成功才 commit；后续异常使数据库事务回滚，文件移动不会回滚。
- 复现结果：第一条在目标目录真实存在，数据库仍为 pending 且路径指向不存在的源。
- 修复建议：先全批次预检，再逐条持久化操作意图与结果；返回逐条状态，失败不抹掉已成功明细；支持中断恢复。成功响应也应返回更新后的路径和 moved 状态，当前列表对象来自更新前的 row。
- 验收：第二条故意失败，第一条结果仍准确；支持跨文件系统移动错误和进程中断；重试不重复或覆盖文件。
- 证据：脚本 R04。

### R05：日志 archive 目录永久绕过清理

- 优先级：P2；状态：待修复。
- 位置：`backend/app/service/log_service.py:72`。
- 触发：轮转日志被打包到 archive 子目录，时间超过 retention_days。
- 原因：只遍历日志根目录，所有目录直接跳过，既不检查 archive 内文件，也没有归档目录容量上限。
- 复现结果：100 天前的归档文件在清理后仍存在。
- 修复建议：把日志归档纳入保留期和总容量预算；记录归档内容的原始时间或清晰定义归档保留起点，防止重新压缩重置年龄。
- 验收：过期归档删除、有效归档保留、总量超限按顺序清理；清理路径严格限定日志目录。
- 证据：脚本 R05。

### R06：改密和隐藏 admin 重置未吊销旧会话

- 优先级：P1；状态：待修复。
- 位置：`backend/app/service/auth_service.py:574`、`:609`。
- 触发：先登录取得会话，用户改密后继续使用旧会话。

- 证据：脚本 R06；admin 重置分支静态确认。

### R08：WebDAV href 缺少同源和根目录约束

- 优先级：P1；状态：待修复。
- 位置：`backend/app/service/shared_protocols/webdav.py:168`、`:264`、`:59`。
- 触发：PROPFIND 响应含另一个 HTTPS 域名的绝对 href，递归扫描将其作为目录加入遍历队列。
- 原因：`_url_from_href` 对绝对 href 只校验 HTTPS；下一次 `_request` 根据同一个 context 添加 Authorization，没有核对目标 origin。
- 影响：非预期远端可能收到 Basic/Bearer 凭据；也可能越出配置根目录扫描。响应解析和请求调用链已确认，未发送真实跨域凭据。
- 修复建议：规范化后检查 scheme/host/port 同源及根路径边界；对重定向同样控制凭据转发；不要将 HTTP 错误或 404 与合法资源状态混淆。
- 验收：跨域、不同端口、根路径逃逸、编码分隔符和重定向用例被拒绝；合法同源中文目录可扫描。
- 证据：脚本 R08 确认跨域解析接受；递归和鉴权调用链静态确认。
