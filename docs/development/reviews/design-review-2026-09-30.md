## 3. 逐项评审

以下“不足/建议/决策”是原始设计审查证据，不重复要求用户确认已采用的P01-P07；实施接续按修复计划第6节。

### S01：接口权限需要完整矩阵，不只列“敏感接口”

- 依据：M9-design-manual.md:14、:78、:242；remote_operations API 使用固定 rename:execute。
- 不足：设计列了权限枚举和主要写操作，但未逐路由定义匿名、普通登录、缺权限、初始化状态的行为；恢复接口没有按实际操作类型授权。读取路径、日志、目录浏览和配置连接测试也有数据或外部请求副作用。
- 建议目标：非明确公开接口默认需认证；按用户直接权限建立路由矩阵，包含读取、修改、外部调用、文件写入、恢复和清理。bootstrap 只开放初始化所需能力，不能把“无用户”变成全 API 放行。
- 验收：匿名/已登录无权限/授权用户/初始化前四类场景覆盖全部路由；rename 与 rollback 恢复权限分别一致。
- 决策：日志是否统一复用登录态或 audit:read，需要选定一个可执行口径；不新增角色。

### S02：默认密码和应急重置开关不是完整安全边界

- 依据：M9-design-manual.md:316 明确默认密码及登录提醒；:63 定义会话模型。
- 不足：未明确改密、管理员应急重置对现存会话的影响；“配置显式开启”不能单独证明远程调用者有权重置。只提示改密和必须改密标记也需明确能否继续执行高风险动作。
- 建议目标：改密及重置撤销旧会话；应急恢复优先本机命令或一次性恢复授权，保留配置开关、审计和关闭机制。登录失败节流，不能在日志记录密码。
- 验收：知道旧密码或持有旧 token 均不能在恢复后继续使用；开关关闭不可重置；恢复凭证不能重放；每次未改密登录仍提示。
- 决策：提醒即可还是限制高风险操作，属于产品政策，不能擅自把已确认的提醒需求改成完全锁定账号。

### S03：不能把 SQLite 事务当成文件操作事务

- 依据：M3-design-manual.md:44 规定逐项失败继续；M9-design-manual.md:283 规定回滚部分成功保留；M11-WebDAV设计手册.md:33 只列写流程。
- 不足：缺少文件动作已发生、数据库提交失败、进程中断、用户重试时的一致性协议。大批次单事务会回滚数据库但不能撤销文件动作；独立远程记录写连接又与外层写事务竞争。
- 建议目标：持久化意图，原子认领任务/条目，执行文件动作，短事务记录每项实际结果，最终汇总批次。明确 applied 与 completed 的区别及重启对账，不自动二次回滚成功项。
- 验收：第二条失败不丢失第一条成功状态；每个文件动作/提交边界注入故障；重复执行只返回既有结果或安全恢复，不覆盖成功结果。
- 成本：需要迁移状态及补偿/对账代码，不只是调整 commit 位置；仍可使用 SQLite 和单机 worker。

### S04：dry-run 确认的是快照，不应永久授权执行

- 依据：M3-design-manual.md:36-44；M7-design-manual.md:282-286。
- 不足：没有定义 dry-run 与预览版本、排除状态、配置版本、源文件身份的关系；检查后修改预览或外部程序替换源文件时，旧结果是否失效不明确。
- 建议目标：执行前核对预览版本及排除状态、源/目标路径、允许范围和必要文件身份；变化则要求重新 dry-run。对本地“目标不存在后再 rename”应选定平台可靠的禁止覆盖实现，而非仅做事先 exists。
- 验收：排除、手改目标、源被替换、目标并发创建均不执行陈旧结果或覆盖现有文件。
- 决策：有效期是否按时间限制可后定，版本/状态重新校验不可省略。

### S05：远程存在性不能充分证明操作身份

- 依据：M11-WebDAV设计手册.md:37、:45-50；:61 已明确不声明通用源版本条件写。
- 不足：“源不存在、目标存在”仅证明路径状态，不证明目标就是本次移动的文件；“源存在、目标不存在”也不能证明源未被替换。未完整定义租约原子获取、续约、过期持有者和幂等键作用域。
- 建议目标：事务或条件更新原子获取租约，释放/续约校验持有者；网络操作跨租约期限时不能允许过期执行者继续随意落账。记录可用的 ETag/大小/时间等证据，身份不足进入人工处理；未知结果先对账，不直接重发 MOVE。ETag 有服务端差异，不能假设跨 MOVE 永远稳定。
- 验收：双调用只能一个获取；过期者不能释放新锁；响应丢失、目标被其他程序创建、同名源被替换均不误标成功。completed 历史也可检查业务状态一致性。
- 限制：无可靠条件写或文件身份能力时应公开保守恢复边界；不承诺通用 exactly-once 远程文件操作。

### S06：missing 必须基于完整、可比较的扫描范围

- 依据：M7-design-manual.md:53、:112、:125-126、:288-296。
- 不足：设计直接把“本次没看见”标 missing，没有扫描子树、递归/隐藏选项、异常目录和是否完整遍历的前提；文件指纹也未包含影响处理的策略版本。
- 建议目标：记录扫描范围和策略版本，仅在成功完整遍历的可比较范围内标 missing；失败子树不推断缺失。大小阈值、解析规则、扩展名等策略变更触发必要重处理，不必重算所有视频内容哈希。
- 验收：关闭递归、读某子目录失败、改变大小阈值都不错误跳过或判缺失；本地/远程改名后索引一致。
- 性能约束：增量扫描主要减少重复解析/写入，不应宣称无需遍历目录，除非后续实现独立变化通知机制。

### S07：实时可见性和日志清理必须有明确协议

- 依据：M9-design-manual.md:177-230，示例仅有 latestId；写入与清理要求已有节流和容量限制。
- 不足：未明确 latestId 是返回页游标还是当前任务高水位；未给出筛选、分页、清理并发时的截断语义；业务长事务下日志如何实时提交也缺少方案。大小限制约束的是估算日志量，不是数据库物理大小。
- 建议目标：将 nextCursor、可选高水位、hasMore、截断状态分清；清理后保留轻量摘要/清理标记。先返回任务 ID，日志写入独立于长业务事务；定期有预算清理，按实测确定写入/轮询负载。前端请求互斥、代次隔离、失败退避及停止条件作为验收项。
- 验收：150 条分两页不漏，轮询中发生清理有明确提示；扫描未结束能读到进度；1 万/10 万条场景记录内存与延迟；空闲系统也清理过期日志。
- 偏离：设计明确要求实时查看、错误退避、部分清理提示，实现未完全满足；无需改变轮询方案就能先修复。
- 文档冲突：project-design.md:258 要求不记录敏感路径，M9-design-manual.md:165 允许完整路径；应区分内部授权日志与文件导出/共享日志，确认路径脱敏口径，避免同一字段在两份文档被相反约束。

### S08：凭据保护不能只写“加密保存”

- 依据：project-design.md:225、:257；M7-design-manual.md:219；M10-design-manual.md:326 明确强加密延期。
- 不足：密钥来源、文件权限、备份迁移、轮换与密文完整性缺少统一约束。使用数据库路径派生密钥不具有独立秘密；与路径绑定还破坏迁移。AI/TMDB 的实际明文存储与设计“加密保存”有偏差。
- 建议目标：独立随机密钥或部署环境秘密，采用成熟带认证加密格式；密钥不随数据库接口泄漏。版本化读取旧数据与逐步迁移，失败可诊断且不回显秘密。
- 验收：数据库单独备份无法推出秘密；合法携带密钥迁移可解密；篡改密文拒绝；缺密钥不默默清空配置。
- 决策：本机密钥文件和环境变量的优先级、备份方式要明确，不需要为个人/NAS 部署引入企业 KMS。

### S09：WebDAV 安全应覆盖返回 URL，不只输入 URL

- 依据：M11-WebDAV设计手册.md:18 排除跨站点移动，:54-61 安全约束。
- 不足：安全条目没有明确 PROPFIND href、重定向、编码路径、用户信息、源根目录边界。只验证初始 HTTPS 地址不足以约束后续遍历和凭据发送。
- 建议目标：严格解析 URL，规范化后验证协议/主机/有效端口与根目录；相对 href 可接受，同源绝对 href 按范围接受，跨源拒绝且不携带认证。请求重定向按明确策略处理，禁止借编码或路径规范化逃逸。
- 验收：跨主机、端口、协议、编码父目录、带 userinfo、重定向场景均不能外发凭据或访问根之外路径。
- 范围：不因内网服务地址本身是私有 IP 就禁止所有 NAS；应限制来源和用户授权范围。

### S10：删除媒体源需要全生命周期关系设计

- 依据：project-design.md 数据表清单；M9 历史/任务治理设计和 M7 索引模型。
- 不足：各阶段新增表后，删除源/改根路径的统一关联策略没有更新；审计历史、可执行待处理项和恢复意图不能同样简单级联删除。
- 建议目标：定义关系清单和保留政策，源配置版本绑定执行计划；运行中禁止破坏性删除/改路径。历史保留快照，失去有效源后不能继续写文件；索引和待处理按策略清理或失效。
- 验收：有扫描、待处理、重命名、回滚、远程恢复历史时删除/改路径，不出现悬空可执行对象，也不删除真实媒体文件。
- 决策：软删除还是拒绝有未恢复操作的删除，需要产品确认；审计保留独立于源存续。

### S11：协议能力要区分读、写与可取消

- 依据：project-design.md:250-251 明确扫描前可读、改名前可写；M5-design-manual.md:54 异常映射。
- 偏离：实现把只读目录拒绝扫描，属于已有正确设计未实现，不应改文档为“扫描必须可写”来消除差异。
- 不足：应用超时和 NFS 内核阻塞之间的边界未完整说明；线程超时不能自动终止系统调用。
- 建议目标：协议能力分别报告 readable/writable/rename/recovery；任务截止与平台挂载参数共同治理，必要时可终止 worker 隔离，不无限积累线程。
- 验收：只读挂载可扫描、预览，但写操作拒绝；失联 NFS 的任务状态和 worker 回收有实测证据。

### S12：外部提交授权、策略与网络预算需要统一

- 依据：project-design.md:259；M6-design-manual.md:97-98；M10-design-manual.md:169-182。
- 不足：拦截覆盖没有定义“一次授权给什么请求”，只改状态无法保证真正提交；primary_only 固定 TMDB 与实现按优先项冲突；parallel 的并行定义与串行调用不一致；重试配置缺少总截止和未知结果语义。
- 建议目标：覆盖授权绑定用户/目标/有效载荷、有效期和单次使用，提交与审计结果分开；多源模式明确选源及启用/占位规则；有界并发、Provider 限流和总预算统一约束。未知结果的聊天请求避免自动无限重放。
- 验收：确认展示实际目标和数量；被拦截条目未授权不外发；授权后恰好执行一次或明确失败；慢源不无限拉长请求；占位 Provider 不被展示为真实搜索成功。
- 决策：主源固定 TMDB 或可配置优先源，需明确选择，不擅自改变用户提交范围。

## 4. 不建议扩大范围的事项

- 不需要引入角色；直接用户权限足够，但必须完整守卫。
- 保留 HTTPS 和 TLS 校验要求；HTTP/Digest 是 M11 已排除项，不是审核中发现的漏开发功能。
- 保留轮询；先修任务 ID、事务可见性、游标和请求竞态，不以 WebSocket 替代这些正确性问题。
- 保留 SQLite；优先缩短事务、原子认领、有界写入及恢复协议，不用换数据库掩盖文件动作一致性问题。
- 无必要默认实现全部远程协议或全量内容哈希。完善当前已交付边界后再评估扩展。
