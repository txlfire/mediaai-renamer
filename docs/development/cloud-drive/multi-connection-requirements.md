# CD2 多连接与目录配置需求分析

类型：需求与范围。日期：2026-10-23。状态：D1至D8范围已确认，MC1目标技术基线已成文；端到端多连接尚未交付，实施进度见演进计划，不改变现行v1.4.0/schema55的单配置行为。

## 1. 已确认与决策边界

| 编号 | 用户已确认事项 | 后续设计约束 |
| --- | --- | --- |
| D1 | 多连接配置，任务明确选择连接 | 不使用可变的全局当前连接解释任务目标 |
| D2 | 首版同时支持每连接多个目录配置 | 公司/家庭、电影/电视剧不靠覆盖同一配置切换 |
| D3 | 首版直接向用户授予连接使用权限 | 必须同时具备原动作权限；不引入角色，任务仍归创建者 |
| D4 | 首版保留全实例保守串行与未知保护 | 多连接不放大并发；一个未决云操作仍可能阻塞其他连接；风控组先保留模型 |
| D5 | 首版增加目录授权白名单 | 连接使用权、目录白名单、原动作权限取交集；选择当前全部不包含未来新增目录 |
| D6 | 保守迁移并重新确认 | 旧配置迁一连接一目录；可靠历史才绑定，其余原所有者只读；管理员确认授权和开关，未决与预算不清零 |
| D7 | 首版提供分层显式诊断 | 分别呈现TLS、受限Token及精确版本；不自动创建Token、不列目录、不随保存/切换运行，云调用受预算约束 |
| D8 | 同连接批准根不重叠，跨连接同路径允许 | 同一连接内拒绝重复及祖孙批准根；跨连接已知别名提示有效授权并集，未授权配置不构成文件系统拒绝规则，不承诺自动识别未知别名 |

上述D8以用户确认的后一条精确边界为准，不禁止家庭、公司等不同连接配置同一个115目录。在某个批准根内选择更深目录盘点，不要求另建目录配置。

接口/表结构、容量及受限恢复以[MC1详细契约](multi-connection-contract.md)的目标技术基线为准，不把文档分析授权解释为批准云请求、库迁移或发布。前期技术取舍见[设计评估](multi-connection-design-review.md)，现状与迁移步骤见[演进计划](multi-connection-evolution-plan.md)。

## 2. 目标与非目标

目标：保存多套连接与目录范围；减少重复填表；准确区分任务来源；避免切换错误、跨用户越权和多入口绕过115风控；保留现有受控改名、隔离与未知核对边界。

非目标：自动探测局域网、自动登录CD2、保存主账号密码/临时Token/私钥、定时整盘扫描、扩展递归预算、跨CD2迁移或跨云复制、永久删除、自动切换到可达地址、扩大精确版本白名单、增加角色。2PB只是用户总库背景，不是本轮容量或吞吐承诺。

多连接不等于自动故障切换，也不等于多个连接可同时写同一云盘。地址可达、策略可用、Token自检通过、盘点成功、写能力受支持是不同结论。

## 3. 用户流程

1. 管理者在系统设置创建具名连接，配置HTTPS入口与公开信任材料；保存不联网。
2. 在连接下维护具名目录配置，例如电影、电视剧；各配置有明确批准根、映射标识及独立功能开关。
3. 明确向用户授予该连接的使用权限并勾选可用目录；使用者还必须具备原有扫描、计划或执行权限。
4. 使用者在新建盘点中先选连接、再选目录配置、最后选择批准根内的本次子目录；确认来源和固定预算。
5. 使用者通过可信HTTPS交接精确绑定本次目录的短期只读Token；保存任务来源后，由现有受控worker执行。
6. 从原任务进入本地建议、复核、改名或隔离；后续请求由原记录解析目标，不读取当前默认连接。
7. 日后切换个人默认选择不改变既有任务；修改连接或目录安全字段时单独提示影响范围。

## 4. 连接与目录配置

| 需求ID | 要求 | 可观察结果 |
| --- | --- | --- |
| MC-01 | 连接使用稳定标识，名称仅供展示；重命名不改变来源身份 | 修改名称后原任务仍指向原标识，历史创建时名称可追溯 |
| MC-02 | 连接包含名称、HTTPS入口、信任材料和生命周期；目录配置包含名称、批准根、映射标识、功能开关、隔离目录名称 | 不再为切换电影/电视剧覆盖全局根；秘密不随配置持久化 |
| MC-03 | 新建连接及目录默认不开放执行，连接启用与动作开关分开 | 单纯保存、启用连接不触发网络或授予写权限 |
| MC-04 | 相同规范端点重复连接拒绝；不同端点可能是别名，不自动视为不同云账号 | 域名大小写、默认443、尾斜杠不能绕过重复检查；别名不获得额外预算 |
| MC-05 | 同一连接内拒绝相等或祖孙重叠的批准根；不同连接允许同路径，已知别名提示授权范围并集 | 不按最长前缀猜目录配置；选更深目录盘点无需另建配置，不妨碍家庭/公司同目录场景 |
| MC-06 | 连接规范端点固定；不同端点需新建连接及目录并重新授权。目录换连接、根或映射变化也属于重新绑定。同端点仅更新 CA 时保留用户授权。 | 换端点不继承目录或授权，旧任务不迁移；在原端点更新 CA 后，旧安全依据和诊断不能继续用于新动作。 |
| MC-07 | 配置采用修订检查并原子写审计；重复保存相同内容不制造修订 | 多管理员并发修改冲突时重新加载，无最后写入静默覆盖 |
| MC-08 | 保存与诊断分离；可查看离线连接，但不自动轮询CD2 | 页面刷新、切换连接、打开下拉框均无云RPC |

连接名的唯一性限定为应用实例内；目录名称唯一性限定为连接内。显示名称修订与安全执行修订分离，避免改名字造成整批重新盘点。具体长度和容量见MC1详细契约，不借此引入无限列表。归档配置不再提供可用批准根；解除归档必须重查同连接重叠，旧历史及未知保护仍保留。

## 5. 权限、个人偏好与历史

| 需求ID | 要求 | 可观察结果 |
| --- | --- | --- |
| MC-09 | 维护连接沿用管理设置的直接权限；使用连接需显式用户授权加原动作权限 | 能维护设置不自动等于能访问其他用户结果或执行云写；没有角色推导 |
| MC-10 | 新用户、新连接默认不获得全部连接；授权变更审计且立即生效 | 不得仅在下拉列表过滤，直接API、worker和每次RPC前同样校验 |
| MC-11 | 任务、建议、导出、日志、反向计划及原UUID查询均检查所属用户与连接授权 | 猜测其他任务ID/连接ID不能读到路径、端点、条目或Token |
| MC-12 | 撤销连接授权或动作权限后停止新请求；已发出的未知请求保留保护 | 不因撤权、禁用账号或关闭连接清除租约；不假称远端已取消 |
| MC-13 | 默认连接/目录是用户偏好，不是任务身份 | A用户切换不改变B用户页面；多标签页不悄悄切换已有草稿目标 |
| MC-14 | 历史按来源展示，保留创建时显示快照与当前名称区别 | 同名路径、同名任务可区分公司与家庭；改名不改写旧审计 |

连接使用授权不自动覆盖全部目录。首版采用显式目录白名单；“授权当前全部”按提交时目录ID列表保存，不建立未来目录自动授权通配符。无目录授权时不能获取根路径或盘点策略，不通过创建重复端点规避权限。

授权根包含其允许的后代目录：不能把另一个未授权配置当成对已有更大范围授权的deny规则。跨连接访问同一数据时，有效可访问范围来自已授予范围的并集；已知别名需提示风险，未知关联不能声称已隔离。通用文件系统拒绝ACL、自动跨别名私密目录识别不属于本轮已确认功能。同连接批准根不重叠不等于跨连接数据隔离，也不解除原动作权限、连接授权及目录白名单检查。

撤权后的普通内容访问应拒绝，不能因为本人创建就继续导出已撤权来源。保留必要的脱敏任务状态与管理员保护核对能力；管理者不因此自动获得其他用户媒体内容。历史未归属记录的旧所有者查看边界单独在演进计划处理。

## 6. 固定任务上下文与Token

| 需求ID | 要求 | 可观察结果 |
| --- | --- | --- |
| MC-15 | 新任务显式携带连接ID、目录配置ID和期望安全修订 | 不允许省略后回退到默认连接；服务端验证父子归属 |
| MC-16 | 任务保存固定端点/信任/根/映射/策略依据，worker从原任务解析 | 浏览器不能在start、恢复或反向请求中覆盖目标；篡改跨连接条目即拒绝 |
| MC-17 | UUID请求指纹包含用户、连接、目录、安全修订、所选范围及动作 | 相同UUID不同连接不能生成第二任务或返回错误来源结果 |
| MC-18 | Token仅属于本次动作、当前用户会话和固定目标 | 切换连接/目录、关闭弹窗、撤权、页面隐藏及会话改变清空待交接秘密；迟到响应不能重新填入 |
| MC-19 | Token从不进入URL、草稿持久化、数据库、日志、异常正文、导出或配置复制 | 用户直接在可信页面输入；不以主账号密码替代，不自动创建/续期/撤销Token |
| MC-20 | 地址不可达、Token过期或证书失败时不切备用连接重试 | 故障只记录在原请求及原来源，用户核对后另行发起新意图 |

Token精确绑定本次选定目录，可能比目录配置的批准根更小；客户端继续采用已验证的Token虚拟根语义。不能将全局账号Token用于“多连接通用登录”。

## 7. 盘点、执行与失效

| 需求ID | 要求 | 可观察结果 |
| --- | --- | --- |
| MC-21 | 网页首版本层、4RPC、30秒、100条、1MiB边界保持 | 多配置不增加单次预算、不后台接续、不将截断当完整 |
| MC-22 | 本地保存、分页、分析、保留例外、导出、清理不产生云请求 | 按原任务上下文查询；切换筛选不自动重新盘点 |
| MC-23 | 固定计划、冲突核对、执行、只读位置核对、反向新计划完整传播上下文 | C2/C3不会在盘点迁移后仍使用旧单例解析目标 |
| MC-24 | 拒绝跨连接/跨目录配置混合创建计划，隔离首版仍限定原批准范围内 | 不能将两个连接里同一个数字remoteId认作同一对象；不提供跨CD2搬运 |
| MC-25 | 展示偏好或名称修改不失效观察；安全配置变化只失效确有依赖的上下文 | 默认连接切换零失效；地址/信任变化使该连接旧执行依据过期，不自动把旧任务迁到新地址 |
| MC-26 | 映射变化及真实改名/隔离处理来源别名；无法证明独立时保守失效 | 不能承诺“只影响一个连接”；普通挂载扫描/重命名的全局保守栅栏不静默移除 |
| MC-27 | 来源已停用、归档或安全修订改变时，旧执行不得继续发送；恢复走独立受限通道 | 停用不等于删除历史；证书续签或地址维修不允许给旧未知请求自动换目标 |

安全修订发生在实际发送前的竞态必须覆盖：HTTP读取、受理事务、worker交接、每个RPC准入及本地提交都复核。不能只在新建表单阶段检查一次。

## 8. 并发、风控与生命周期

| 需求ID | 要求 | 可观察结果 |
| --- | --- | --- |
| MC-28 | 首版保留应用实例全局单云RPC、worker与云写互斥的保守上限 | 保存多个连接不增加活跃云请求或允许绕过未知槽 |
| MC-29 | 暂停、冷却、未决意图和已消费预算不随连接选择、复制或重建而清零 | 新连接、新根、新任务不能绕过全局保护；不按TTL删除未知记录 |
| MC-30 | 风控组与来源命名空间分离；未知关联默认共用保守保护 | 相同云账号不同CD2未来仍可共享频率，目录路径相似不被当作身份证据 |
| MC-31 | 忙时首版不自动持有Token排长队，不自动开启跨连接调度 | 明确返回忙/保护原因；已经受理的请求先查询，不生成新UUID重试 |
| MC-32 | 连接/目录支持停用与归档；历史证据不级联删除 | 有引用、未决、预算或恢复记录时禁止硬删除；首版不提供批量硬删 |
| MC-33 | 记录/缓存/日志容量保留全实例上限，不按连接数成倍扩容 | 归档不是自动清理；审计、批准预算、写证据按原生命周期保留 |
| MC-34 | 连接复制如提供，仅复制非秘密设置并默认关闭动作，不复制验证通过状态 | 不复制用户授权、任务、暂停/冷却、Token或身份已验证结论 |

应用不能协调另一个独立MediaAI数据库或其他115客户端；保留维护窗口、单写者及外部并发风险声明。多连接不解决上游缺少原子源身份条件的问题。

## 9. 页面、诊断与容量建议

系统设置采用连接列表与选中详情，详情下维护目录配置及用户授权；不把多连接页做成大量展开表单。盘点入口采用连接、目录配置、具体目录逐级选择；展示环境名称、批准根和动作，危险确认再次展示原来源。历史页支持连接/目录筛选，但筛选不改变记录绑定。

连接选择器应可搜索；离线、停用、无权、未验证明确区分，不能用“最近一次连接成功”代表本次仍成功。策略GET只检查本地条件。首版显式诊断将TLS检查、Token自检、运行版本分级呈现，小范围盘点是另一项动作；所有CD2应用/管理调用计入批准范围，不后台轮询、不列全局根；令牌缺失时允许标记未验证而不是冒充失败。

首版技术容量基线：每实例64连接、每连接128目录配置、每实例1024目录配置，计入归档；列表服务端分页、每页最多100条。版本、授权、上下文与诊断的独立上限和恢复预留见MC1详细契约；这些是设计限制，不是性能实测或2PB索引能力，不扩大原人工复核200条/20MiB等独立额度。

显示验收覆盖1080p、笔记本100%及4K/Windows200%/浏览器125%对应CSS视口，六主题亮暗；连接列表局部滚动、操作与状态可达、长名称/路径不撑整页、键盘可选择并关闭弹层。物理设备和读屏的外部待验仍分别保留。

## 10. 验收与未决项

验收必须以MC-01至MC-37追溯到测试，不仅截图：同路径跨连接、相同remoteId、父子目录、别名CD2、切换时迟到响应、撤权前后、证书续签、停用后恢复、混用UUID、共享冷却、旧记录无法归属、迁移中断、缓存已清理及反向计划均需覆盖。详细矩阵见[演进计划](multi-connection-evolution-plan.md#4-验收矩阵)。

| 补充需求ID | 要求 | 可观察结果 |
| --- | --- | --- |
| MC-35 | 目录白名单显式存储并在每个动作复核 | 新增目录、配置复制不自动授予；撤销连接授权不因旧目录授权而仍可用 |
| MC-36 | 显式诊断固定目标、预算、UUID和分层结果 | TLS成功/Token失败/版本未知可以同时准确展示，不输出一个含糊的“连接成功” |
| MC-37 | 保守迁移不猜历史、不复活旧计划 | 无可靠来源依据的记录保留历史查看，不赋予新执行资格；不清除未知保护 |

MC1已明确DDL/索引/仓储、API错误表、容量与受限恢复的技术基线；产品实现、性能、迁移和真实链路仍须后续门禁。跨用户只提供脱敏保护诊断，不新增代执行；原信任无法安全核对时保持冻结，不以换CA/地址释放未知。未证明来源独立时沿用保守失效，不把文档结构验证当成产品或迁库验收。
