# C2-0 目录改名能力评估

类型：技术能力评估。日期：2026-10-17。范围为CD2官方1.1.2公开协议及当前未发布源码；不是实际写入验收，也不授权真实操作。过程与本地证据见[阶段记录](../../work-logs/progress-2026-10-17-cd2-c2-design.md)，约束见[目录改名安全设计](../../design/cd2-directory-rename-safety.md)。

## 1. 结论

**当前保持目录名称建议和当前视图导出，不开放CD2目录改名。** 官方公开路径改名契约不能证明本项目要求的原子源身份条件及禁止覆盖；现有观察、普通文件队列和本地锁不能补足该缺口。这是“证据不足，未放行”，不是已经证明CD2服务器必然覆盖或必然改错对象。

C2-0资料、实现核对和离线反例已完成。用户在受控空目录试验后接受维护窗口首版边界，后续[完整产品实施](c2-implementation-plan.md)已接固定计划、隔离执行、独立只读位置核对、部分批次本地同步与反向新计划，schema50本地回归通过；真实产品链及实机状态见[验收记录](c2-acceptance-report.md)。原子身份、跨重映射唯一性和外部并发安全缺口不因此消失，不安装115私有SDK、改走挂载盘或用主账号扩大产品权限绕过约束。

## 3. 能力矩阵

| 核对项 | 已确认的事实 | 尚缺证据及决定 |
| --- | --- | --- |
| 单项改名 | E1的RenameFileRequest只有theFilePath/newName；E2说明可处理文件夹 | 没有预期对象、父对象、版本条件及禁止覆盖参数；不能发布为安全目录执行能力 |
| 批量改名 | RenameFilesRequest是单项请求列表 | 没有逐项原子/回滚保证，不能当整批事务；本期不使用 |
| 移动冲突 | MoveFile有optional conflictPolicy，枚举为Overwrite=0、Rename=1、Skip=2，并有跨云及递归冲突选项 | 省略optional不能当显式Overwrite或Skip；即使显式Skip，也没有源身份条件，且不等于同父basename改名，不作兜底 |
| 远端对象标识 | CloudDriveFile.id为string；还有路径、时间和CloudAPI等信息 | 未证明id跨改名/重启稳定、账号范围内唯一且不复用；readOnly=false也不是安全写能力证明 |
| 父对象及版本 | 可按路径FindFileByPath读取对象；CloudAPI含名称/用户/路径展示字段 | 没有在RenameFile中原子比较父身份、账号映射世代或条件版本；展示名/用户名不能代替稳定账号键 |
| 结果与恢复 | FileOperationResult包含success、errorMessage、resultFilePaths | 无逐项身份、幂等键或操作结果票据；没有相关契约时，响应丢失/取消都不能按路径重放，结果路径不能证明因果 |
| 能力发现 | GetServiceCapabilities仅canRestart/canUpdate | 不是条件改名能力查询；CloudSync另有版本条件、购买另有幂等说明，均不能泛化到文件改名 |
| 事件 | FileSystemChange含类型、路径、新路径和可选对象 | 该消息未提供用于本次改名恢复的可重放序号/操作关联；事件不能代替身份条件、完整目录或执行回执 |
| 云端缓存 | 列目录有forceRefresh/checkExpires；当前观察新鲜度为unknown | 强刷也是新云请求，并不能消除查询与修改之间的竞态；不得无预算循环探测 |
| 本地/FUSE路径 | 普通文件动作与平台禁止覆盖原语已存在 | 挂载路径/inode不等于远端稳定身份，现有服务拒绝目录；不能降级复制删除 |

其中“缺少请求字段”是可检查的协议事实；“实际实现是否另有等效保证”仍待官方或受支持接口契约确认。一次试写成功或目标存在时碰巧拒绝，不足以证明所有并发窗口安全。

## 5. 离线验证结论

19项验证分为：8个弱保证/名称语义场景、6个自建条件模型场景、4个当前产品保护和1个协议摘要核对。模型不发送网络请求，不连接真实库；未增加产品测试计数。

反例覆盖源路径替换、检查后目标出现、只有禁止覆盖仍改错对象、同id跨账号/父身份变化、本机锁外的客户端、未知结果重放、仅凭路径存在性误判，以及大小写/Unicode等价风险。条件模型将身份/父关系/世代和禁止覆盖合并为不可分割操作，并用收据模型展示不重放原动作；这只是说明所需语义，不能当作真实适配器或服务端能力。

当前代码保护验证：写请求不在投影；未准入RPC在访问库前被拒；含allow_rename的Token被拒；本地文件身份函数拒绝目录。无发现需要为本阶段修改产品代码。

## 6. 放行缺口与后续条件

| 编号 | 所需证据 | 不满足时 |
| --- | --- | --- |
| G1 | 官方或受支持接口给出稳定对象/账号范围、映射世代及原子源身份/父关系条件；条件不满足时无副作用 | 只建议/导出，不发写 |
| G2 | 同父改名具有服务端原子禁止覆盖/禁止合并语义，包含大小写、Unicode和目标目录冲突 | 不以先查后写或MoveFile Skip替代 |
| G3 | 旧新身份及后置条件可受预算核对；未知不重放，无法确定时能保留并冻结 | 不宣称自动恢复或撤销；不是必须有特定字段名的幂等键 |
| G4 | 本项目落实共同写槽、账号别名/重叠来源/子树冻结、权限复核、独立意图和有界路径修订 | 不接入普通改名队列执行 |
| G5 | 新的专用测试目录、临时对象、具体写/恢复范围与预算获用户另行授权，验证外部竞态和中断 | 不凭已有只读授权或账号密码试写 |

当前G1/G2尚无满足证据，G3/G4尚未实现/验收，G5未授权。推荐后续先拿到G1/G2契约；本阶段资料核对完成后停止在安全门禁，不继续扩展真实探测或搭建一个永远不可用的执行开关。用户可继续使用C1的本地建议和相对路径报告，在CD2原生客户端自行决定处理；本项目不承诺其操作可撤回。

## 7. 对外能力询证清单

下列问题可提交CD2维护方；本阶段仅准备问题，不自动发送、创建公开Issue或附带私人端点/目录/账号信息：

1. 同父目录改名能否原子绑定预期源对象、原父对象、账号映射及原名称/版本？若支持，具体RPC、字段/认证元数据、版本和云提供方限制是什么？
2. 能否显式请求禁止覆盖和禁止目录合并，并保证目标并发出现时无副作用？大小写/Unicode别名目标如何处理？RenameFile和MoveFile是否有不同保证？
3. CloudDriveFile.id的唯一范围是什么，改名/父目录移动/缓存清理/重启/账号重绑后是否稳定，删除再建是否可能复用？是否存在可供应用使用的稳定账号键及父对象身份？
4. 写请求取消/超时后是否可能继续完成？有无可靠的逐项操作回执/结果查询；若有幂等键，其作用域、期限及同键不同参数语义是什么？
5. 对精确父目录受限Token，子目录改名使用哪种命名空间，最小权限与受限根如何表达？服务端是否会执行跨云复制、后台排队或隐藏重试，调用次数如何解释？

仅回复“支持改名”“API都有”或提供成功截图不足以关闭G1/G2；需可归档、绑定版本/提供方的具体契约。若官方无此能力，继续建议/报告路线，其他受支持接口属于新的技术选型，不自动接入115私有接口。

## 8. 受控首版续作与新增证据

2026-10-17用户将C2实际目录改名及详细核验确认为最高优先级，暂停C3/C4；随后明确接受“受控模式，先验证再决定放行”。该选择允许评估维护窗口、单写者、前后身份核对的首版边界，不等于证明原子条件、批准生产放行或授权任意媒体改名。

新增官方依据：[维护者对Issue575的回复](https://github.com/cloud-fs/cloud-fs.github.io/issues/575)。维护者说明1.1.0起WebDAV在Overwrite:F且目标存在时返回412、双方不动；跨账号操作可能转为后台任务。此依据针对回复中的WebDAV文件场景，不是RenameFile的源身份CAS保证，也未证明115目录/代理的条件MOVE。G2可增加待实测路线，G1缺口没有因此关闭。

当前计划先准备本地一次性工具和离线门禁测试，再在专用空目录验证同父改名、身份变化、冲突不覆盖及清理；不以测试成功推导所有并发场景。真实测试的目录、40次应用协议请求/至少2秒间隔/5分钟上限、Token撤销及异常遗留规则已单独询问，收到该项明确授权前不执行。独立目录测试不是C3广告删除，不能触碰任何现有媒体。

用户随后明确批准该轮空目录测试，现已完成：[受控实测报告](c2-controlled-probe-report.md)。实际CD2/CLOUDAPI1.1.2原生gRPC同父改名、改回、本次ID稳定及同名目标拒绝且双方不变通过；36应用请求/6管理，测试根正常删除并核对不存在，短期Token撤销核对。该一次性授权已消耗，旧C1八会话/25RPC不变。

据此可以将“本端点本轮目录改名和冲突行为未经实测”改为“已有受控样本实测”；G1的原子身份保证仍未证实，G2不扩大为任意并发/提供方契约。用户随后确认受控边界并批准继续完整开发；本地固定计划、独立权限及核对窗口已实施，执行预算/隔离worker/恢复/路径修订尚未完成。产品默认不开放实际执行，本轮空目录授权不直接放行正式媒体写入。当前实现契约见[C2-A](c2-plan-contract.md)，后续状态见[实施记录](../../work-logs/progress-2026-10-17-cd2-c2-implementation.md)。
