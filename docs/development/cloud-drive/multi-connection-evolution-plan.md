## 3. 保守迁移与兼容

### 3.1 升级前提

1. 先由旧版本处理运行、未回收worker、未决RPC、云写和普通文件动作保护，确认实际进程退出与远端状态；不能先导入新应用再检查。
2. 停止新任务，备份一致性数据库、运行配置、匹配凭据密钥和TLS材料。用只读SQLite预检，不在预检中调用create_app/ensure_database。
3. 在独立副本运行迁移与验证。发现未决、字段不一致、超批次或来源无法满足迁移规则时停止，不自动删槽、清冷却或猜测绑定。

### 3.2 单例配置与权限

将当前配置迁成一个稳定连接和一个目录配置，保留原显示材料及政策出处；三个动作开关按D6关闭，由管理者确认后再开启。全局预算/暂停/冷却/已消费账本、未决意图与旧审计原样保留；不得把“新连接”解释为新风控额度。

不按用户名admin推定所有者，不建立角色。管理设置者可维护并明确授予自身/其他用户连接和目录使用权；迁移不自动把新权限授予所有现有用户。授权与动作开关改变有独立审计，管理能力不授予其他人的内容查看或远端代执行权。

MC1选择：当前配置为空或缺少端点、批准根、非空映射时，不创建占位连接/目录，保留旧单例只读材料并进入首次配置流程；已有材料无法通过严格校验时停止迁移，不将损坏配置当空配置静默丢弃。完整有效配置迁入一连接一目录，disabled且三个开关关闭，不联网验证。迁移重跑以固定迁移键识别既有对象，不能再创建一套默认连接。设置页能解释“旧配置未迁为可用来源”。

### 3.3 历史记录与未决

- 不因endpoint_hash与当前值相同、路径相同、remoteId相同或默认配置名称相同就认领历史；同一地址可能已重绑云账号。
- 只有可验证的不可变来源快照及明确证据链才能建立可靠绑定。不能恢复的安全版本标记legacy_unbound/历史来源未核定，保留原ID、所有者、范围、结果、审计与原摘要，不捏造旧证书/映射版本。
- 来源未核定的旧记录允许原所有者在原动作权限下只读查看，管理员仅有受限诊断，不经当前新连接授权“认领”或导入新任务。不能据此start、reverse、位置核对或继续旧云请求。
- 管理者后来补录历史说明，只是有审计的说明，不等于重新获得远端执行资格。需要实际操作时重新盘点小范围、创建新计划，不能将旧UUID和旧身份改绑到新目标。
- 若有未知结果而无法证明来源，应在迁移前停止并走旧核对流程；不能以“历史只读”方式旁路活跃未决。副本迁移核对不得更改原正式库。

MC1冻结schema55历史处理：现有端点/根/remoteId及policy_hash不足以组成不可变来源证据，因此首个迁移实现将既有历史全部标legacy_unbound，不从当前配置推定bound。若后续发现另有完整可信证据，须新增明确规则、合成正反例及评审后才能采用，不能在迁移器内临时放宽。来源未核定不妨碍原所有者本地只读历史，也不恢复远端资格。

迁移预检对read_sessions、inventory_jobs、directory_plans/executions/recoveries、quarantine_plans/runs、ad_reviews这8类根表合计最多50000行；超过则停止并另备分批演进方案，不删除历史强行通过。按主键每批500行读取/校验，离线副本一次迁移事务提交；不以500行批读宣称可在线迁移。schema号、各表新增FK/CHECK和对应索引由实际迁移脚本显式登记，不以ALTER失败后忽略代替幂等。

### 3.4 旧接口与回退

开发隔离扩展当前版本为3，主schema仍55。扩展1升级到3补诊断原owner PID/host/instance列及请求context查询索引；扩展2升级到3只加该索引。升级必须显式离线，确认无worker、未决RPC、原生写/恢复保护及活动诊断；历史owner不猜测补录，不改来源、用量、暂停或冷却。版本与列/索引形态不符时拒绝，审计或DDL失败整事务回滚。启动不自动升级，无HTTP迁移入口；该开发扩展号不是正式发行版迁移号或降级兼容承诺。

旧GET配置返回只读legacy/migrationRequired及新入口，不返回可执行配置；旧PUT固定409/multi_connection_required。无connectionId/profileId的新建意图显式拒绝，不能悄悄映射个人默认连接。查询原ID只返回原历史语义；不得接受“如果仅剩一个连接就默认执行”的回退规则。

新schema不能交给旧v1.4.0代码直接打开。回退使用匹配的旧镜像、旧数据库、配置和密钥；新版本已产生任务/审计时先保存新库，不将新记录无条件丢弃。副本恢复成功不等于真实故障回退演练，容器策略不等于NAS整机开机验收。
