## 5. 晚间真实试验的停止结论

用户单独批准唯一新建根下两个小TXT、两空子目录的移动/恢复/冲突验证。实际在第5次应用请求GetApiTokenInfo返回PERMISSION_DENIED后停止，尚未创建子目录、文件或调用MoveFile；另7次管理调用包括撤销临时Token并确认不存在。25.179秒、最小实际发送间隔2.251秒，旧实例不变。

私有工具对该公开自检误附受限Token鉴权头；官方协议将其列为公开方法，既有产品连接器不附该头。这个差异与实测拒绝相符，离线已修正并补无鉴权头回归；没有再次真实调用证实根因，不推断为Token根/有效期错误，也不能推断CD2不支持移动。

一次授权已消费，不能换随机根自动重做。仅创建的测试根随后另获身份/强制刷新空目录核对及普通清理授权，6应用RPC/2管理调用、16.177秒完成并确认不存在；不扩大成新的移动试验。当前同云移动、反向恢复及冲突安全门禁仍未关闭，正式隔离/正文取样/删除继续不放行。

## 6. 第二次新授权试验与受控产品边界

在首轮停止、Token撤销和独立清根后，用户另行批准一次同范围新试验，使用独立状态和消费锁，不重放旧请求。实际60应用RPC/13管理调用、162.560秒、最小实际间隔2.251秒，所有调用均收到响应，无未决和未关闭文件句柄。

正向移动和反向恢复后文件ID保持；同名冲突采用Skip，接口返回成功但未移动，源/目标ID均保持。该结果不能称为“RPC拒绝”，也不能只根据成功返回判断移动完成。两个小TXT、两个空子目录及唯一根均核对后普通清理，临时Token撤销并确认不存在，两旧实例未变。未读现有媒体、重启或永久删除。

用户在结果之后明确确认维护窗口、单写者、小批量串行、前后身份核对、未知不重试、反向恢复新计划；不能防御外部客户端并发替换源对象。产品按[隔离契约](c3-quarantine-contract.md)和[实施计划](c3-quarantine-implementation-plan.md)推进，执行默认关闭。Q1本地计划不产生云动作；新执行/恢复链须以本轮综合和已单独批准实机测试取得证据，不复用此前门禁。
