# CD2 / 115 超大库整理可行性评估

类型：候选方案与分期评估。日期：2026-10-16。依据源码34a8ce8、v1.3.0/schema39及当日官方公开资料。用户仅授权评估，本文不是已批准详细设计、可用功能说明或真实云盘验收报告。

2026-10-20状态补充：原评估的首次授权、待核对项和源码差距保留为历史背景，不代表目前仍只允许评估。C0-C3开发源码已为schema54；C2受控空目录产品链、C3公司1.1.2受限Token小夹具产品链已验，执行默认关闭，未发布。当前放行边界见第11节及[C4清单](c4-acceptance-checklist.md)，不能用历史schema42口径决定升级。

## 1. 结论

**建议增加该场景，但先交付低扰动盘点、目录名称建议和广告候选清单，再按能力门禁开放写入。推荐CD2官方API作为主接入，fnOS同机挂载作为可选补充；不直接接115私有接口，不默认全库扫描，不自动删除。**

| 需求 | 可行性 | 主要前提 |
| --- | --- | --- |
| CD2/115目录与文件盘点 | 有条件可行，建议首期 | 实际版本/令牌/目录规模核对，有界目录队列，区分缓存与新鲜数据 |
| 去论坛广告前缀、规范文件夹名称建议 | 可行，建议首期 | 基于已盘点名称/上下文/既有元数据，不触发内容下载或自动TMDB/AI请求 |
| 真实文件夹改名 | 有条件可行，不能直接复用文件改名 | 目录身份、禁止覆盖、同账号互斥、子路径一致性和中断恢复；CD2路径写入原子条件仍有缺口 |
| 广告文件辨别与意见 | 可行，但不能保证零误判 | 规则优先、保护附属文件、解释理由与证据；视频/图片内容分析独立授权 |
| 隔离及广告删除 | 后置受控能力，首期不开放 | 独立确认及权限、固定目标、真实身份条件、可恢复性验证；不足时仅导出清单手动处理 |

用户实际环境：CD2在fnOS，连接115及其他云盘，以115为主、总容量超过2PB。用户补充：通常按电影等业务目录及其欧美、大陆、日韩等分类操作，不整盘扫描。**账号容量不等于任务规模，容量也不等于文件条目数**；重点核对所选子树的目录数、条目数、单目录规模和缓存新鲜度，而不是先建立全账号索引。CD2实际版本和安装形态、事件订阅许可、原有同步/备份规则仍待确认。已对指定CD2首页作一次无认证静态读取，200/CloudDrive；没有登录、执行页面脚本、列目录或访问媒体。

## 2. 官方事实及限制

1. CD2官方提供gRPC接口，公开指南当前标示1.1.2；开发者应匹配实际服务版本。应用适合使用有目录范围、权限和有效期限制的API令牌，不必保存CD2主账号密码。[API指南](https://www.clouddrive2.com/api/CloudDrive2_gRPC_API_Guide.html)
2. 当前公开proto中，`GetSubFiles`返回文件列表流，条目有名称、类型、大小、时间和id等字段；请求有`forceRefresh/checkExpires`，但没有公开页号或断点游标。**流式响应不等于云端分页，也不证明断流后能从某个条目续传**。`id`在改名、重启后的稳定性仍需验证。[官方proto](https://www.clouddrive2.com/api/clouddrive.proto)
3. `RenameFile`只有源路径与新名；`DeleteFile`使用路径请求，未暴露预期对象ID/版本或幂等键；改名也没有公开的禁止覆盖参数。`MoveFile`的冲突策略包含Overwrite、Rename、Skip，不能省略策略假定安全。这里是接口证据缺口，不是断言所有服务端实现都会覆盖或一定不安全。[官方proto](https://www.clouddrive2.com/api/clouddrive.proto)
4. CD2官方提醒，普通删除作用于云上真实文件，可能无法恢复。备份/双向同步中的历史文件夹和回收站规则是另一功能，不能据此承诺普通删除能撤销。[官方帮助](https://www.clouddrive2.com/help.html)
5. 经CD2发生的变更可有事件通知，需核对版本/会员/令牌；云盘官方客户端发生的变化不保证实时送达。官方同步说明也指出，外部改名可能不改变父目录时间。**事件和目录mtime只能作增量提示，不能作完整一致性证明**。[事件说明](https://www.clouddrive2.com/features.html)、[云端目录时间说明](https://www.clouddrive2.com/two-way-sync.html)
6. CD2媒体库自身有目录速率与设备间叠加说明；这些是其产品行为，不是115向本项目授予的安全配额。115公开平台也保留动态服务限制；本次未取得适用于该账号/操作的固定安全频率。[CD2媒体库](https://www.clouddrive2.com/media-library.html)、[115开放平台](https://open.115.com/)

资料核对不等于实际服务能力通过；不照搬官方某功能的默认值或暂时解限时间作为MediaAI风控保证。

## 4. 接入路线

### 推荐：同一fnOS上的MediaAI，经CD2官方API获取元数据

- CD2继续管理115认证、缓存与上游适配；MediaAI使用用户创建的最小权限令牌，仅访问选定的115媒体子目录，不选择聚合根或整个2PB账户。
- 一次目录列表消费返回的类型、名称、大小和时间，避免对每个条目再次stat、取详情、取下载地址；未知字段保持未知，不补拉整个目录统计。
- 缓存优先，通常不强制刷新；过期/缺失缓存仍可能请求115。展示观察时间和新鲜度，不标成“纯离线、无云请求”。
- 只读取官方接口；不直接读取/修改CD2私有缓存数据库，不安装未核验第三方115 SDK，不使用Cookie或设备/IP轮换规避限制。
- Python gRPC接入可能需要grpcio/protobuf及固定版本生成代码；后续实施才评估依赖、许可、Python版本及哈希锁，本轮不安装。没有必要安装新的MCP或设计Skill。

### 补充及备选

| 方式 | 适用情况 | 结论 |
| --- | --- | --- |
| CD2原生挂载目录只读映射到MediaAI | API暂不满足版本/权限，或将来单独授权少量内容分析 | 可作兼容补充，但透明缓存、枚举/stat放大和合成inode限制仍在 |
| 经SMB再访问CD2挂载 | MediaAI确实必须在另一台机器 | 增加文件系统调用和身份/挂载问题，不作为2PB首选 |
| CD2 HTTPS WebDAV | 只有该方式能接入或需比较条件写能力 | 只读回退候选；不是更低请求量保证，目录写仍需新适配与验证 |
| 直接115开放API | 未来确需对象ID定向操作且CD2无法提供 | 独立认证、授权及维护范围，不是本轮推荐接入，也不使用私有接口补洞 |

用户当前管理入口为HTTP；**静态首页可达不代表已具备安全API通道**。跨主机传令牌优先配置证书有效的TLS及支持gRPC的代理/监听，保留主机名校验；同机受控网络如何授权明文API是后续部署决策，不默认把令牌发往当前HTTP端点。既有HTTP WebDAV排除项不改变，不自动调整CD2、fnOS或防火墙。

fnOS CD2的原生安装/容器及挂载传播方式须核对实际部署，不能只因“在fnOS搭建”就假定目录已对MediaAI容器可见。挂载丢失时不将留下的空目录当作云盘已清空。

## 5. 超大库扫描与风控建议

### 5.0 分类目录任务与扫描建议

**任务以所选目录子树为单位，2PB只表示账号背景，不作为每次扫描的工作量或首期必须全量索引的目标。** 支持用户自定义目录结构，不把欧美、大陆、日韩硬编码为分类规则。

推荐交互：选择`电影` → 查看本层已有缓存/按需列出直接子目录 → 勾选本次分类 → 展示范围与扫描建议 → 确认后同账号串行分批执行。目录树按层展开，不为显示完整树或估算总量提前递归整个电影库。

| 所选范围与已知状态 | 默认建议 | 明确的覆盖边界 |
| --- | --- | --- |
| 电影目录，尚无分类信息 | 先做“本层概览”，供选择子分类 | 只列当前层，不递归欧美/大陆/日韩；本层也可能很大，仍受消息/条目预算限制 |
| 首次选择欧美等一个分类 | 先选其中一个代表性影片目录小范围试扫，再按批准范围分批盘点该分类 | 试扫只代表所选样本，不能显示整个分类已扫描 |
| 同时选择欧美、大陆、日韩 | 建立三个子树工作单元，同115账号串行，分别记录进度/断点 | 多分类不增加并发；未开始、已暂停、已完成分别展示 |
| 已有较新观察，用户只整理名称/筛广告 | 直接分析已有盘点数据，暂不访问CD2 | 明确观察时间、已覆盖范围和未知项；写入前仍需独立重新核对 |
| 只新增少量影片或有变更线索 | 定向扫描新增目录或受影响子树 | 不把“只检查变化”描述为保证发现所有外部改名；必要时用户批准分批复核 |
| 选择整个电影子树 | 建议按直接分类分批并可排除不处理的分类 | 不扩大到剧集或其他云盘；仍须处理电影本层直接存放的文件，不能只扫子文件夹 |
| 没有条目数/缓存过旧/单目录很大 | 显示“规模未知，建议先试扫或缩小范围” | 不为给出精确预计时间、容量或总数而偷偷完整扫描 |

建议依据仅用已有观察、当前层允许的元数据、上次耗时/失败/预算记录；显示可解释理由，不只按目录名或账号PB容量判断大小。不把目录名称建议误当成要改名电影/欧美等组织分类目录；此类目录默认保留，用户选中的影片/剧集目录才进入命名建议。

范围与完成语义：

- 确认根/分类、递归范围、排除目录和读预算；父子重复选择去重，不将同一路径重复扫。新增范围必须再次确认，不能沿路径跳转/云账号换绑越界。
- 只读盘点可在批准子树与预算内发现新子目录；这不授权新发现对象进入已确认的改名/删除计划，写操作仍绑定固定对象集合。
- 存在本层直接文件、子目录未开始或partial时，分别报告；例如“欧美已盘点，大陆排队，日韩未选择”，不能因此显示“电影库全部完成”。没有扫描的范围显示未知，不显示零文件。
- 达到正常批次预算可在用户预先确认的**任务总预算和调度策略**内续批，不重复已完成目录；未批准续批或总预算耗尽则暂停。每批重新开始不得重置总预算形成无限扫描，未完成的流式大目录仍受无条目游标限制。
- 风控、认证异常或未知写与普通批次结束分开：立即按账号暂停相关队列，不自动切下一个分类继续请求，也不因“继续下一批”绕过冷却。
- 观察与missing核对限定到完整、新鲜且可比较的已选目录范围；未选/排除/未开始分类的历史记录不标missing、不生成清理候选。缓存分析结果与重新验证结果明确区分。

### 5.1 盘点模型

- 建立独立的通用目录/文件盘点，不把非视频塞入当前重命名预览；文件系统访问方式与“CD2/云盘安全策略”分开，普通本地/NFS默认行为不被本轮修改。
- 单目录层级列举、磁盘持久化待访队列、有界消息/条目批次和短事务；UI查询本地数据库分页，不因滚动、筛选、看日志再次访问CD2。
- 完整列举后才原子发布该目录的新一代观察，记录范围、观察时间和完整性；预算截止、断流、缓存过旧、拒绝或风控时保持partial/stale/unknown，不能把未见条目批量标missing或广告。
- 断点最少保证到“已完成目录”。当前proto没有可验证条目游标，未完成的巨型单目录不可假装精确续传；重取需预算/用户策略，不能静默循环重扫。
- 对单目录超大响应设置接收消息、条目、内存、时间与落盘上限；流中止也不能保证CD2已停止向115分页。无法有界消费的目录保持未完整，不承诺支持任意巨大扁平目录。
- 优先用户指定新入库目录、小范围手动刷新及CD2事件触发的定向失效；断线事件缺口只标相关范围待核对。不启动递归watcher制造另一轮枚举，不自动做全库周期纠错扫描。
- 父目录mtime只能减少“可能变化”的检查；无法证明外部改名都被发现。发现缺失只作复核线索，不自动生成删除动作。

### 5.2 预算与熔断

所有枚举、属性复核、候选内容读取、改名、隔离、删除和恢复都计入预算。按用户明确关联的CD2实例/云账号归组，多个别名/路径不能各开一组额度；115与百度分别归组，同时保留实例总并发上限。不把完整账号或Token写入任务/日志。

**下表仅为小范围试运行候选上限，待实际环境验证，不是115配额或免风控承诺，也不是已生效配置。**

| 控制 | 候选起点 |
| --- | --- |
| 读盘点 | 同账号最多1个在途RPC，准入间隔至少2秒，不突发补发 |
| 一轮盘点 | 所选分类的一个候选批次；最多200个目录或10000个条目或15分钟，任一达到即保存断点/partial；不是整个分类的支持上限，续批另受任务总预算约束 |
| 默认内容读取 | 0字节；不取缩略图/直链、不运行ffprobe/OCR、不计算全文件哈希 |
| 真实写（仅能力开放后） | 同账号串行，动作间隔至少5秒、每个确认计划最多20个对象；复核RPC仍占读/共享预算 |
| 冷却 | 认证异常、验证码、风险提示或反复限速时持久化暂停，默认人工核查后恢复，不定时探测账号是否已解限 |

本机多worker共享预算和租约，不持SQLite事务等网络。CD2内部重试、预读、云端分页及其他播放/备份/客户端会叠加，MediaAI只承诺控制自身准入；实际115请求数不可观测时显示“未知”，不把CD2 RPC数冒充上游次数。CD2本身QPS参数可列为人工检查项，不自动改高或改写系统设置。

已发出的写操作不能靠取消收回；网络超时/返回丢失为unknown，不重发改名、移动或删除。未知写未核清前冻结相关账号/子树写入，恢复只读核对也占预算，避免高频存在性探测。进程未确认退出不释放槽，重启不清空冷却与未决意图。

## 6. 文件夹名称建议与执行边界

### 建议层先做

- 第一类“名称净化”：仅去除用户批准的论坛前后缀、推广词、网址样式与冗余分隔，保留年份、季、版本、合集等信息；支持词条例外及预览命中位置。
- 第二类“规范命名”：复用已确认影视元数据生成影片/剧集目录名。没有现成元数据时先本地建议；TMDB或AI必须另行确认，不能为2PB每个目录自动匹配。
- 展示原名→建议名、规则、元数据来源、冲突、已索引影响范围及完整性；例如合成名称`[论坛推广] 示例电影(2024)`可建议为`示例电影 (2024)`，不把“收藏版”等真实版本信息一并删掉。
- 混合作品、合集、多季及低置信目录只给建议，不按第一个视频强行命名整目录。媒体根、云账号根、季/剧集结构及BDMV/CERTIFICATE/VIDEO_TS等目录默认保护。

### 执行层必须独立设计

1. 首轮只考虑同父目录下改basename，不迁目录、不跨云/跨账号、不合并目录；计划禁止祖孙目录同时入选，不自动临时改名解决交换/环路。
2. 目标存在、大小写/Unicode冲突、符号链接/快捷入口、只读/压缩包虚拟目录、挂载/账号映射变化时拒绝。禁止失败后退化为复制删除。
3. 以经验证稳定的远端对象标识、父对象、云账号和版本/快照绑定计划；挂载inode不作为云端稳定ID替代品。准备后改配、撤权或原对象替换使计划失效。
4. 目录动作与普通文件改名/回滚/迁移共同互斥；同账号重叠媒体源别名、扫描发布、外部处理中预览和未决动作一并检查。用户在CD2/115其他客户端的改动不受本项目锁约束。
   目录改名还可能经事件通知触发媒体服务器重新枚举或同步任务处理，产生额外请求；需核对其监控/扫库设置并协调执行窗口，不能把“一个目录改名请求”等同于“整个系统只有一次云请求”。本项目不自动关闭其他程序。
5. 目录改名是一项云端动作，不递归逐个改其所有子文件。当前路径可用“目录身份＋相对路径＋修订”或有界路径重建维护；重建未完成时冻结受影响子树写入，不能巨型事务更新全部路径或让旧预览继续执行。
6. 历史扫描/改名/审计/回滚的原路径快照不可篡改。保存路径演进关系，使当前定位与历史证据分开；旧dry-run失效，历史回滚重新对账并干跑，不能按字符串前缀直接REPLACE所有历史路径。
7. 动作意图→发出→远端核对→业务同步分别持久化，成功不等于全部子路径已同步。只读恢复核对目录身份及实际父子关系，不能仅凭旧路径消失/新路径存在判断成功；不确定时人工处理。

**原子条件缺口：**“先查询对象ID，再调用路径改名/删除”仍有检查与执行间的竞态；内部互斥、人工确认和回写审计都不能补成服务端原子条件。本次没有证明CD2此接口具备要求的身份条件/防覆盖保障。后续须取得并验证实际端点的相应原子语义，或独立评估有对象ID语义的受支持接口；测试成功几次本身不是普遍证明。能力不足时保持建议/导出，不降低现有安全门禁。

## 7. 广告识别与清理

### 分级取证

| 层级 | 输入与成本 | 输出边界 |
| --- | --- | --- |
| 默认规则 | 已盘点名称、类型、大小、同目录关系、用户词条；无内容下载 | 推广词/站点样式/成组重复名称等为线索；解释原因，不据后缀或小体积直接删除 |
| 既有指纹 | 仅使用接口已经提供的可信哈希等字段，不为补证下载计算 | 与用户批准广告样本匹配作证据，校验对象/规则版本，仍需确认 |
| 可选TXT取样 | 用户选定候选并单独批准读取；建议每文件最多64KiB、一轮最多20项 | 超限/编码未知/截断保留不确定；不执行脚本、不访问其中链接 |
| 图片/视频深检 | 后续独立范围，本期默认不做 | OCR/抽帧/ffprobe可能下载、预读或seek；可先让用户提供本地样本，不全库批量读取 |
| 可选AI解释 | 仅在确认的候选范围、脱敏后外发；复用敏感词及外发保护 | 输出结构化分类/理由，不执行AI返回路径、命令、链接或删除指令 |

取样上限是应用消费预算，不证明实际115下载同量：CD2可能按更大块预读，HTTP Range也未必被遵守。内容阶段未验证实际放大前不开启后台取样。

**默认保护：**字幕、NFO、poster/fanart/folder图片、`.actors`、校验清单、说明文档、章节/播放列表及正片/预告/花絮/特典/样片关联内容。TXT和图片不是天然垃圾，小视频不是天然广告；`AD`、`广告`等词也可能是正常片名。未知扩展名和特殊对象不自动清理，用户保留白名单优先。

候选分为“保留 / 需确认 / 建议隔离 / 建议删除”，附低中高证据等级，不伪造已校准的百分比。默认不勾选，批量只作用于用户确认的固定候选ID集合，不能把当前页当全部，也不能因后续扫描增加文件而扩大确认范围。以本地规则和抽样标注集验证误判，误判会影响删除安全，不仅是分类准确率指标。

### 清理动作

- 优先推荐忽略/标记保留；有已验证安全能力时，可选择同账号、同云盘、指定隔离区的服务端移动。隔离也是真实写，会影响路径、外部播放器和同步任务，并非零成本、无风险操作。
- 不跨账号/云或经本地复制；不自动创建可扩散的隔离树。隔离位置、范围、恢复办法和权限在执行前固定，不合并目录、不覆盖同名；不能确保语义时只导出清单。
- 目录改名与广告处理分不同计划；前一动作使旧路径或快照变化时，后一计划必须重核，不在同一批中猜测新路径继续删除。
- 真删除使用单独权限与危险操作确认，不等同rename:execute，更不等同现有待处理记录移除。保持直接用户权限，不引入角色；权限标识和接口在详细设计时冻结。
- 未证明恢复能力时明确提示“可能不可恢复”，不提供虚假撤销承诺；首期不开放真删除。后续若开放，仍需满足对象身份条件、固定范围、审计和未知不重放，不能以确认框替代原子安全。
- 不递归删除目录，不自动删除清理后的空目录，不清空云盘回收站，也不按保留天数自动清空隔离区。恢复隔离文件或改回目录名称也须重新检查身份、冲突和账号预算。
- 执行前核对CD2备份/同步、媒体服务器监控及其他自动化是否覆盖目录；删除/改名可能被复制到其他位置或被重新同步回来。不能仅在MediaAI内部暂停就保证外部任务停止。

## 8. 数据、界面与日志影响

本次只确定后续需要管理的概念：云连接与账号预算组、目录/文件观察代次、候选及理由、用户保留例外、固定动作计划、逐项意图及路径修订。**不在评估中冻结表结构、迁移SQL或新API**；项目继续使用参数化sqlite3，没有ORM，不为了本功能引入另一持久层。详细设计须补全接口定义、客户端调用、错误/状态契约及迁移验证。

- 提供独立“目录整理/广告候选”工作台，不把所有对象塞入重命名视频表；显示范围、新鲜度、已盘点/未完成目录数和剩余预算，不为算总数先做全盘统计。
- 目录建议与广告清单分视图；普通用户先看风险/证据，确认按钮与删除分层。保持现有主题、固定操作列、分页和真实缩放要求，本轮不改前端。
- 查询、筛选、查看详情和日志默认只读本地观察；显式重新核对才进入预算队列。运行摘要可按既有约1.5秒观察，不能每次UI轮询就探测CD2。
- 常规进度按批聚合，不为2PB每条写高频INFO；理由按有界字段保存，日志不记录Token/密码/直链/完整正文，导出默认相对路径且提示隐私。
- 观察数据、候选和普通报告单独有数量/逻辑字节/时间预算；淘汰缓存不删除云文件，不能触发自动重扫。保留用户确认、动作意图和必要审计；未决不因普通日志清理而删除。
- 受容量限制无法保留更多观察时暂停并说明，不能静默淘汰仍被确认计划引用的身份。SQLite/WAL物理容量另测，不承诺2PB库无需额外本地索引空间。

验收围绕用户实际选择的分类子树，分别记录目录数量、文件数量、最大单目录条目、缓存状态和扫描深度；不以全账号2PB作为单次任务基准。先用小分类/样本及合成数据验证，再视所选子树规模增加10万/100万条目压力边界；记录RSS、SQLite/临时库/WAL、磁盘、P95查询、取消时延和恢复成本，不把元数据模拟量换算成2PB实机验收。UI只消费分页，不回传百万对象或全选ID数组。

必测风险：缓存过旧、目录mtime不变的外部改名、事件丢失/重复、流式列表中途断开/无游标、挂载丢失、账号换绑、重复来源、Token过期/撤销、风控后重启仍暂停、CD2内部重试、单目录大消息、超预算不标missing；同名替换/覆盖竞态、祖孙计划冲突、批量部分成功、云端成功但数据库失败/响应丢失、旧预览/回滚失效；字幕/海报/预告误判、恶意文本提示注入、内容预读放大、隔离跨账号误配、外部同步传播及恢复冲突。

真实115验证只在用户明确批准的专用目录内逐级扩大，不做全盘压力测试；所有改名/移动/删除另获具体授权，记录临时对象及还原结果。遇风险立即暂停，不换接口/IP/设备标识规避。
