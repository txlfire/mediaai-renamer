## 实施

- auth 依赖不再在空用户表时放行；main 对全部业务 router 加登录依赖，健康检查及 auth 公共入口保持既有功能，auth 自身的 me/改密仍检查 token。

- 远程恢复读取持久化 operation_type 后选取 rename:execute 或 rollback:execute；前端按钮按相同规则禁用。
- 本机模块 app.admin_recovery 先检查实例配置/数据库及恢复开关，持久化意图后恢复；HTTP reset-admin-password 保留地址但返回 403。登录页删除 query 参数触发的隐藏恢复按钮。
- 前端改密成功清除旧 token/用户状态并提示重新登录；失败保留会话。日志、预览/待处理相关按钮按权限禁用，不改变原布局。

## 接口兼容与调用

业务路径/请求/成功响应未变；新增匿名 401、缺权限 403 是明确的安全兼容调整。`POST /api/auth/change-password` 成功仍返回用户对象，但旧 token 不能再用；前端重新登录。旧 `POST /api/auth/reset-admin-password` 仅返回 403，使用本机恢复命令，见总用户手册。

```powershell
$headers = @{ Authorization = "Bearer $accessToken" }
$body = @{ currentPassword = $currentPassword; newPassword = $newPassword } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:8970/api/auth/change-password" -Headers $headers -ContentType "application/json" -Body $body
```

调用变量由登录及用户输入提供，不把实际密码/token 写入文档。成功后重新 POST login 获取新 token。
