## 2. 执行顺序与检查范围

| 顺序 | 范围 | 重点 | 对应证据 |
| --- | --- | --- | --- |
| 1 | 登录、用户权限、配置与凭据 | 接口鉴权、直接权限、会话失效、密码重置、配置脱敏、凭据存储与日志泄露 | `api/auth.py`、`api/users.py`、`service/auth_service.py`、`core/config.py`、权限与认证测试 |
| 2 | 扫描、预览、重命名与回滚 | 路径边界、目标冲突、并发锁、数据库与文件状态一致性、中断恢复、幂等和错误处理 | 扫描、预览、重命名、回滚服务及对应测试 |
| 3 | 共享目录与 WebDAV | 协议输入、TLS、认证、路径编码、超时、遍历与 MOVE、失败恢复 | `service/shared_protocols/`、远程操作服务、协议单元与集成测试 |
| 4 | 元数据与 AI | 外部提交保护、Provider 切换、请求参数、超时与重试、批量行为、错误反馈 | 元数据与 AI 服务、设置页面、相关测试 |
| 5 | 日志、任务治理与数据库 | 日志容量与保留期、清理后状态、增量查询、浏览器刷新成本、分页、索引、迁移与事务 | 日志与任务服务、`core/database.py`、日志组件、迁移测试 |
| 6 | 前端与交互 | API 错误处理、权限入口、配置新增与保存、固定列、150% 缩放、批量操作和状态同步 | 页面、路由、stores、API 客户端、浏览器验证 |
| 7 | 部署与发布 | Windows/Linux 启停、单容器路由、目录映射、持久化、依赖与版本一致性 | `scripts/`、Docker/Compose、工作流、发布文档 |

每项问题记录严重程度、文件与行号、触发条件、影响、验证证据和修复建议。性能、安全性、可读性、错误处理与边界条件均纳入审查；未复现的疑点单独标记，不能写成确定缺陷。

## 5. 验证安排

正式审查先记录 Node、npm、Python 版本和依赖状态，再执行以下基线命令：

```powershell
npm run backend:test
npm run frontend:test
npm run frontend:build
npm run check:encoding
git diff --check
```

验证结果记录执行环境、退出码、失败用例和证据。准备阶段只核对了命令定义，尚未运行测试或构建。

WebDAV 集成测试使用独立测试目录和环境变量；确认测试脚本的写入与清理范围后执行 `npm run webdav:test`，不能使用正式媒体文件验证 MOVE。外部 AI/元数据服务的真实调用单独记录，离线单元测试不能作为实际连通性证据。

浏览器验证覆盖用户维护、Provider 新增/切换/保存/测试、扫描与重命名日志、固定操作列，并包含 150% 缩放。日志快速刷新性能需记录数据量、查询频率和浏览器表现，不能只凭视觉判断。
